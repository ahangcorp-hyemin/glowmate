# Mobbin UI 레퍼런스 러닝 (방문예약·지도)

Mobbin MCP로 우리 신규 화면(방문예약·지도 멀티핀)을 실제 앱 레퍼런스와 대조. 결론: 우리 구조가 이미 정합적이라 **검증됨**. 배울 점만 선별 반영.

## 방문 예약 — 레퍼런스: Zocdoc(의료), Square Go(뷰티살롱), IKEA
- [Zocdoc 예약 플로우](https://mobbin.com/flows/fcd6461e-af19-4ca9-9864-8b21c286888c) — 의료 예약, 우리와 가장 유사
- **검증된 우리 패턴**: 날짜 헤더 아래 시간 슬롯 pill 그리드 / 병원 카드 상단 고정 / 이름·연락처·동의 체크 / 완료 화면. 전부 레퍼런스와 동일 구조.
- **차이(우리 데이터 정직성)**: Zocdoc은 병원 카드/검색결과에 *실제 가능 슬롯*("Tomorrow 8:15 AM…")을 바로 노출. 우리는 병원이 슬롯 데이터를 안 줘서 "희망 시간 신청" 모델. 슬롯 API가 생기기 전까지 이게 정직한 형태.
- **반영한 러닝**: Zocdoc 완료 화면의 `Prepare for appointment`(방문 준비) 링크 → 우리 고유 자산인 "전화 전 질문지"와 정확히 매핑. 완료 화면에 "📋 방문 전 질문 미리 보기"를 1순위 버튼으로 승격(예약 직후 이탈 대신 우리 콘텐츠로 유도).
- **보류**: 보험카드 스캔·환자여부 등 미국식 필드는 우리 맥락 무관.

## 지도 멀티핀 — 레퍼런스: Wanderlog, Tripadvisor, CAVA
- [Wanderlog](https://mobbin.com/screens/389fba88-fc57-4315-ba2a-422ddc759cfa), [Tripadvisor](https://mobbin.com/screens/970bf202-97ea-44ca-92ce-0b7732388eef)
- **검증된 우리 패턴**: 핀 탭 → 하단 place 카드 → 상세. Wanderlog/Tripadvisor와 동일.
- **보류(1-thing)**: CAVA식 "번호핀 + 하단 카드 가로 캐러셀"은 탐색성은 좋지만 복잡도↑. Wanderlog식 카드 내 [저장]/[길찾기]/[상세] 인라인 버튼도 유용하나, 우리는 상세 페이지에 이미 그 CTA가 있어 지도 카드는 단순 유지가 맞음.
