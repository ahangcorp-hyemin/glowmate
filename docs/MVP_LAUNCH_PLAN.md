# MVP 런칭 플랜 — IA 재구성 · 우선순위 · 개발 기획

> 2026-08-14. 근거: 4050_DECISION_RESEARCH(n=243) · HYPOTHESIS_VALIDATION · HOSPITAL_ENRICHMENT · 본 문서의 의료진 API 리서치.
> 상황: 지금은 공공데이터 기반이지만 곧 **병원 입점 영업**이 필요하고, 그 **모객을 위해 콘텐츠**를 쌓는 단계.
> 내일 개발 킥오프용. gstack 절차: 아침에 `/plan-ceo-review`로 본 문서 스코프 락 → P0 항목별 `/spec` → 구현 → `/ship`.

## 0. 의료진 정보 공공 API 리서치 결론 (오늘 실측)

| 원하는 것 | 공공 API | 판정 |
|---|---|---|
| 개인 의사 명단·면허·이력 | ❌ 없음 — [보건복지부 면허 데이터](https://www.data.go.kr/data/15003224/fileData.do)는 **집계 통계뿐**(개인정보 비공개) | **불가 → 제휴/병원 제공이 유일** |
| 병원별 전문과목·전문의 수 | ⭕ [HIRA 의료기관별상세(15001699)](https://www.data.go.kr/data/15001699/openapi.do) "전문과목별 전문의수" — **키 전파 대기중**(`bun run probe`로 추적) | 전파되면 **전문의 검증 배지** 병원단위 자동화 |
| 총 의사수 | ✅ 병원정보서비스 drTotCnt — **이미 인제스트됨**(704곳) | 완료 |
| 개별 전문의 소속 검증 | △ [피부과의사회 akd.or.kr](https://akd.or.kr/dermatologist/verify) 이름검색 — **API 없음**, 웹 조회만 | 입점 심사 때 **수동/제휴 검증**(자동 크롤은 회색) |

→ 결론: **의료진 프로필(사진·이력·상담스타일)은 입점 병원이 직접 제공하는 구조로 설계**해야 함. 공공데이터는 "전문의 있음" 검증 배지까지만. 이는 리서치 결론("신뢰 단위=사람")과 맞물려 **입점의 핵심 가치제안**이 됨: "글로우메이트는 의사 '사람' 정보를 심층으로 보여주는 유일한 곳".

## 1. IA 재구성 — 3필러 MVP

```
[홈]                          [콘텐츠]                     [탐색]
병원매칭 (지금 완성됨)          SEO 유입 (모객 엔진)          후기 기반 브라우징 (수집 후)
├ 견적받기(고민→조합→근거)     ├ 공개 Q&A (F6, 룰베이스 출처답변)  ├ 4050 검증후기 피드(유튜브·홈쇼핑式)
├ 시술 레슨(알고가기)          ├ 시술 비교 콘텐츠(F2 "울쎄라vs써마지") ├ 증상별(처짐/꺼짐/색소) 큐레이션
├ 근처병원(위치·상세·CTA)      ├ 순서 로드맵(F7 "뭐부터?")        └ 시술수첩 여정(§10, 후순위)
└ 상담 질문지                 └ 4050 어휘 랜딩·아티클
        ↑                            ↑                          ↑
   전환(상담·CTA)              획득(검색 트래픽)             리텐션·습관
```

- 하단 탭 3개: **홈(매칭) · 알아보기(콘텐츠) · 탐색(후기)**. 탐색은 MVP에선 "준비중 + 후기 남기기" 수집 모드로 시작.
- 콘텐츠는 **병원 모객용이기도 함**: "4050이 이렇게 모입니다" 증거 = 입점 영업 자료.

## 2. 우선순위 (P0 런칭블로커 → P1 성장 → P2 확장)

### P0 — 런칭 전 필수 (내일부터, ~1주)
| # | 항목 | 근거 | 구현 난이도 |
|---|---|---|---|
| P0-1 | **IA 3탭 재구성** + 랜딩 4050 실어휘 교체("확 늙은 것 같은 날"·"티 안 나게"·§56 필터) | 어휘 리서치·C2 | 하 (기존 화면 재배치) |
| P0-2 | **공개 Q&A 페이지(F6)** — 엔진 답변조립기 재사용, 시술×질문 정적 페이지 → SEO | 커뮤니티질문 87건 | 중 (엔진 재사용) |
| P0-3 | **비교 결정기(F2)** "울쎄라 vs 써마지, 나는?" — 레슨 compare를 독립 진입점化 | 비교 38건+설명공백 | 중 |
| P0-4 | **적정가 신호** 견적에 "이 가격대면 적정 범위" 밴드 | 가격불투명 30건·공장형 선택이유 1위 | 하 (카탈로그 min/max 활용) |
| P0-5 | **후기 수집 폼**(탐색 씨앗) — 시술·병원·나이대·만족도·본문, 영수증 인증 업로드(=우리 퍼널 결제 증거의 전신) | 탐색 필러 + 데이터 해자 | 중 (reviews 테이블 기존) |
| P0-6 | **딸 보내기(F1)** — 견적/레슨 결과 "엄마에게 카톡 공유" 딥링크(가입 없이 열람) | 딸자녀 43건(주류 유입) | 하 (공유 URL) |

### P1 — 런칭 직후 (2~4주)
| # | 항목 | 근거 |
|---|---|---|
| P1-1 | **상담 D-day 모드(F3)** 질문지+대응카드+견적 기록장(병원별 편차 시각화) | 사전무장·업셀 8건 |
| P1-2 | **회복 가이드(F4)** D+N 타임라인 "정상범위/병원연락" — 시술수첩(§10)의 첫 조각·**전후관리 가치의 시작** | 회복불안 25건 |
| P1-3 | **돈값 계산기(F5)** 월환산 비용 | 효과회의 30건 |
| P1-4 | **전문의 검증 배지** — 15001699 전파되면(probe) 전문과목·전문의수 인제스트 | 퀸잇 등식 1번 |
| P1-5 | **50대 IA 분기(F8)** 연령별 랭킹 가중치 | 8.1 랭킹 |
| P1-6 | **병원 입점 랜딩+문의폼**(영업 레이어 1호) — "4050이 모이는 곳" 콘텐츠 지표 첨부 | 모객 |

### P2 — 검증 후 (H1 인터뷰 결과 반영)
| # | 항목 | 조건 |
|---|---|---|
| P2-1 | **시술수첩**(여정 OS: 회복 다이어리→잔량바→재시술 리마인드) | H1에서 회복불안 강도 확인 후 |
| P2-2 | **입점 어드민**(병원 셀프 프로필·의료진 등록·정액광고 관리·§56 검수큐 = 0003 트리거 활용) | 입점 3곳+ |
| P2-3 | **우리 퍼널 결제 증빙 루프**(병원에 "우리 링크 경유" 증거 전달 — 링크아웃 UTM+예약확인 업로드) | 입점 후. §27 정액 유지, 건당수수료 금지 |
| P2-4 | **순서 플래너(F7)** 시각화 · **UGC 운영툴** · 40대 남성 트랙(F9) | 여력 |

**우선순위 논리**: P0은 전부 "이미 있는 엔진·데이터 재사용 + 획득(SEO)·전환(적정가)·유입루프(딸)"라 1주 안에 런칭 가능. 영업 레이어는 **트래픽 증거가 생겨야 영업이 되므로** P1 후반. 어드민은 입점이 생겨야 의미 있어 P2.

## 3. 내일 개발 킥오프 (gstack)

1. **아침**: `/plan-ceo-review`로 본 문서 P0 스코프 락(잘라낼 것 결정) — 15분
2. P0-1(IA)부터: `/spec` → 구현 → 브라우저 검증. 이후 P0-2~6 순서대로. 각각 PR 머지(브랜치 보호 절차 확립됨)
3. 병행: `bun run probe` 하루 1회 → ✅ 뜨면 P1-4 즉시 착수
4. H1 인터뷰 준비는 리서치 문서의 리크루팅 계획대로 별도 트랙

## 4. 리스크 메모
- 후기 수집(P0-5)은 **§56·개인정보 동의(§23)** 설계 필수 — 대가성 표기·민감정보 별도동의. 기존 leads 테이블 규약 재사용.
- "적정가 밴드"는 카탈로그 참고가 기반임을 명시(실거래 아님) — 시술수첩 실데이터가 쌓이면 실측 밴드로 승급.
- 의료진 프로필은 병원 제공 자료만 게시(공공 API 없음 확정) — 무단 크롤 금지.
