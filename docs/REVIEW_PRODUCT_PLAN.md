# 후기 제품 기획 — 수집 방식 결정과 3주체 설계

> 2026-08-15. 모두닥 정독(리뷰랜딩·파트너포털) + 경쟁사 수집방식 비교 리서치 + REVIEW_ROI.md 재확인.
> D3(B2B 범위)는 사용자 결정: **입점랜딩+문의폼까지**. D1(인증)·D2(보상)는 아래 리서치로 결정.

## 1. 플랫폼별 수집 방식 — 각자의 이해관계에서 왜 그렇게 했나

| 플랫폼 | 수집·인증 방식 | 왜 그렇게 했나 (이해관계) | 결과·교훈 |
|---|---|---|---|
| **모두닥** | 본인인증 + **영수증/홈택스 인증 필수** + 시스템 모니터링·검수팀 + 익명 게시. 보상은 **플랫폼이** 지급(병원결제 포인트·기프티콘). "특정 병원 유도 아님" 고지 | BM의 뿌리가 '리뷰 신뢰' 그 자체(리뷰 플랫폼→광고 수익화). 신뢰가 해자라 인증 필수. **할인몰 결제 데이터로 '작성 가능한 리뷰'를 자동 파악**해 인증 마찰을 흡수. 보상을 병원이 아닌 플랫폼이 줘서 §27·대가성 회피 | 53.5만 인증 후기 = 병원 394만 회원 소구의 핵심 자산 |
| **강남언니·바비톡** | 영수증 인증 있음. 단 병원-환자 간 "후기 조건 할인" 관행 → 병원 개입 후기(작성일 지정, 병원이 계정 확보해 대필) 논란(ZDNet 2022) | BM이 병원 광고·이벤트 전환이라 후기=병원 마케팅 자산. **병원이 후기 생산에 개입할 인센티브**가 구조에 내장 | 후기량은 많지만 4050이 가장 불신하는 지점("대가성 후기") — 우리 리서치 ⑥과 일치 |
| **네이버 플레이스** | 영수증 인증 단독으로 시작 → 대행업체 허위·중복·보상형 조작 범람 → 2025.10 **네이버페이·예약·위치기반·실명 다층 인증**으로 강화 | 트래픽 거인이라 수집량 걱정이 없음 → 신뢰만 문제 → 인증 강화 일변도 | **영수증 단독 인증도 조작 가능**(영수증 거래·대행). 인증 '수단'보다 검수·어뷰징 탐지가 본질 |
| **바비톡(콜드스타트)** | 후기 이전에 **익명 커뮤니티·Q&A**(심리적 지지 공간)로 시작 → 후기로 확장 | 민감 시술 카테고리는 '털어놓을 곳'이 먼저 모임 | 콜드스타트는 인증이 아니라 **말할 이유**가 만든다 |
| **집품** (ROI 문서) | 공공데이터 프로그래매틱 페이지로 트래픽 → **방문자 전환형** 보상 | 트래픽을 사지 않고(콜드 CAC 회피) 이미 온 방문자의 전환만 지불 | 우리 순서와 동일(병원 2,791 공개 페이지 先) |

**교훈 3줄**: ① 인증 수단은 조작될 수 있다 — 신뢰는 '필수 인증'이 아니라 **검수 + 병원 개입 차단 원칙**에서 나온다. ② 인증 마찰은 결제 데이터(모두닥)나 트래픽(네이버)이 있어야 감당된다 — 우리는 둘 다 없다. ③ 보상은 병원이 아니라 플랫폼이, 트래픽 위에서만.

## 2. 결정

### D1 인증 강도 → **영수증 '선택' + 배지 구분 + 전수 검수** (게시 기본값: 검수 대기)
- 근거: 네이버 사례 = 영수증 필수여도 조작됨(수단≠신뢰). 모두닥의 필수 인증은 결제 인프라가 마찰을 흡수했기에 가능 — 우리는 없음. 4050은 홈택스 인증 같은 절차에 마찰이 큼(리서치: 앱 강제=진입장벽).
- 설계: 제출 시 영수증 사진 **선택** 첨부 → 첨부·확인분만 `✓ 실방문 인증` 배지. 미첨부는 검수 통과 시 `미인증` 라벨로 구분 게시. **모든 후기는 hidden으로 들어와 검수 후 공개**(§56 필터 + 수기 확인).
- **병원 개입 차단 원칙**(강남언니 반면교사, 명문화): 병원 경유 작성 요청·작성일 지정·대필 정황 시 게시 거부. 부정 후기 삭제 압력에 불응(ROI 문서 §4).

### D2 보상 → **단계식: 지금 무보상 → 트래픽 후 방문자 전환형 기프티콘** (ROI 문서 그대로)
- 1단계(지금): 무보상. "같은 고민 하는 또래에게 도움" 프레임(4050 커뮤니티 환원 문화가 실증됨 — 리서치 §1 사후 행동). 초기 물량은 H1 인터뷰(15~20명 사례비 기지급)·지인 스노우볼에서 **+0원**으로.
- 2단계(공개 페이지 트래픽 발생 후): 방문자 전환형 기프티콘 5,000원, kill rule(후기당 월 유입증분 < 2세션 × 2개월 → 중단). 표시광고법 표기("기프티콘을 받고 작성").
- 스키마에 `reward_disclosed` 필드를 지금부터 넣어 2단계 전환 시 코드 변경 최소화.

### D3 B2B 범위 → **입점랜딩 + 문의폼** (사용자 확정)
- 모두닥 파트너 포털 분해: 무료(프로필·사진·영업시간 셀프관리 + 리뷰 답글) = 입점 훅 / 유료(이벤트 노출·신청정보 엑셀·성과 리포트) = 수익화.
- 지금 구현: `/partners` 랜딩 — 소구(전국 2,791 노출·광고 순위 없는 거리순·4050 타깃·무료 프로필 등록 약속·정액 광고 안내 §27) + 문의폼(`partner_inquiries`).
- 입점 3곳 달성 시: 셀프 프로필 포털 → 리뷰 답글 → 노출 상품(정액) 순으로 단계 개방.

## 3. 3주체 설계

```
[유저]                         [우리(운영)]                    [병원(고객사)]
후기 쓰기(익명·§23 동의)   →   검수 큐(hidden 기본)        →   (입점 후) 새 후기 알림
영수증 선택 첨부           →   §56 필터 + 수기 확인            리뷰 답글(포털 단계)
'또래에게 도움' 프레임      →   인증 배지 부여                  부정후기 삭제 압력 불응 원칙
                              표시광고법·개입차단 집행          입점랜딩 → 문의폼 → 세일즈
```

- 유저 UX(4050): 큰 글씨 단일 폼(멀티스텝 아님 — 이미 앱에 익숙해진 뒤가 아니라서 이탈 최소화), 필수 5개(시술·병원명·연령대·만족도·본문), 선택 2개(경과 주차·영수증), §23 민감정보 동의 1체크 + 병원 무관 서약 1체크. 제출 후 "검수 뒤 공개돼요" 정직 고지.
- 우리 운영: 게시 기본값 hidden → 검수 후 shown. is_adverse(부작용 언급)는 내리지 않고 유지(신뢰 자산 — 스키마에 이미 존재).
- 병원: 지금은 랜딩+문의폼만. 문의는 `partner_inquiries`에 적재(엑셀 export는 Supabase 대시보드로 충분).
