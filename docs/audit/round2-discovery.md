## 공격 결과

**A — 악의적 준수: 결함 3건**

1. **프레임 절단으로 상위노출 편향을 재생산한다 (치명적).** K-5 는 소스를 `map_category_enumeration`(전수 나열)·`public_license_registry` 로 잠그고 필터에 가격·예약·광고·평점정렬·검색상위N 토큰을 금지했다. 그런데 REQ-1 검사는 `population.csv ≥ 300행` — **하한만 있고 전수성 검증이 없다.** 지도 서비스의 기본 정렬은 인기·광고 가중 정렬이므로, "전수 나열" 을 시작해 300행에서 멈추면 **금지 토큰을 한 개도 쓰지 않고** K-5가 금지한 "검색 결과 상위 N" 을 정확히 얻는다. 검사기는 300행·9칸≥20·토큰 0매칭을 모두 통과시킨다.
2. **카테고리 용어 집합과 축 결정표가 무잠금이다.** 어떤 카테고리 키워드로 나열할지(예: medical 축을 "도수치료 전문의원"으로 좁힐지 "한의원" 전체로 잡을지), 그리고 REQ-4가 말하는 **protocol.md 의 "축 결정표"** 를 누가 어떻게 정하는지에 대한 하한이 계약에 없다. G1은 축별 판정이므로, 축 결정표 한 장으로 어떤 업종이 어느 축의 분자·분모에 들어가는지가 결정된다. D1b FORBID-2 는 *조사 중 축 재배정*만 막고, **사전 배정의 편향은 막지 않는다.**
3. **판정이 점추정으로만 내려진다.** K-4(0.40/0.25)와 REQ-6(Wilson 95% 구간 산식)이 함께 있는데, **REQ-7의 verdict 규칙은 구간을 사용하지 않는다.** 축별 유효표본은 33 내외이므로 Wilson 구간은 ±16~17%p다. 참값 30%인 축이 `proceed` 로, 참값 45%인 축이 `axis_excluded` 로 확정될 확률이 실질적으로 존재하며, 그 판정은 계약을 100% 준수한다. 구간을 계산해 기록하되 판정에 쓰지 않는 것은 "측정했다"는 외관만 만든다.

**B — 조건 회피: 결함 2건**

- **K-3 #1 "현재 게시"에 최신성 요건이 없다.** K-2 는 *종료된 이벤트 가격*만 금지한다. 2023년에 올린 인스타 게시물의 가격표는 삭제되지 않았으므로 "현재 게시"이고 `price_found=true` 다. H1은 "지금 크롤러가 가져와 노출할 수 있는 가격"의 대리 지표인데, 이 정의는 그것을 측정하지 않는다. 조건을 아슬아슬하게 비껴가는 대표 사례.
- **K-3 #2 "동일 페이지"가 넓다.** 금액 숫자와 서비스명이 같은 페이지에 있기만 하면 되므로, 상담료·주차료·타 지점 가격·인접 광고 영역의 금액이 "대상 서비스명"과 같은 롱페이지에 있을 때 판정이 사람마다 갈린다. 이 모호성은 D1b 이중판정(agreement ≥ 0.90)이 흡수하도록 설계됐으나, 이중판정의 독립성이 자기신고다(§D1b 공격 C).

**C — 탐지 무력화: 결함 2건**

- **메타테스트 5종이 FORBID-1~5 만 덮는다.** `--check sampling`(고정 시드 재현) · `--check aggregation`(이중판정 시드 재산출) · `--check ledger-schema`(JSON Schema draft 2020-12) 에 대응하는 위반 픽스처가 없다. 이 세 검사를 `return 0` 으로 구현한 `validate_d1a.py` 는 D1a 메타테스트 5종을 전부 통과하고, F1 FORBID-6("인자 없이 항상 exit 0")도 통과한다 — **부분 스텁은 잡히지 않는다.**
- **메타테스트가 REQ가 아니다.** done_when 은 CI가 판정하지 않는다. CI 가 실제로 돌리는 것은 `--all` 뿐이며, 그것은 저자의 데이터로 exit 0 이 나오는지만 본다.

**D — 지름길 유도: 결함 1건 + 방어 확인**

## 공격 결과

**A — 악의적 준수: 결함 2건 (둘 다 치명적)**

1. **전 행 `price_found=false` 가 최단 준수 경로다 (원칙 2.5 정면 위반).**

2. **D1a 재실행으로 사전등록을 무력화한다 (P2 잔존 우회로).**
   D1b out_of_scope 는 명시적으로 *"protocol.md 수정 — 수정이 필요하면 **D1a 재실행**"* 을 허용하고, D1a rollback 도 재실행을 전제한다. 그런데 **어느 계약도 (a) 재등록 횟수, (b) 재등록 사유 기록, (c) `ledger.checked_at` 이 현재 lock 이 main 에 들어온 시각 이후일 것을 요구하지 않는다.** 따라서:
   `D1a v1 머지 → (PR 없이) 표본 100건 예비 조사 → 37% 확인 → D1a v2 머지(프레임 카테고리·축 결정표·definition_examples 를 K 제약 안에서 재선택) → D1b 제출`

**B — 조건 회피: 결함 3건**

- **`blocked ≤ 5` 상한이 어느 acceptance/FORBID에도 없다.** K-6·done_when 에만 있고, 검사되는 것은 `n ≥ 90`(REQ-4)과 `replacement_log ≤ 5` 뿐이다. `blocked = 9, unreplaceable = 0` 이면 n = 91 로 통과한다. `blocked` 는 곧 조사 회피이므로 상한이 실효 없는 것은 그대로 조사 소진 요건의 구멍이다.
- **`n < 90` 이 전역 수치인지 축별인지 확정되지 않았다.** 축별 primary 는 34/33/33 이므로 축별로 읽으면 항상 `inconclusive`, 전역으로 읽으면 **한 축에 손실이 몰려도 발동하지 않는다.** blocked 5 + 교체불가 5가 한 축에 몰리면 그 축 유효표본은 23~28인데 전역 n=90 이라 확정 verdict 가 나간다. FORBID-4의 `when` 이 "…인 축이 존재하는 경우"라 문장 자체가 전역 값을 축 단위 조건에 끼워 넣고 있다.
- **`not_present` 는 무증거 코드다.** REQ-3은 값이 "URL 형식이거나 허용 코드 2종 중 하나"면 통과시키므로, 확인하지 않고 false 처리하는 경로를 차단하겠다는 REQ-3의 주석과 실제 검사가 어긋난다. 제약은 `channel_absent` 5개 행 비율 ≤ 10% 하나뿐이고 이는 `not_present` 로 전량 회피된다.

**C — 탐지 무력화: 결함 2건**

- **이중판정의 독립성이 여전히 자기신고다.** 검사는 `cohort` 값이 서로 다르고 "각 판정에 별도 스냅샷 취득 시각"이 있는지다. 조사 주체는 단일 `research-discovery` 이고 cohort 는 자유 문자열이며, 취득 시각 두 개는 같은 페이지를 두 번 저장하면 생긴다. **같은 판정을 두 번 적으면 agreement = 1.00.** 특히 위 공격 A-1 하에서는 이 장치가 아무 마찰도 만들지 않는다.
- **`origin/main...HEAD` 가 CI 체크아웃 깊이에 의존한다.** shallow clone(기본 `fetch-depth: 1`)에서는 merge-base 를 계산할 수 없어 검사가 에러 또는 스킵된다. FORBID-1 은 이 배치의 **유일한 사전등록 집행 장치**이므로 detect 에 "full fetch 또는 base ref 명시 fetch"를 조건으로 못박지 않으면 조용히 무력화될 수 있다.

**D — 지름길 유도: 결함 1건(=공격 A-1) + 방어 확인**

- 방어됨: 표본 갈아끼우기(FORBID-2 대칭차집합) · 스니펫 창작(FORBID-3 부분문자열+sha256) · 홀드아웃 선개봉(FORBID-5 재집계 동등) · 캡차 우회(FORBID-6). 1차 지적을 정확히 막았다.

**E — DAG 정합성: 결함 2건**

5. **이중판정 독립성 강화** — cohort 를 자유 문자열이 아니라 `owner_agent` 와 다른 주체(예: 팀 리드 배정 2차 조사자)로 규정하고, 두 판정의 스냅샷 sha256 이 서로 달라야 함(동일 파일 복제 금지)을 검사. *이유: agreement 는 현재 자기복제로 1.00 이 된다.*
6. **`docs/gates/G1.md` 스키마를 계약 고정 상수로 못박아라** — F1 REQ-7 스키마와 F4 파서가 동시에 성립하는 단일 정의(필드명·per_axis enum·기계 판독 형식)를 D1b 본문에 표로 고정하고, 가능하면 `docs/gates/G1.json` 같은 기계 판독 발행물을 함께 산출. C4가 가정하는 `config/g1-axes.json` 의 생산자도 여기서 확정. *이유: 현재 3개 계약이 같은 파일에 대해 서로 다른 스키마를 요구한다.*
7. **rollback 2) 수정** — F4 외에는 자동 차단이 없음을 사실대로 기재하거나, C1·C4 계약에 게이트 파싱 선행 검사 추가를 상신. **`scripts/discovery/fixtures/d1b/**` 를 touches 에 추가.**

## 공격 결과

**A — 악의적 준수: 결함 2건**

1. **K-4 통과 기준이 산술적으로 100/100 을 요구한다 (치명적, 방향은 역설적).** 실측 대상은 K-2 에 의해 정확히 **상위 100개**로 상한이 걸려 있는데, 통과 기준은 "엔진별 `enterable ≥ 100`" 이다. 즉 **측정한 100개가 두 엔진 모두에서 전부 enterable 이어야 통과**한다. `blocked` 가 1건이라도 있으면(FORBID-4는 20건까지 허용) 그 순간 100 달성이 불가능하다. 결과적으로 계약을 성실히 수행하면 G2 는 사실상 항상 `channel_redesign` 이 되고, H3("100개 이상 존재한다")는 **검증된 적 없이 기각**된다. 개발 에이전트가 막혔을 때 취할 행동은 (a) 실측 개수를 임의로 늘리거나 (b) K-4 를 재해석하는 것이며, 둘 다 계약 밖 재량이다.
2. **`ugc_ratio ≥ 0.5` 의 UGC 판정 기준이 무잠금이다.** K-1은 대형 플랫폼 **제외 목록**만 고정했다. 제외 후 남는 도메인 각각을 "개인 블로그·카페 글·커뮤니티 게시물"로 볼지 여부의 판정 규칙이 없고, `--check difficulty` 는 "라벨이 룰 재적용 결과와 일치"하는지(내부 일관성)만 본다. 임계 두 개 중 하나가 저자 재량이면 하한을 못박은 효과의 절반이 사라진다. 더욱이 UGC 의 주 서식지(blog.naver·cafe.naver·tistory)가 K-1 제외 목록에 있어, 남은 도메인에서 UGC 비중 0.5를 만족시키는 것이 무엇을 의미하는지 정의가 필요하다.

**B — 조건 회피: 결함 2건**

- **FORBID-6의 탈출구가 자유 문자열이다.** `when` 은 "프록시 로테이션·캡차 우회·자동 재시도" 인데 detect 는 "blocked 조합에 serp 행이 있으면서 `collection_note` 에 `manual_recheck` 표기와 재캡처 스냅샷이 없으면 실패". 즉 **`manual_recheck` 라고 적고 스냅샷을 붙이면 프록시로 얻은 캡처도 합법**이다. 금지 대상(취득 수단)은 관측 불가하고 탈출구는 1바이트다.
- **`no_volume_data` 가 조용한 배제 통로다.** REQ-2는 volume 빈칸 행을 `status='no_volume_data'` 로 허용하고, K-2는 volume 합 < 30 을 분자·분모 모두에서 제외한다. 도구가 값을 주지 않았다고 신고하면 어떤 키워드든 측정 대상에서 빠진다. 도구 응답 물증(스크린샷·CSV export)을 요구하는 REQ가 없다 — SERP 스냅샷에는 물증을 요구하면서 검색량에는 요구하지 않는 비대칭.

**C — 탐지 무력화: 결함 1건**

- **대조군 봉인이 같은 PR 안에서 이뤄진다 (C-1).** "difficulty_rule 확정 **후** 개봉" 은 단일 PR 산출물로는 증명할 수 없다. D1 이 정확히 이 이유로 D1a/D1b 로 분할됐음을 감안하면, D2 의 유일한 자기채점 차단 장치가 같은 결함 위에 서 있다. 게다가 대조군 20건과 그 기대 라벨을 저자가 만들었으므로, 봉인 순서가 지켜져도 "저자의 육안 판단 ↔ 저자의 룰"의 일치를 확인할 뿐 외부 정박이 없다.
- 방어 확인: FORBID-3의 **csv↔스냅샷 도메인 목록 100% 대조**와 로그인 지표 정규식은 실제로 위반을 포착한다. `capture_mode` 자기신고를 물증으로 승격한 것은 이 배치에서 가장 잘 작동하는 detect 중 하나다.

**D — 지름길 유도: 결함 1건**

- 임계 낮추기는 FORBID-1이, 초장문 키워드 양산은 FORBID-2가, blocked 남발은 FORBID-4가, 엔진별 결합 회피는 FORBID-5가 막는다. **남은 최단 경로는 `blocked` 20건 + `no_volume_data` 다량 신고**로 실측 부담을 줄이는 것이며, 이는 위 B-2 와 결합해 G2 를 `inconclusive` 로 몰고 간다. `inconclusive` 는 이 계약에서 아무 불이익이 없다.

**E — DAG 정합성: 결함 1건**

- **`blocks: [W1]` 이 역방향 없이 떠 있다.** W1 은 D2 없이 착수·머지 가능하다. D2 `why` 는 "W1·W4에 투입할 개발 비용"을 근거로 삼는데, 정작 W1 은 G2 판정을 기다리지 않는다. (W4 는 `depends_on` 에 D2 가 있어 정상.) 매니페스트가 잡지 못하는 방향이므로 판단으로 지적한다.

**F — 존재 이유: 이상 없음**

H3의 임계(1페이지 진입 롱테일 ≥ 100)를 직접 측정하며 G2 판정을 산출한다. 다만 위 A-1 때문에 **측정 설계가 가설의 임계와 정합하지 않는다** — 존재 이유는 맞고 설계가 틀렸다.

## 필수 수정 사항

1. **K-2 와 K-4 를 정합시켜라.** 둘 중 하나: (a) 실측 대상을 "volume ≥ 30 인 키워드 중 상위 **300개**"로 확대하고 통과 기준을 `enterable ≥ 100` 유지, 또는 (b) 통과 기준을 `enterable 비율 ≥ X%` + `추정 총 enterable 모수 ≥ 100`(실측 비율 × volume≥30 키워드 총수, 구간 추정 포함)로 전환. *이유: 현재 설계로는 성공이 정의상 불가능하다.*

3. **대조군을 D2 밖으로 빼거나 외부 정박하라 (C-1).** 최소안: 대조군 20건의 키워드 목록과 기대 라벨 해시를 **D2 PR 이전에** 별도 PR/이슈로 등록(GitHub 서버 시각은 위조 불가)하고, D2 는 그 해시를 참조만 한다. 대안: 대조군 추출을 `volume ≥ 30` 모집단에서 고정 시드 무작위로 규정. *이유: 같은 PR 안의 봉인은 순서를 증명하지 못한다 — D1 분할의 근거와 동일.*
4. **검색량에도 물증 REQ 를 부과하라** — `no_volume_data` 행에 도구 응답 export 파일(csv/스크린샷) + 조회 시각 필수. *이유: 분모에서 조용히 빠지는 통로.*
5. **FORBID-6 detect 보강** — `manual_recheck` 문자열이 아니라 **차단 시각과 재캡처 시각의 간격 하한(예 ≥ 30분) + 재캡처 스냅샷의 응답 헤더(Date) 보존**을 검사. *이유: 현재 탈출구는 문자열 한 개다.*
6. **`docs/gates/G2.md` front-matter 를 F1 게이트 스키마와 일치시켜라** (C-2). **W1 `depends_on` 에 D2 추가를 상신하거나 `blocks` 에서 W1 제거.** **`scripts/discovery/fixtures/d2/**` 를 touches 에 추가.**

G3의 존재 이유(법적 실사)가 통째로 자기신고가 된다.
   D1b FORBID-3의 because 는 이 실패 양식을 이미 정확히 서술했다 — *"`evidence_channel` enum 과 URL 존재만 검사하면 아무 페이지 URL 을 넣고 스니펫을 지어내는 것으로 전 검사를 통과한다 — 형식 검사가 아니라 내용 검사여야 한다."* D3는 같은 배치 안에서 그 교훈을 적용하지 않았다.
2. **K-6 의 "최소 확보 하한"에 서류 도피로가 있다.** `allowed|conditional` < 2 여도 `report.md` 에 `data_acquisition_blocked` + **대안 소스 3건 실사표**를 붙이면 `--check reachability` 는 exit 0 이다. 대안 3건의 verdict 에는 아무 요건이 없으므로 전부 `pending` 으로 적어도 된다. 즉 **"전 소스 수집 불가" 상태가 서류 3장으로 합법화**된다. 원칙 2.5 의 짝으로 K-6를 도입한 취지(리스크 0 = 제품 0 회피)가 절반만 달성됐다. (다만 법적 실사에는 정말로 "전부 금지"라는 참인 결론이 있을 수 있으므로, 요구되는 것은 금지가 아니라 **에스컬레이션의 기계 검증 가능성**이다 — 현재 "팀 리드에게 에스컬레이션"은 탐지 수단이 없다.)

**B — 조건 회피: 결함 2건**

- **`pending` 이 무제한 도피처다.** `pending` 은 ToS 확보 실패 상태이고 어댑터 대상에서 빠지는 것 외에 아무 비용이 없다. K-3 필수 3소스(naver_place·kakao_map·official_website)를 전부 `pending` 으로 두어도 REQ-1(실사표 작성)만 충족하면 되고, REQ-3~6의 부담(crawl_policy·HAR probe·republish·reachability)은 **전부 면제**된다. 가장 비용이 낮은 준수 상태가 "아무것도 수집 가능하지 않다"이며, 여기에 K-6 서류 도피로가 붙는다.
- **FORBID-4 `when` 의 동기 조건**(위 표 참조). detect 가 넓으므로 실효는 있으나 `when` 이 사문화되고, 규격 §3.2("판정 가능")를 어긴 조건문이 계약 본문에 남는다.

**C — 탐지 무력화: 결함 2건**

- **HAR 은 저자가 통째로 생성할 수 있는 파일이다.** REQ-4·FORBID-3의 검사는 "log ↔ HAR 20/20 대응", "HAR 기준 429·403 = 0", "HAR 타임스탬프 60초 윈도우" — **전부 HAR 내부 정합성**이다. HAR 은 사람이 손으로 쓸 수 있는 JSON 이므로, 실제 요청을 한 번도 보내지 않고 이상적인 HAR 을 작성하면 전 검사를 통과한다. D1b 가 스냅샷에 대해 요구한 **외부 정박(추출 텍스트의 부분문자열 + sha256 대조)** 에 해당하는 장치가 없다.
- **robots 검사만 내용 검사이고 ToS·PII 는 각각 형식·샘플 검사다.** FORBID-5(PII)는 저자가 고른 **샘플값 3건**만 본다. 실제 필드값 분포에 개인 식별자가 섞여 있어도 샘플 3건을 무해한 값으로 고르면 통과한다. 값 기준으로 승격한 것은 개선이나(1차 지적 반영), 표본을 저자가 고르는 한 자기채점이다.

**D — 지름길 유도: 결함 1건 + 방어 확인**

- 방어됨: **요청률 낮추기**(FORBID-4 + K-2 하한 6)는 이 배치에서 가장 잘 설계된 지름길 봉쇄다. 글롭 밖 경로 검증(FORBID-6), robots 실경로 대조(FORBID-1)도 실효가 있다.
- 남은 최단 경로: **소스를 `pending` 으로 두는 것**(위 B-1). REQ-3~6 의 실작업 전부가 면제되므로 압도적으로 싸다.

**E — DAG 정합성: 결함 1건(경미)**

- `blocks: [C1, C2, C3]` 는 전부 역방향 성립. `depends_on: [F1]` 정당.
- **K-4 의 tombstone 값이 F2a 와 어긋난다.** D3: "payload 컬럼만 **tombstone 문자열**로 대체". F2a REQ: "`tombstone_source_record(id, reason)` … **raw_payload 가 NULL**, tombstoned_at·tombstone_reason 기록". 방식(행 보존)은 일치하나 값 규약이 다르다. D3 는 F2a 를 `depends_on` 하지 않으므로(정당) **두 계약이 서로를 검증하지 않는다** — C1 이 두 규정을 동시에 만족시키려 할 때 드러난다.

**F — 존재 이유: 이상 없음(경미한 지적)**

G3 판정을 직접 산출한다. S1 참조는 인과가 2단계 떨어져 있으나(소스 확보 → 가격 수집 → 회당 단가) 규격상 허용 범위.

## 필수 수정 사항

1. **ToS 검사를 내용 검사로 승격하라** — `verdicts.csv` 에 `tos_clause_text`(인용 원문)를 추가하고, (a) 그 문자열이 ToS 스냅샷 추출 텍스트의 **부분문자열**일 것, (b) 계약이 제공하는 **금지 표현 사전**(크롤링·자동화된 수집·로봇·스크래핑·복제·재배포 금지 계열 정규식)과 대조해 매칭 시 기본값 `forbidden`, 예외는 `exception_reason` + 팀 리드 승인 라벨로만 뒤집기. *이유: 현재는 조항 번호 하나로 어떤 소스든 `allowed` 가 된다.*
2. **`pending` 에 비용을 부과하라** — K-3 필수 3소스가 `pending` 인 경우 G3 verdict 를 `inconclusive` 로 강제하고(어댑터 대상 0), report.md 에 재시도 계획 + 재실사 기한 기재를 REQ로. *이유: 가장 싼 준수 상태가 "아무것도 못 한다"이면 그것이 선택된다.*
3. **HAR 을 외부 정박하라** — probe 응답의 `Date`·`Server` 헤더 보존 + reachability 스냅샷 파일의 sha256 이 HAR 엔트리 content 해시와 일치할 것을 검사. *이유: 현재 물증은 저자가 손으로 쓸 수 있는 JSON 이다.*
4. **PII 샘플 3건의 추출 방법을 규정하라 (R-6)** — 각 allow_field 에 대해 reachability 10건에서 **고정 시드 무작위 3건**을 뽑아 기재. *이유: 표본을 저자가 고르면 값 기준 검사도 자기채점이다.*
5. **FORBID-4 `when` 에서 동기 표현 제거** — "`max_requests_per_min` < 6 인 소스가 `forbidden` 이 아닌 경우"로 재작성. **K-2 문장 수정** — "요청률 6 이상에서 429 를 회피할 수 없는 소스는 `forbidden` 으로 판정한다".
6. **K-4 tombstone 값 규약을 F2a(`raw_payload IS NULL` + tombstoned_at/reason)와 일치시켜라.** **`docs/gates/G3.md` front-matter 를 F1 스키마와 일치**시키고, **`scripts/discovery/fixtures/d3/**` 를 touches 에 추가.**

## 공격 결과

**A — 악의적 준수: 결함 3건**

1. **코퍼스 40건의 추출 방법이 없어 분모를 고를 수 있다 (R-6 미충족).** K-4 는 "지도 서비스 강남3구 × medical_wellness 전수 나열 · 가격 속성 필터 금지" 까지만 정한다. 그 프레임에서 **어떤 40건을 뽑는지**가 없으므로, 화이트리스트가 잘 매칭될 표기 형태(단순 "OO 10회 50만원")를 가진 업체 40곳을 고르면 `show_ratio` 는 dev·holdout 모두 0.9 를 넘고 REQ-4·FORBID-2 는 만점이다. **현실의 medical 가격 표기는 여전히 대부분 hide 될 수 있다.** D1a 가 `sample.csv` 에 대해 고정 시드 층화 무작위를 못박은 것과 대조된다.
2. **`no_price_display` 가 자기신고 분모 조정 손잡이다.** show 비율의 분모는 "가격 표기가 존재하는 건" 인데, 어떤 건이 표기 보유인지는 저자가 기록한다(K-4). `--check corpus` 는 스냅샷 존재·부분문자열만 보고, **표기가 있는데 `no_price_display` 로 적었는지는 검증하지 않는다.** 판정하기 까다로운 표기를 분모에서 빼면 하한 0.60 은 언제든 충족된다.
3. **lexicon 20개 정규식이 공허해도 만점이 나온다.** REQ-5 검사는 "정규식 ≥ 20 · 컴파일 성공 · **저자가 만든 golden hit 20 / miss 20 과 100% 일치**" 다. `origin: observed ≥ 0.5` 는 lexicon 케이스 **전체**에 대한 비율이므로, **hit 20건을 전부 synthetic(자기 정규식에 맞춘 문자열)으로, miss 20건을 observed 로** 채우면 비율 0.5 를 만족한다. 결과: 실제 광고 문구를 하나도 잡지 못하는 사전이 전 검사를 통과한다. **규제 방어 방향(미탐지)에는 실측 하한이 없다** — 과잉 hide 방향에만 K-5 하한을 세운 비대칭.

**B — 조건 회피: 결함 1건**

- **FORBID-5 는 `applies_to` 에 비-medical 축이 **포함**된 경우만 발동한다.** 하류(W1·W2·W3·W4·W5·W6)는 "D4 사전으로 렌더 HTML 스캔"을 축 필터 없이 규정하고 있으므로, `applies_to: [medical_wellness]` 만 붙은 규칙이라도 **하류가 전 축에 무차별 적용**하면 필라테스·스파의 "신규 할인"이 차단된다. D4는 스키마에 `applies_to` 를 필수화했을 뿐, **하류가 그것을 읽도록 강제하는 규약(예: 판정 함수가 axis 인자를 요구하도록 export 형태를 제한)은 REQ-7의 시그니처 한 줄뿐**이고, 하류 계약은 그 함수가 아니라 "사전 파일 grep"을 쓴다. FORBID-5의 because 가 서술한 실패가 FORBID-5 를 지켜도 발생한다.

**C — 탐지 무력화: 결함 2건**

- **홀드아웃 10건 봉인이 같은 PR 안에 있다 (C-1).** "룰 확정 후 개봉" 은 단일 PR 산출물로 증명 불가. 저자가 먼저 열어 display 포맷을 맞춘 뒤 재봉인해도 산출물은 동일하며, REQ-4의 **격차 < 0.20 검사는 오히려 양쪽에 맞췄을 때 가장 잘 통과**한다. 과적합 검출 장치가 과적합의 증거를 지운다.
- **하류 detect 가 존재하지 않는 파일을 스캔한다 (P6).** W1 FORBID / W2 FORBID / W3 FORBID / W4 FORBID / W5 detect / F4 REQ-3·FORBID-3 가 `docs/discovery/D4/forbidden_lexicon.yaml` 을, C6 FORBID-2 가 `medical_scope.yaml` 을 지목한다. D4 `touches` 는 `docs/discovery/D4/report.md` 만 허용하므로 **그 경로들은 생성되지 않는다.** F4 는 "사전 파일이 없으면 exit 1" 이라 영구 차단, W1~W6는 매칭 0건으로 **조용히 통과**한다 — 1차 감사 P6 의 지적("없는 파일을 스캔하는 테스트는 스텁이 되고 스텁은 항상 통과한다")이 그대로 유효하다. 추가로 F4 REQ-3의 `guardrail_ref` 정규식 `^MED-[A-Z]-\d{2}$` 는 D4 K-2 의 `-X` 접미 rule_id 를 **거부**한다.

**D — 지름길 유도: 결함 1건**

- 방어됨: `default_action: hide` 강제(FORBID-1), 골든 기대값 수정 금지(FORBID-6), advisory 네임스페이스 분리(FORBID-3), 근거 조문 형식(FORBID-4).

**E — DAG 정합성: 결함 2건**

- `depends_on: [F1]` 정당, blocks 나머지 10건은 역방향 성립.

**F — 존재 이유: 경미한 결함**

S1·S3 는 성립(medical 축의 가격·리포트 표기를 이 규칙이 좌우한다). **G4 는 부정확** — PRD G4 는 "가격 신뢰도 스코어 임계"이며 D4는 그것을 생산·검증하지 않는다. v1 의 G3·H1 오참조를 제거한 판단은 옳으나, 대체로 넣은 G4 역시 정합하지 않는다. `hidden_legal` 을 소유하는 C7 을 경유한 간접 참조임을 명시하거나, 규제 리스크에 대응하는 지표/솔루션 참조로 교체해야 한다.

## 필수 수정 사항

1. **K-4 에 추출 방법을 못박아라 (R-6)** — "프레임에서 **고정 시드 무작위 40건**(구별 층화, 시드는 `report.md` 기재, 재실행 재현 검증)". `--check corpus` 에 시드 재현 검사 추가. *이유: 분모를 고르면 show 하한 0.60 은 아무것도 보장하지 않는다.*
2. **`no_price_display` 판정을 검증 가능하게 하라** — 각 `no_price_display` 건에 대해 5채널 확인 결과(또는 최소 공식 웹 + 지도 등록정보 스냅샷) 첨부를 REQ로. *이유: 분모에서 빼는 것이 무비용이면 그것이 선택된다.*
3. **lexicon 에 실측 하한을 부여하라 (R-7 · 미탐지 방향)** — golden `kind=lexicon` **hit 케이스의 `origin: observed` 비율 ≥ 0.5** 를 별도로 요구하고, hit 케이스는 코퍼스/홀드아웃 원문에서 추출한 문자열이어야 하며 각 hit 에 출처 스냅샷 경로를 기재. *이유: 현재는 자기 정규식에 맞춰 지어낸 20문장으로 만점이 나온다.*
4. **홀드아웃 10건을 외부 정박하라 (C-1)** — 코퍼스 수집·봉인을 **선행 PR**(또는 해시 사전 등록)로 분리하거나, 홀드아웃 라벨링 주체를 다른 owner_agent 로 지정. *이유: 같은 PR 안의 "룰 확정 후 개봉"은 증명 불가하며, 이는 D1 분할의 근거와 동일한 논리다.*
5. **P6 를 끝까지 집행하라** — K-1 에 **경로 이행 규정**을 추가: (a) `docs/discovery/D4/**` 에 규칙 yaml 을 생성하는 것을 FORBID 로 금지(현재는 touches 로만 암시), (b) 하류가 인용해야 하는 **정확한 심볼**(`import { evaluate } from '@glowmate/legal-medical'` + `exported_rules.json` 의 `rule_id`)을 계약에 명시, (c) 하류 8건의 detect 문자열 정정을 **상신 목록으로 열거**(W1·W2·W3·W4·W5·W6·C6·F4 + F4 의 rule_id 정규식에 `-X` 허용). *이유: 정본만 바꾸고 인용처를 두면 하류 detect 6건이 스텁이 된다 — 1차 지적이 그대로 유효하다.*
6. **C6 `depends_on` 에 D4 추가 상신**, **82~84행 상신 주석을 현재 상태로 정정**, **`scripts/discovery/fixtures/d4/**` 를 touches 에 추가**, **`traces_to` 의 G4 참조 근거를 C7 경유로 명시하거나 교체.**
