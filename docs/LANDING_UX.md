# 랜딩페이지 UX 인사이트 (Toss + 전환형 SaaS 랜딩 리서치)

Mobbin에서 Toss(앱) + Craft·Podia·Height·Superhuman·Better Stack·Cake·Maze(웹 랜딩) 리서치 후 정리. 우리 홈에 적용할 원칙만 추림.

## A. Toss에서 배울 것 (앱 문법)
1. **1문장 = 1생각, 볼드 헤드라인**. 줄바꿈으로 호흡을 만든다. ("신용점수, 대체 왜 필요할까요?")
2. **질문형·개인화 헤드라인**. "이지인님의 대출 금리는 신용점수에 따라 달라져요" — 남 얘기가 아니라 내 얘기로.
3. **아이콘 + 베네핏 라인 스택**. 기능이 아니라 "그래서 나한테 뭐가 좋은지"를 3줄로. (신용점수↑ → 금리↓ / 한도↑)
4. **하단 단일 고정 버튼**. 파란 풀폭 하나. 경쟁 CTA 없음.
5. **큰 숫자로 페이오프 시각화**. "932점 ▲30점" — 결과를 눈으로 보여준다.
6. **3D 이모지 포컬 1개**. 장식 아닌 시선 고정점.

## B. 전환형 웹 랜딩 정석 (Craft·Podia·Height…)
1. **Above-the-fold 완결**: 가치 제안 + 단일 CTA가 스크롤 없이 보인다.
2. **헤드라인은 베네핏, 서브는 한 줄 부연**. Craft "Create documents, make impact" / Podia "A simpler, smarter, better way…".
3. **CTA는 하나를 반복**. 히어로에 1개, 페이지 끝에 같은 1개(Better Stack "Downtime ends today" → Sign up). 경쟁 버튼 금지.
4. **제품을 보여준다**. 히어로 아래 스크린샷/목업으로 "이게 네가 받을 것"을 즉시 제시(Craft·Cake·Height 전부).
5. **키워드 강조**. 헤드라인 안 핵심 단어에만 액센트 컬러(Cake "all-in-one equity platform").
6. **사회적 증거를 CTA 근처에**. 숫자·로고·후기 뱃지.

## C. 스티키 CTA 원칙 (지금 우리 버그)
- **문제**: 히어로 버튼과 하단 스티키 버튼이 텍스트도 같고 동시에 보여서 중복·산만.
- **정석(scroll-reveal)**: 스티키는 **히어로 CTA가 뷰포트를 벗어난 뒤에만** 등장. 히어로 버튼이 보이는 동안엔 스티키 숨김.
- **구현**: IntersectionObserver로 히어로 버튼 관찰 → 화면 밖이면 스티키 fade-in(8px 슬라이드업). 히어로 재진입 시 fade-out.
- **차별화**: 히어로 버튼 = 맥락 안의 주 CTA(+보조문구). 스티키 = 지속 리마인더(버튼만, 살짝 그림자·백드롭).

## D. 우리 홈 적용안
1. 히어로: 볼드 헤드라인 유지 + 서브 1줄 + 히어로 CTA(맥락형).
2. **페이오프 미리보기(Toss 큰 숫자 문법)**: "이런 결과를 받아요" — 견적 결과 축소 목업 카드(시술 조합 + 예상 범위). '이게 네가 받을 것'을 즉시 보여줌.
3. 신뢰 수치 3카드 유지(사회적 증거).
4. 아이콘+베네핏 라인(왜 우리인지 3줄) — Toss 문법.
5. 액션 카드(후기·방문예약) + 프리셋 질문.
6. **스티키 CTA는 scroll-reveal**로 전환(C 원칙). 히어로 CTA와 안 겹침.
