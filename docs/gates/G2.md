## 판정 상태

| 항목 | 값 |
|---|---|
| `final` | **`not_decided`** — 계약 K-4 의 허용 집합 `{pass, channel_redesign, inconclusive}` 밖 |
| `google_verdict` | `not_measured` |
| `naver_verdict` | `not_measured` |
| 차단 원인 | D2 REQ-2 (검색량 측정 도구 자격증명 부재) → REQ-3·5·6·7 연쇄 차단 |

`final` 을 계약의 허용 집합 밖 값으로 둔 것은 의도적이다.
`validate_d2.py --check verdict` 는 이 값을 **위반으로 판정하고 exit 1** 한다 —
G2 가 미판정 상태라는 사실이 검사기에서 조용히 사라지지 않게 하기 위한 것이다.

`inconclusive` 로 적지 않은 이유: K-4 의 `inconclusive` 는 *"측정했으나 blocked 가
상한을 넘어 판정이 불가능한 상태"* 이며, 지금은 **측정 자체를 시작하지 못한 상태**다.
둘을 같은 값으로 적으면 "네이버 캡처를 시도했으나 차단당했다" 는 서사가 만들어진다.

## G2 가 미판정인 동안 막히는 것

계약 DAG 상 D2 는 **W1-SEO-FOUNDATION** 과 **W4-COMBO-LANDING** 을 block 한다.
G2 가 `pass` 가 아니므로 두 태스크의 착수 근거(SSG 중심 스택 · 조합 랜딩 대량 생성)는
아직 실측으로 뒷받침되지 않는다.

`validate_d2.py --check verdict` 가 exit 0 이 되는 것으로 판정을 확정한다.
