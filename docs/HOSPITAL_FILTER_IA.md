# 병원찾기 필터·뷰 IA 재정비 (유사서비스 리서치 기반)

## 문제 (유저 지적)
1. **위계 붕괴**: 시술 필터칩(울쎄라·써마지…)과 목록/지도 토글이 **똑같은 pill**이라 "필터"와 "뷰 전환"이 안 구분됨.
2. **분류 부적합**: 울쎄라·써마지 같은 **브랜드명** 분류는 4050이 모를 수 있음. 그들은 "처짐·주름·기미" 같은 **고민**으로 생각한다(우리 견적 플로우도 고민 진입).

## Mobbin 러닝
- [Beli](https://mobbin.com/screens/32d59cc3-9c2d-4a1c-ab29-a58bf8b23f4c): **List|Map = 연결된 세그먼트 컨트롤**(하나의 트랙, 활성=흰 카드). 필터는 그 아래 별도 드롭다운 pill 행. → 뷰 전환과 필터는 다른 컨트롤 모양이어야 한다.
- [Subway](https://mobbin.com/screens/bbd67285-d12a-4b22-b9c7-abe2beb2b48a): 결과 헤더 우측에 [View Map] 버튼 분리(필터와 다른 위치·모양).
- [Tabby](https://mobbin.com/screens/5617ab31-7cb2-4aa9-8eb8-707f8e098266): 상단 카테고리 칩(Fashion/Beauty&Health) = 니즈 분류, 브랜드명 아님.
- 결론: (a) 뷰 전환은 세그먼트 컨트롤로 시각 분리 (b) 필터는 니즈/고민 기반.

## 재정비안
### 1. 분류 = 고민 기반(우리 CONCERNS 재사용, 4050 실어휘)
브랜드명 → 고민 칩으로 교체. 우리 CONCERNS(탄력·처짐, 주름, 색소·기미, 볼륨, 모공·피부결, 이중턱·목주름)를 그대로 사용.
- `전체`(기본, 가격 렌즈 없음) + 고민 6종.
- 각 고민은 대표 시술로 매핑해 가격 렌즈(있을 때만)·라벨에 사용. 데이터 없으면 거리순 그대로(정직).

### 2. 위계 = 3층으로 분리
```
[검색바]                               ← 이름 검색
[고민 칩: 전체 탄력·처짐 주름 …]          ← 필터(무엇을)
────────────────────────────────
[내 주변 N곳]        [목록 | 지도]       ← 결과 헤더 + 세그먼트 뷰전환
[리스트 카드…]
```
- 고민 칩: 회색 pill(선택 시 그린 틴트) — 필터.
- 목록/지도: **세그먼트 컨트롤**(회색 트랙 1개, 활성 반쪽만 흰 카드+그린) — 필터칩과 완전히 다른 모양.
- 결과 개수 "내 주변 N곳"을 좌측에 둬서 헤더임을 명확히.

### 3. 정직성
- 고민 필터는 병원 리스트를 가짜로 좁히지 않는다(병원별 시술 데이터 없음). 거리순 유지 + 가격 렌즈만 반응. '전체'가 기본.
