# 모두닥 견적 퍼널 전수 캡처 + 암묵지 가설 (영상 2편, 2026-08-14)

영상: 견적 신청(140s) + 받은견적 탐색(62s). 프레임 단위 정독. 각 피처마다 **[가설]** = 왜 이렇게 만들었을지에 대한 암묵지 추론.

## 1. 홈 (랜딩)
- **최상단 고정 풀폭 CTA** "임플란트 무료견적 받기 >" — 카테고리 탭 바로 아래, 스크롤 전 노출.
  - [가설] 유입의 대부분이 검색광고→즉시 전환 목적. 탐색보다 **신청이 먼저**다. 고연령 유저는 스크롤 중 길을 잃으므로 첫 화면에서 끝내게 한다.
- **신뢰 수치 블록**: "인증된 리뷰 535,724개 / 회원 수 3,948,915명 / 의사 수 106,420명" — 홈에 2회 반복 노출.
  - [가설] 고관여·고가 시술은 "여기 써도 되나"가 1차 장벽. 큰 숫자의 반복이 신뢰 형성. 특히 4050+는 '남들도 많이 쓰는 것'을 안전 신호로 읽음.
- **정렬 투명성 고지**: "병원이 제출한 견적수가 많은 순으로 게시합니다. 같은 견적수라면 평점/리뷰 수가 높은 병원이 먼저."
  - [가설] '광고 순위 아니냐' 불신을 선제 차단. 정렬 기준 명시가 그 자체로 차별화 무기.
- **의사 Q&A 입력 박스**: "증상/치료, 궁금한 점이 있나요? 의사가 답변해 드려요!" + 입력창.
  - [가설] 견적까지 안 갈 유저도 질문으로 리드 전환. 입력창을 홈에 박아 행동 문턱을 최소화.
- **하단 탭에 '리뷰작성'이 1급 탭** (할인몰·홈·의료상담/가격·리뷰작성·마이페이지).
  - [가설] 리뷰 = 공급이자 콘텐츠이자 SEO. 수집을 소비와 동급으로 두는 구조적 의지. 포인트 보상과 연결.

## 2. 견적 신청 위저드
- **1화면 1질문 라디오**. 첫 질문 "귀하의 나이는?" 선택지가 **만 65세 이상 → 60~65세 → 50대…** 고연령부터.
  - [가설] 주 고객(임플란트=고연령)이 자기 선택지를 맨 위에서 바로 발견하게. 선택지 순서 = 타깃 선언.
- **지역: 권역 그룹 다중선택** (서남2권/동북1권 등 괄호 병기).
  - [가설] '우리 동네' 단위 신뢰 + 병원 매칭 반경을 유저가 직접 넓히게 해 발송 병원 수(=결과 만족)를 키움.
- **조건 요약 화면**: "최근 설정한 조건" 카드(연령대/부위·개수/선호 지역) + 수정하기 + "일부 질문이 변경되었습니다. 업데이트 후 제출해주세요."
  - [가설] 재신청 유저의 재입력 비용 제거(조건 저장). 제출 직전 요약으로 "내가 뭘 신청하는지" 확신을 준 뒤 연락처를 요구.
- **자유 메시지란**: "병원에 전달하고 싶은 메세지를 자유롭게 작성해주세요. (최대 500자)"
  - [가설] 유저의 사정(틀니 고민, 예산 등)을 병원에 전달 → 병원 응답 품질↑ → 전환↑. '내 말이 병원에 전달된다'는 감각 자체가 신뢰.
- **연락처 수집**: "견적 결과를 전달받을 이름과 연락처가 필요해요" + 성함·전화 + 3자 제공 동의 + [동의 후 신청완료].
  - [가설] 연락처는 **결과 수신 수단**으로 프레이밍(마케팅 수집으로 안 읽히게). 위저드 끝에 배치해 매몰비용으로 완주율 확보.

## 3. 결과 전달 (리텐션 채널)
- **이중 채널**: 웹푸시 + **카톡 알림톡**. "임플란트 견적 결과가 도착했어요. 뷰티앤디지털치과병원을 비롯한 **총 14곳**에서 맞춤 견적 결과를 발송했습니다. 👉 아래 버튼을 클릭하여 지금 바로 확인해보세요!" + [견적 확인하기].
  - [가설] 고연령의 생활 채널은 카톡. '14곳'이라는 풍성함 숫자가 재방문 동기. 견적을 '도착한 우편물'로 은유(맞춤 견적서 도착 + ₩ 봉투 아이콘).
- 개별 병원 프리미엄(AD) 알림톡 별도 발송 + "프리미엄 견적(AD)으로 안내드리는 첫 번째 병원의 메시지입니다" 고지.
  - [가설] 병원별 과금 상품(알림톡 1건 단위)이면서, AD 표기를 정직하게 달아 신뢰 유지.
- "견적 결과 수신에 동의하신 경우에만 발송되는 메시지입니다." 반복 고지.
  - [가설] 스팸으로 읽히는 순간 채널이 죽는다. '당신이 요청한 것'임을 매번 상기.

## 4. 받은 견적 리스트
- 상단 배너: "🔔 내 조건에 맞는 견적서가 도착했습니다. 병원에 **상담요청 또는 전화/채팅**을 진행해보세요!"
  - [가설] 리스트 도착 즉시 다음 행동을 지시. 상태 알림에는 반드시 다음 스텝을 붙인다.
- **3계층 섹션**: ① 프리미엄 견적(AD) "요청하신 지역에 우선 안내되는 견적입니다" ② 내 근처 견적 "선택하신 지역에 있는 병원 견적이에요" ③ 더 많은 견적 모아보기 "다양한 지역의 견적도 함께 비교해보세요".
  - [가설] 광고 인벤토리(①)를 만들되 '왜 먼저 보이는지' 설명. ③은 이탈 직전 유저에게 재고 소진용 롱테일.
- **카드마다 소셜프루프 배지**: "✓ 한 달간 모두닥을 통해 N명 방문완료" (30명/13명/11명/1명…1명까지도 표기).
  - [가설] '이 플랫폼으로 실제 방문한 사람이 있다' = 견적이 가짜가 아니라는 증명. 1명이라도 0명보다 강력. 월 단위로 최신성 부여.
- **가격 표기**: 정가 취소선(350,000원) → "모두닥 8월 최저가" 빨간 뱃지 + 대부분 **blur 처리** "**원~" + [₩ 가격보기]. 일부만 공개(180,000원~).
  - [가설] (a) 월 표기로 최신성·한정감. (b) blur는 클릭(=리드 이벤트) 유도 + 병원의 공개가격 부담 완화. (c) 일부 공개 카드가 'blur도 진짜 가격이 있다'는 앵커.
- 번호 랭킹 뱃지(1,2,3…) + 평점(리뷰수) + 동 단위 위치.
- 카드 버튼 2개 고정: [전화] (아웃라인) + [가격 상세보기 >] (필).
  - [가설] 전환 경로를 전화/웹 두 갈래로 항상 열어둠. 고연령은 전화 선호 — 전화를 숨기지 않는다.

## 5. 병원 상세 (견적 컨텍스트)
- 상단 마퀴 광고문구 배너("강남*역삼역 도보 5분 임플란트치과") + 방문완료 배지 + 병원명·평점·동·[병원정보>].
- **액션 4버튼 바**: 찜하기 / 예약하기 / 채팅하기 / 전화하기.
  - [가설] 결정을 못 한 유저(찜), 결정한 유저(예약), 부끄러운 유저(채팅), 급한 유저(전화) — 온도별 전환 경로를 전부 병렬 노출.
- **견적 리뷰 섹션이 병원정보보다 위**: 닉네임+날짜+평점+[방문완료] 뱃지+본문 2줄+더보기.
  - [가설] 견적 컨텍스트에선 '남들이 실제로 갔는가'가 시설정보보다 중요.
- **병원정보 아이콘 그리드**: 화/목 야간진료 · 간단 뼈이식 포함 · 정품 국산 임플란트 사용 · 자체기공소 보유.
  - [가설] 고연령 의사결정 요인(야간 가능? 정품? 추가비용 함정?)을 아이콘 4개로 압축.
- **가격견적 탭**: 옵션별 카드(오스템 BA·CA, 보철 지르코니아) — "임플란트 23만원/개, +뼈이식 11만~16만원/개(가격 범위?), **총 수술비 23만원**, 뼈이식 포함 시 34만~39만원" + [가격문의].
  - [가설] '견적'의 실체는 옵션×범위×**총액**. 추가비용(뼈이식)을 미리 범위로 공개해 "가서 바가지" 공포를 해소. 총액 볼드가 핵심.
- **프리셋 질문 채팅**: "병원측에 더 궁금한 사항이 있다면?" + 카톡형 UI + 버튼 3개: "구체적인 가격은 어떻게 되나요?" / "예약 가능한 날짜가 언제인가요?" / "전화로 상담 받아보고 싶어요."
  - [가설] 첫 마디를 못 꺼내는 유저(특히 고연령)의 작문 부담 제거. 버튼 1탭 = 리드 1건.
- **채널 락인 고지**: "⭐ 모두닥 견적가로 받으려면? 반드시 '모두닥'을 통해서 신청하셔야 견적가로 받으실 수 있습니다."
  - [가설] 정보만 얻고 직접 전화하는 누수 차단 + 병원에게는 모두닥 경유 측정 보장.
- 병원 이벤트 텍스트(기간 한정, 포인트), Before&After 갤러리(병원 제공), 0504 **안심번호** 통화.
  - [가설] 안심번호 = 유저 번호 보호 + 통화 추적(성과 측정). 전환 성과를 병원에 증명하는 인프라.
- 크로스셀: "다른 병원의 임플란트 견적도 있어요 (AD) — 고민 중이라면 이 병원도 둘러보세요!"
  - [가설] 상세 이탈 트래픽 재활용. 비교심리를 인정하고 리스트로 되돌린다.

## 6. 리뷰 (핵심 자산)
- 리뷰 구조: [✓ 견적완료][✓ 모두닥으로 방문] 배지 + "받은 진료: 임플란트" + 평점 + 방문완료 + 날짜 + **의사: 실명** + 본문 + **시술 스펙 표**(오스템 CA / 어금니 2개 / 앞니 1개) + **"✓ 모두닥에서 확인한 가격과 같았어요 — 실제 결제금액: 900,000원"**.
  - [가설-핵심] 고연령은 "가서도 그 가격이 맞는지, 가면 딴 걸 권하는지"를 가장 두려워한다. 그래서 리뷰의 1급 필드가 감상이 아니라 **가격 일치 여부 + 실결제액 + 정확한 시술 스펙**이다. 리뷰가 곧 가격 검증 데이터.
- 리뷰 필터에 **"견적 가격과 달랐어요 3"** — 불일치 리뷰도 카운트해 노출.
  - [가설] 나쁜 신호를 숨기지 않는 것이 전체 신뢰를 만든다. 불일치 3건의 존재가 일치 리뷰들을 진짜로 만든다.
- 리뷰 본문 패턴: 대기시간·과잉진료 없음·직원 친절 등 '병원 방문 공포' 해소 서사.

## 7. 우리(글로우메이트)와의 구조 차이
- 모두닥: 병원이 견적을 **제출**(B2B 공급) → 유저에게 발송. 우리: 공공데이터+룰베이스 자동견적(병원 공급 전무) — 파트너가 생기기 전까지 '병원 발송 견적'은 불가능.
- 따라서 이식 가능한 것: **홈 퍼널 구조(고정 CTA·신뢰 수치·투명성 고지), 위저드 문법, 알림/도착 프레이밍, 소셜프루프 문법, 리뷰 스키마(가격일치·실결제액·스펙), 프리셋 질문, 온도별 다중 CTA**.
- 이식 불가(현 단계): 병원 제출 가격, blur 가격보기(가격 데이터 자체가 없음), 안심번호, 알림톡(채널 미구축).
