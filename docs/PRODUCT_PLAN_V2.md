# 글로우메이트 제품 기획서 v2 — 차별화 4피처 + 검증 설계

## 0. 전략 프레임 (리서치 결론의 우리식 번역)
- 강남언니 누적 900만·MAU 29만 = **이 카테고리는 저빈도가 본질**. 1위도 못 푼 리텐션이 빈틈.
- 4050이 비어 있는 이유 3가지(레퍼런스 부재·비포애프터 UX 충돌·작은 폰트) 전부 우리 기존 원칙과 일치.
- 통과 문법 4개 → 우리 매핑: ①공급 부트스트랩을 AI로(SKU 엔진) ②고빈도 전환(시술 원장) ③양방향 매칭(역경매) ④코호트 프루프(가격 분포). **④→②→③→① 순으로 이미 일부 깔려 있음** — 우리는 제로에서 시작하지 않는다(아래 각 절의 '현재 자산' 참조).

## 1. 피처 ① 시술 SKU 정규화 엔진
**한 줄**: 병원들이 제각각 광고하는 "300샷 19만"·"600샷 33만"을 `시술군×브랜드×정량×부위×회차×총액`으로 정규화해 **단가 비교**를 최초로 가능하게 한다.

**현재 자산**: procedures 14종(카탈로그), hospital_procedure_prices 테이블(빈 상태), 어드민 검수 인프라.

**스키마(0012 후보)**
```sql
create table procedure_skus (
  id uuid pk, procedure_id text ref procedures,
  brand text,            -- 울쎄라/슈링크/리쥬란HB…
  qty int, qty_unit text, -- 300, 'shot' | 2, 'cc' | 1, 'session'
  area text,             -- 전안면/하안면/눈가…
  sessions int default 1,
  includes text[],       -- 마취크림, 재생관리…
  renewal_weeks int      -- 재시술 권장 주기(원장 연동 키!)
);
create table hospital_offers (
  id uuid pk, hospital_id ref, sku_id ref,
  total_price int, vat_included bool,
  source_type text check in ('official_site','public_event','user_receipt','partner_submit'),
  source_url text, collected_at, verified_at, status text default 'pending' -- 검수 큐
);
-- 뷰: price_per_unit = total_price / (qty*sessions)
```
**콜드스타트**: 강남·서초 1권역 × 시술 5종(울쎄라·슈링크·리쥬란·보톡스·필러)만. 넓이가 아니라 정규화 정확도가 해자(여신티켓 4,500개로도 못 이긴 이유).
**수집 우선순위**: (a) 파트너 제출 (b) **유저 영수증**(이미 수집 중 — 어드민 검수에서 SKU 태깅만 추가) (c) 병원 공식 홈페이지 공개 가격표(아래 법적 가이드 내에서) (d) 크롤링은 최후.

**법적 가이드(판례 기반)** — [야놀자 v 여기어때](https://www.lawtimes.co.kr/news/articleView.html?idxno=182087): 형사(망침입)는 무죄였지만 **민사에서 부정경쟁방지법 '성과도용' 인정**. [잡코리아 v 사람인](https://magazine.hankyung.com/business/article/202108256209b): DB권 침해로 **합의금 120억**. 교훈:
1. **경쟁 플랫폼(강남언니·바비톡·여신티켓) DB는 절대 수집 금지** — 그들의 '상당한 투자로 만든 성과' 그 자체라 성과도용 정면 해당.
2. 병원 **개별 공식 홈페이지의 공개 가격표**는 상대적으로 낮은 리스크: 가격은 '사실'이라 저작권 대상 아니고, 개별 사이트에서 사실만 추출하면 DB의 '상당 부분 복제'도 아님. 단 (a) robots.txt 준수 (b) 저부하(리퀘스트 간격) (c) **이미지·문구 복제 금지, 사실(숫자)만 추출** (d) source_url 보존 (e) 병원의 삭제 요청 즉시 반영 창구.
3. 심의필 광고 이미지 재게시 금지(저작권+의료광고법 이중 리스크).
4. 프로덕트 확정 전 의료광고·데이터 전문 법무 검토 1회(비용 항목으로 잡을 것).

## 2. 피처 ② 시술 원장(元帳) + 재시술 알림
**한 줄**: 시술 이력을 넣으면 "다음 재시술 시점 + 그때의 예상 견적"을 알려주는 개인 캘린더 — 저빈도를 고빈도로 바꾸는 유일한 레버(Allē/ASPIRE로 행동 검증됨, 브랜드 중립이 빈틈).

**현재 자산**: localStorage 견적 스냅샷·방문 내역(무가입 원칙), 후기의 procedure_spec/paid_amount, SKU의 renewal_weeks.
**MVP(무가입 유지)**
- `내 활동`에 "시술 기록" 추가: 시술·날짜·(선택)금액. **입력 자동 제안**: 후기 작성 완료 시·방문신청 확정 시 "기록에 추가할까요?" 1탭.
- 기록되면: 내 활동·홈에 "보톡스 D-98 — 효과 감소 구간, 지난번 32만원" 배너. 견적으로 원탭 연결(원장→견적 루프).
- 수동입력은 3주 만에 죽는다(Fort 교훈) → 자동 제안 경로가 본체. SMS 파싱은 앱 없인 불가라 스코프 밖.
**리텐션 채널 한계와 순서**: 웹은 푸시가 약함 → (1) 방문 시 배너(MVP) (2) 웹푸시 옵트인 (3) 카카오 알림톡(모두닥 채널 — 채널 개설+연락처 동의 필요, 별도 결정). MVP는 (1)만.

## 3. 피처 ③ 역경매형 견적 요청 (Pluto 패턴)
**한 줄**: 고민·예산·다운타임만 입력 → 구조화 견적요청서 → 조건 맞는 병원에만 발송 → **양쪽 관심 확인 후에만 연락처 공개**. 4050의 전화 공포 제거.

**현재 자산**: visit_requests(파트너 직전달/컨시어지 이원화, §27 무수수료 구조) — 역경매는 이것의 확장이다.
**스키마(0013 후보)**: quote_requests(concern들, budget_max, downtime_days, region, 이력 요약, status: open→quoted→connected→closed) + quote_replies(hospital_id, offer_sku, total_price, note, status).
**플로우**: 유저 요청(연락처는 받되 병원에 비공개) → 파트너 병원에 전달(비파트너는 컨시어지가 전화 수집 — 초기엔 이게 대부분) → 24h 내 회신 목표 → 유저가 병원 선택 시에만 연락처 오픈.
**§27 설계(치명 지점)**: 성사 수수료 금지. 수익은 (a) 병원 정액 노출료(기존 ad_placements 확장) (b) **유저 멤버십**(무제한 요청·원장 관리·상담 지원 — 4050 지불의사↑, 규제 최안전). 병원 회신 텍스트는 §56 필터(bannedPhrases) 통과 후 노출 — 검수봇 인프라는 이미 있음.
**콜드스타트**: 파트너 0인 지금은 **컨시어지 역경매**(우리가 3곳 전화로 견적 수집해 24h 내 회신)로 시작 — 수동이지만 ①의 수집 경로(source_type='concierge')와 겹쳐 일석이조.

## 4. 피처 ④ 코호트 가격 분포
**한 줄**: 후기가 아니라 **"48세·처짐·다운타임불가 코호트의 실결제 분포(중앙값·사분위)"**가 신뢰 자산. 친구 기반 소셜은 이 영역에서 역효과(익명 코호트가 정답).

**현재 자산**: 이미 수집 중(paid_amount·price_match·procedure_spec·age_band) + 3건 임계 노출 규칙(docs/PRICE_DATA_STRATEGY.md) — **이 피처는 30% 완성 상태**.
**추가할 것**: (a) 코호트 축 = 시술×연령대(×고민은 후기에 고민 필드 추가 후) (b) 분포 컴포넌트(중앙값+P25~P75 밴드, n 표기) (c) 노출 위치: 견적 결과·레슨·병원찾기 필터별 헤더 (d) **n<5 코호트 절대 비노출**(기존 3건 규칙을 코호트 단위 5건으로 상향).

## 5. 검증 설계 (개발과 병렬)
**리플레이 인터뷰 15명** = 반복시술자5 · 1회이탈자5 · 미실행관심자5 (당근 동네생활·맘카페, 강남언니 유저풀 배제, 사례비 5만원)
- 60분: 트리거15' → **폰 켜고 화면 재현**20' → 중단·좌절15' → 대안행동10'
- 판정: A(가격) B(전화공포) C(선택불능) 신호 사전 정의, **9/15 동일 신호면 채택**, 어정쩡 금지
- 가설→코어 매핑: A→① / B→③ / C→②+컨시어지
**병렬 정량**: 랜딩 3종 × 메타 광고 각 20만원 — A"같은 리쥬란, 병원마다 40만원 차이" / B"전화 안 걸고 견적" / C"48세 피부엔 뭐가 맞을까". CTR·이메일 전환으로 인터뷰 교차검증.
→ USER_INTERVIEW_KIT.md를 이 설계로 개정.

## 6. 로드맵 제안 (의존성 순)
| 주차 | 배포물 | 왜 이 순서 |
|---|---|---|
| W1 | **④ 분포 노출**(수집은 이미 됨) + ② 원장 MVP(기록+D-day 배너) | 신규 수집 없이 기존 데이터로 출시 가능, 인터뷰 전 리텐션 가설 계측 시작 |
| W1~2 | 인터뷰 15명 + 랜딩 3종 (병렬) | 코어 결정 데이터 |
| W2 | ③ 컨시어지 역경매 베타(수동, 강남 5시술) | visit_requests 확장 최소 개발, ①의 수집 경로 겸함 |
| W3~ | ① SKU 엔진(0012)+어드민 SKU 태깅 — 인터뷰가 A로 판정 시 승격 | 가장 무거운 개발이라 검증 후 |
| 상시 | 법무 검토 1회(크롤링·§27·심의) | ①·③ 확정 전 필수 게이트 |

## 7. 하지 않는 것 (명시)
- 경쟁 플랫폼 크롤링(성과도용), 친구 기반 소셜, 셀피 "진단"(§27·진단 표방 리스크 — '관심 시술 탐색' 프레이밍 별도 기획 전까지 보류), 성사 수수료, 후기 5번째 기능화(분포가 우선).
