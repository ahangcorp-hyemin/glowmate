## 1. 가설 트리 (검증 순서대로)
```
H0 공급: 병원이 위임 문의에 가격을 회신한다          ← 최대 리스크, 가장 먼저
 └ H0-a: 전화 회신율 ≥40%   H0-b: 카톡채널이 전화보다 낫다(A/B)
H1 수요: 4050이 견적 요청을 제출한다 (주 10건)
 └ 시딩 필요: 인터뷰 15명 초대 + 랜딩 B 광고 병행
H2 가치: 받은 견적이 결정에 도움이 된다
 └ H2-a 열람한다  H2-b "도움됐다" 말한다  H2-c 방문으로 이어진다(connect)
H3 병목 규명(인터뷰 연동): 4050이 전화 안 하는 이유는?
 └ ①공포(사회적 불안) ②학습된 무력감("어차피 내원 상담하래") ③호구 공포(정보 비대칭)
   → 각각 다른 제품: ①역경매 ②SKU DB 공개 ③코호트 분포. 리플레이 인터뷰 B신호를 3갈래로 코딩
H4 자산: 콜 부산물이 해자가 된다
 └ H4-a SKU 행 축적  H4-b 견적-실결제 괴리율 데이터(병원별 정확도)
```

## 2. 핵심지표 (계층별)
### 게이트 지표 (이거 없으면 다음 단계 없음)
| 지표 | 목표 | 측정 | 시점 |
|---|---|---|---|
| **파일럿 콜 회신율** | ≥40% (10통: 전화5·카톡5) | 스프레드시트 실측 | 개발과 병렬, 첫 3일 |
| 법무 자문 완료 | 서면 2건(알선 해당성·노출료 분리) | — | 베타 공개 전 하드 게이트 |

### 퍼널 지표 (계측 이벤트)
```
quote_request_view(진입점별) → quote_request_submit → notify_channel(sms|app)
→ quote_result_open(명시 POST=viewed_at) → quote_connect_click → visit_request 생성(quote_request_id 배선)
```
| 단계 | 참고 기준(4주, n<30이라 판정용 아님) |
|---|---|
| 제출 | 주 10건(캡) — 미달 시 수요 시딩 강화, 초과 시 대기열 |
| SLA 준수(영업일 24h) | 90% |
| 3곳 회신 달성 | 60% |
| 열람률 | 80% (문자 선택률과 교차 해석) |
| connect | 25% — **참고 지표**(정식 임계는 주 30건+부터) |

### 자산 지표 (공동 주산물 — CEO 리뷰 승격)
| 지표 | 의미 |
|---|---|
| SKU 검증 행 누적(source=concierge) | 콜 1건의 1:N 재사용 가치 |
| 수집가 재사용 노출 수 | concierge 출처 가격이 다른 유저 화면에 보인 횟수 |
| **견적-실결제 괴리율(병원별)** | connected 사후 1문항으로 축적 — 복제 불가 해자 |
| 병원 관계: 회신율·선호 채널·재접촉 성공률 | L3/L4 전환 판단 근거 |

## 3. 검증 루프 (주간 사이클)
```
월: 지난주 요청 리뷰 — 판정 시트 갱신(아래) / 되물음 로그 → 폼 필드 후보
화-금: 요청 처리(콜패킷) + 파일럿/실측 기록
금: 주간 회고 15분 — ①회신율 추이 ②괴리 클레임 유무 ③출력 카드 변형 결과 ④사다리 전환 트리거 점검
```
**4주 판정(정성 게이트 — 정량 아님을 명시)**
- 통과: 견적 수령 유저 인터뷰(전원 시도)에서 "결정에 도움" 신호 다수 + 회신율 실측 ≥40% + 괴리 클레임 0
- 피벗 신호: ①회신율 <40% 지속 → L3 텍스트-퍼스트 or 파트너 선영입 재검토 ②제출 미달+시딩 무반응 → H1 기각, ④분포·②원장에 집중 ③열람 <50% → 문자 기본 2택 강화 ④괴리 클레임 ≥2건 → range 고지 강화+해당 병원 풀 제외
- 확장 신호: 주 10건 캡 2주 연속 소진 + 도움 신호 → 캡 20건 + L1 콜패킷 고도화

**사다리 전환 트리거(재확인)**: L1 즉시 / L2 주15건 / L3 파일럿 A/B 승자면 즉시 병행 / L4 동일 병원 3회째 접촉.
