## §0 착수 게이트 — 현재 **보류(blocked)**

### 0-1. 왜 닫혔는가

| 항목 | 값 |
|---|---|
| 상태 | **보류(blocked)** — 어댑터 코드·픽스처 작성, 대상 호스트로의 요청, 스모크 실행 전부 금지 |
| 판정일(UTC) | 2026-08-03 |
| 소스 verdict | `naver_place` = **`forbidden`** · rule `R-ROBOTS-DISALLOW` |
| robots 근거 | `map.naver.com/robots.txt` 가 `User-agent: *` 에 `Disallow: /`. `m.place.naver.com`·`pcmap.place.naver.com` 은 robots.txt 자체가 HTTP 429 로 취득 실패(1시간 간격 2회 독립 시행) — **확인 불가를 허용으로 바꾸지 않는다** |
| ToS 근거 | 네이버 이용약관(서술형, 조 번호 없음)이 자동수집을 금지. verdict 는 robots 근거로 이미 확정 |
| 공식 API 경로 | 네이버 API Hub 지역검색 — 인증은 성공하나 **쿼리당 5건 상한 · `start` 파라미터 무시 · `total` 항상 5**(실측). 강남3구 전수 나열이 불가능해 REQ-2 `discover()` 를 대체하지 못한다 |
| 게이트 파급 | D3 K-6("어댑터 대상 allowed/conditional ≥ 2건") 미달 → `docs/gates/G3.md` = `blocked_escalated`, 어댑터 대상은 `official_website` 1건 |
| 판정 근거 정본 | `docs/discovery/D3/verdicts.csv` (`naver_place` 행) · `docs/discovery/D3/report.md` §1·§2·§4 · `docs/discovery/D3/sources/naver_place.md` · `docs/gates/G3.md` |
| 근거 문서 현재 위치 | D3 머지 전에는 브랜치 `feat/d3-source-dd` (워크트리 `.claude/worktrees/agent-ad90790884f8e3098/docs/discovery/D3/`). 머지 후 `docs/discovery/D3/` 가 정본 |

> **보류 ≠ 폐기.** 커버리지 기여가 가장 큰 소스(제외 시 업체 커버리지 손실 60~85%, D3 §4.2)이므로
> 계약을 살려 둔다. 이 문서를 지우면 제휴가 성사됐을 때 REQ·FORBID 를 처음부터 다시 만들어야 한다.

### 0-2. 자동 해금 조건 (사람이 기억할 필요 없는 형태)

```
게이트 열림 ⇔ verdict(naver_place) ∈ {allowed, conditional}
              ∧ (verdict == conditional → docs/discovery/D3/crawl_policy.yaml 에 naver_place 블록 존재)

verdict 는 docs/discovery/D3/verdicts.csv 의 source == "naver_place" 행에서만 읽는다.
평가 주체: CI job `source-verdict-guard` (FORBID-1 detect). 사람의 승인 플래그가 아니다.
```

조건식이 참이 되는 순간 이 계약은 **별도 승인·개정 없이 착수 가능**해진다(§0-4 재확인 항목만 수행).
조건식이 거짓인 동안에는 리드 구두 승인이 있어도 착수 불가다 — 판정 정본은 `verdicts.csv` 한 곳뿐이다.

### 0-3. 조건식을 참으로 만드는 경로 (해소 경로)

| # | 경로 | 필요한 산출물 | 비고 |
|---|---|---|---|
| A | **운영사(네이버)와 데이터 제휴·사전 승낙 취득** | 승낙 범위·기간·재공개 조건이 적힌 문서를 `docs/discovery/D3/snapshots/consent/naver_place.*` 로 보존 → D3 재실행으로 verdict 를 `conditional` 로 갱신 | 승낙 범위 밖 경로는 여전히 `forbidden` 으로 남긴다 |
| B | **공식 API 정책 변경** | 지역검색(또는 후속 API)이 (i) 페이지네이션으로 강남3구 전수 나열 허용 **그리고** (ii) 결과의 로컬 저장 허용 을 모두 충족함을 실측 리포트로 증빙 → D3 재실행 | (i)·(ii) 중 하나만 충족되면 여전히 착수 불가. (iii) 가격·프로그램 필드 부재는 REQ-4 재현율 재산정 사유 |
| C | **robots 정책 변경** | `map.naver.com`·`m.place`·`pcmap` robots 스냅샷 재취득에서 대상 경로가 `Allow` 로 확인 → D3 재실행 | robots.txt 가 다시 429 면 `R-ROBOTS-UNKNOWN` — 해금 아님 |

세 경로 모두 **재판정은 D3 재실행으로만** 이루어진다. 이 계약 안에서, 또는 이 계약의 PR 에서
`verdicts.csv` 를 고쳐 스스로 게이트를 여는 것은 FORBID-6 위반이다.

### 0-4. 해금 시 재확인 항목 (착수 전 1회)

1. **REQ-2 달성 가능성** — 해금 근거가 경로 B(공식 API)라면 쿼리당 5건 상한이 해소됐는지 확인한다. 상한이 남아 있으면 `discover()` recall ≥ 0.95 는 원리적으로 달성 불가이므로 **착수 전에 REQ-2 를 개정**한다(임계를 낮추는 것이 아니라 발견 방식을 다시 정의한다).
2. **FORBID-1 (b) 예외 경로** — 제휴로 발급된 공식 키의 주입 경로가 C1 시크릿 관리에 등록됐는지.
3. **crawl_policy 조건 전사** — verdict 가 `conditional` 이면 요청률·경로 화이트리스트·재공개 제한이 C1 allowlist 에 반영됐는지(반영은 C1 소유, 미반영이면 블로커 보고).
4. **G3 재판정** — `docs/gates/G3.md` 가 `blocked_escalated` 에서 갱신됐는지.

## §9 하류 영향 — 리드 상신 (이 계약에서 해결하지 않는다)

`docs/tasks/**` 를 `depends_on` 기준으로 조회한 결과, C2 를 선행으로 갖는 살아 있는 태스크는 **C5-ENTITY-RESOLUTION 1건**이다

C4·C6·C7 은 C2 에 직접 의존선이 없다(C6 ← C5, C7 ← C4·C6 이므로 **간접** 영향은 받는다).

|---|---|---|---|
| **C5-ENTITY-RESOLUTION** | 직접 | C5 REQ-8 이 "C2·C3 가 실제 수집한 source_record 500건에서 **서로 다른 소스 2개 이상이 연결된 venue ≥ 40개**"를 요구한다(`C5.md:126-131`). 어댑터 대상이 `official_website` 1건뿐이면 소스가 1개라 이 REQ 는 **원리적으로 충족 불가**이고, C5 의 `why`("소스 교차 검증")도 성립하지 않는다 | (i) C5 도 연쇄 보류, (ii) `official_website` 어댑터 신설 태스크로 `depends_on` 교체 + REQ-8 을 단일 소스 기준(도메인 간 중복·체인점 지점 분리)으로 재정의, 둘 중 택일 |
