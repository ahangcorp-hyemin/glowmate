# W6 — 리드 액션 & 계측

> 개정 2판 (감사 `docs/audit/W1-O3-audit.md` W6 절 반영)
> 주요 변경: 분모(detail_view)·식별자·수집 엔드포인트·봇 판정을 **W9 로 이관하고 명시적 의존** ·
> `qualified_lead` 를 surface='detail' 로 명문화 · 유실 관측을 **서버측 하트비트**로 교체 ·
> lead_event 마이그레이션 소유권을 F2 로 반환 · medical 조건부 FORBID 신설

# ─── 요구사항 ───────────────────────────
requirements:
  - id: REQ-1
    statement: >
      4종 액션(call, kakao, map, booking) 클릭 시 W9 수집 클라이언트를 통해 lead_action.v1 이벤트가

      없는 페이로드는 수집 API 가 422 로 거부한다.
    acceptance: >
      계약 테스트 `pnpm test:lead-contract` — 4종 정상 페이로드 202, 필수 필드 결손 5케이스 전부 422.

  - id: REQ-2
    statement: >
      qualified_lead_daily 뷰는 surface='detail' AND is_bot=false AND event_version 필터를 포함하며,
      리스트·조합 랜딩 표면에서 발생한 lead_action 은 집계 결과에 0건으로 반영된다.
    acceptance: >
      골든 쿼리 테스트 `pnpm test:lead-views` — 픽스처(detail 30건, list 10건, 봇 5건) 입력 시
      qualified_lead 합계 30.

  - id: REQ-3
    statement: >
      lead_conversion 뷰는 (qualified_lead 수 ÷ W9 detail_view 수)를 산출하되, 코호트 축은 분모·분자
      양쪽에 존재하는 서버 산출 속성 price_block_present 로 분리한다 (뷰포트 관측값 price_block_seen 은
      코호트 축으로 사용하지 않는다).
    acceptance: >
      골든 쿼리 테스트 — 픽스처(detail_view 100건 중 present 60 / absent 40, lead 15건 중 present 12)
      입력 시 present 0.20, absent 0.075 반환. price_block_seen 을 코호트 축으로 쓰면 absent 분모가
      0 이 되어 테스트가 실패한다.

  - id: REQ-4
    statement: >
      동일 (visitor_id, venue_id, action_type) 조합이 30초 이내 재발생하면 집계에서 1건으로 계산되고,
      30초를 초과한 재발생은 별도 건으로 계산된다.
    acceptance: >
      골든 쿼리 테스트 — (a) 5초 간격 5회 입력 시 qualified_lead=1 및 dedup_dropped=4,
      (b) 31초 간격 5회 입력 시 qualified_lead=5.

  - id: REQ-5
    statement: >
      리드 링크 클릭 시 이벤트는 페이지 이탈 전에 keepalive 로 전송되며, 100회 반복 e2e 에서
      서버 수신 건수가 99건 이상이다.
    acceptance: >
      Playwright e2e `pnpm test:e2e:lead-beacon` — 수집 엔드포인트 수신 카운트 ≥ 99/100.

  - id: REQ-6
    statement: >
      price_block_seen 은 가격 비교 블록이 뷰포트에 50% 이상 연속 1초 이상 노출된 경우에만 true 로
      기록된다.
    acceptance: >
      컴포넌트 테스트 — IntersectionObserver mock 4케이스(미노출 / 30% 2초 / 50% 0.5초 / 50% 1.2초)
      결과가 false, false, false, true.

  - id: REQ-7
    statement: >
      스테이징에서 합성 리드 클릭 프로브가 15분 주기로 1건을 발생시키고, 서버측 지표
      lead_ingest_expected_vs_received 가 최근 60분 창에서 수신/기대 비율을 반환한다.
    acceptance: >
      `pnpm test:e2e:lead-heartbeat` — 프로브 4회 실행 후 비율 ≥ 0.95, 수집 차단 주입 시 비율 0 으로
      관측되어 실패(값이 항상 1 로 고정되면 실패).

# ─── 조건부 금지사항 ────────────────────
forbid:
  - id: FORBID-1
    when:         리드 액션 클릭 시 수집 API 요청이 실패(4xx/5xx/차단)하거나 sendBeacon 이 false 를 반환한 경우
    must_not:     tel:/카카오/지도/예약 링크의 이동을 차단·지연하거나 재시도를 위해 대기
    because:      계측 실패가 전화 연결 실패로 번지면 측정하려던 리드 자체를 파괴하고, 사용자는 "전화 버튼이 안 되는 사이트"로 인지해 재방문하지 않는다
    detect:       e2e 테스트 — 수집 엔드포인트를 500/차단으로 mock 한 상태에서 클릭 후 navigation 이 100ms 이내 발생함을 assert
    on_violation: block_merge

  - id: FORBID-2
    when:         lead_action 스키마의 기존 필드명·타입·enum 의미를 변경하는 경우
    must_not:     event_version 증가 없이 동일 파생 뷰에 계속 적재하거나, 수신 이벤트의 버전 분포를 관측하지 않는 상태로 배포
    because:      같은 이름 다른 의미의 이벤트가 섞이면 NSM 추세와 H4 코호트 비교가 조용히 틀리고, 구버전 캐시 클라이언트가 남아 있는 동안 그 오염 사실조차 관측되지 않는다
    detect:       CI 잡 event-schema-guard(W9 규약) — 스키마 diff 대비 version bump 강제 + qualified_lead_daily 의 event_version 필터 존재 검사 + lead_events_by_version 지표 노출 테스트
    on_violation: block_merge

  - id: FORBID-3
    when:         클라이언트 페이로드가 is_bot · visitor_id · surface 값을 명시해 수신된 경우
    must_not:     그 값을 그대로 집계 입력으로 사용 (surface 는 서버가 라우트로부터 확정, is_bot·visitor_id 는 W9 산출값으로 덮어쓴다)
    because:      클라이언트가 표면과 봇 여부를 신고할 수 있으면 리스트 표면 클릭을 detail 로 위장하거나 봇 트래픽을 정상으로 위장해 NSM 을 원하는 값으로 만들 수 있고, 조작된 리드 수치 위에서 과금 모델이 설계된다
    detect:       통합테스트 — 위조 페이로드 3종 입력 시 저장된 surface·is_bot·visitor_id 가 서버 산출값과 일치함을 assert
    on_violation: block_merge

  - id: FORBID-4
    when:         qualified_lead 집계 정의(표면 필터 · 30초 중복 창 · is_bot 제외 조건)를 변경하거나 상세 이외 표면에 리드 CTA 를 추가하는 경우
    must_not:     동일한 뷰 이름·지표 ID 를 유지한 채 정의만 바꿔 과거 구간과 연속된 하나의 시계열로 표시
    because:      NSM 정의가 조용히 넓어지면 리드가 늘어난 것처럼 보이지만 실제로는 다른 지표를 보고 있는 것이며, 리드 단가가 증명됐다는 잘못된 결론으로 수익화 단계에 진입한다
    detect:       뷰 스냅샷 테스트 + CI — qualified_lead_daily.sql 또는 surface enum diff 가 포함된 PR 은 라벨 `metric-definition-change` 와 작성자 외 승인 없이는 머지 불가, 정의 버전 컬럼 bump 검사
    on_violation: block_merge

  - id: FORBID-5
    when:         lead_action 이벤트 속성 또는 버튼 컴포넌트 props 를 정의·확장하는 경우
    must_not:     전화번호 · 예약 링크 쿼리스트링 원문 · 사용자 입력 텍스트를 이벤트 속성으로 전송
    because:      리드 버튼은 업체 전화번호를 다루는 유일한 지점이라 그대로 전송하면 이벤트 로그가 연락처 데이터베이스가 되고, 동의 절차가 없는 서비스에서 그 적재는 개인정보보호법 위반이며 로그 백업까지 오염된다
    detect:       CI pii-guard — lead_action 스키마 필드명 금지목록 대조 + 저장 페이로드 샘플 100건의 전화번호 정규식 매치 0건
    on_violation: block_merge

  - id: FORBID-6
    when:         업체의 category_axis 가 medical_wellness 인 경우
    must_not:     리드 버튼 라벨·aria-label·이벤트 속성에 D4 금지표현 사전의 시술명·효능 문구를 포함
    because:      "○○주사 예약하기" 형태의 CTA 는 의료광고법상 비급여 시술 유인 표시에 해당하고, 같은 문자열이 이벤트 로그에 축적되면 위반 범위가 화면을 넘어 데이터까지 확산된다
    detect:       컴포넌트 테스트 + CI 린트 — medical_wellness 픽스처 5건의 버튼 라벨·이벤트 속성을 D4 사전과 대조, 히트 1건 이상이면 실패
    on_violation: block_merge
