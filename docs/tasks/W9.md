# W9 — 관측 이벤트 기반 (전환 분모 · 필터 · 코호트 · 리텐션)

> 신설 (감사 `docs/audit/W1-O3-audit.md` 체계적 결함 #5 — "계측이 가설을 감당하지 못한다").
> **출시 후 검증 가설 4개(H4·H5·H6·H7)가 전부 판정 불가 상태였다.** H4는 전환율의 분모(상세 조회수)가 없고,
> H5는 필터 사용 이벤트가 없고, H6은 리포트 보유 코호트를 나눌 속성이 없고, H7은 재방문을 식별할 지속 식별자가 없다.
> 본 태스크가 그 기반(식별자 · 수집기 · 분모/코호트 이벤트 · 리텐션 뷰)을 단독 소유한다. W6 는 이 위에 리드 액션만 얹는다.

# ─── 요구사항 ───────────────────────────
requirements:

    statement: >
      visitor_id 는 서버가 발급하는 1st-party 쿠키 값이며 만료 400일, 값은 랜덤 128bit 를
      환경변수 솔트와 결합해 해시한 문자열이고, 원시 IP·UA 전체 문자열은 저장되지 않는다.
    acceptance: >

      (c) 저장 레코드에 IP·UA 원문 컬럼 값이 존재하면 실패.

  - id: REQ-2
    statement: >
      session_id 는 마지막 이벤트로부터 30분 무활동 시 새로 발급되며, 새로고침·같은 탭 이동에서는
      유지된다.
    acceptance: >
      `pnpm test:identity` — 3케이스(새로고침 후 동일 / 29분 후 동일 / 31분 후 상이) 전부 통과.

  - id: REQ-3
    statement: >
      업체 상세 라우트 요청 1회당 미들웨어가 detail_view 이벤트 1건을 서버측에서 발생시키며, 속성으로

      7개를 모두 포함한다. has_editor_report 는 F2 editor_report 테이블 조회로 산출한다.
    acceptance: >
      `pnpm test:e2e:detail-view` — 상세 라우트 20회 요청 시 수신 이벤트 20건, 7개 속성 결손 0건,
      has_editor_report 값이 픽스처 기대값과 20/20 일치.

  - id: REQ-4
    statement: >
      니즈 태그 쿼리 파라미터가 포함된 리스트 라우트 요청 1회당 filter_applied 이벤트 1건이
      미들웨어에서 발생하며 속성으로 (tag_ids[], result_count, session_id) 를 포함한다.
    acceptance: >
      `pnpm test:e2e:filter-event` — 태그 쿼리 요청 3회 시 이벤트 3건, tag_ids 가 URL 쿼리와 3/3 일치,
      태그 없는 요청 3회에서는 이벤트 0건.

  - id: REQ-5
    statement: >
      is_bot 은 서버측 결정론적 규칙 목록(UA 패턴 파일 + headless 표식 + visitor 당 분당 이벤트 60건 초과)
      으로만 산출되고, 클라이언트 페이로드의 동일 키는 무시된다.
    acceptance: >
      `pnpm test:bot-classify` — (a) 봇 UA 픽스처 20건이 is_bot=true, (b) 클라이언트가 is_bot=false 를
      명시한 봇 UA 요청도 is_bot=true, (c) 정상 UA 픽스처 20건이 is_bot=false (전량 봇 판정 시 실패).

  - id: REQ-6

      수집 엔드포인트는 Origin 헤더가 SITE_ORIGIN 과 불일치하면 403 을, 동일 visitor_id 기준 분당

# ─── 조건부 금지사항 ────────────────────
forbid:
  - id: FORBID-1
    when:         visitor_id · session_id 를 생성하거나 이벤트 속성을 확장하는 경우
    must_not:     원시 IP · UA 전체 문자열 · 이메일 · 검색어 원문 · 정밀 좌표(소수점 4자리 초과)를 값 또는 해시 입력으로 저장, 또는 해시 솔트를 소스코드에 하드코딩
    because:      로그인·동의 절차가 없는 서비스에서 식별정보가 축적되면 개인정보보호법상 수집 근거 없는 보관이 되고, 솔트가 코드에 있으면 유출 시 해시를 되돌릴 수 있어 로그 백업 전체가 개인정보 파일이 된다
    detect:       CI pii-guard — 이벤트 스키마 필드명 금지목록 대조 + 저장 페이로드 100건의 전화/이메일/IP 정규식 매치 0건 + 솔트가 환경변수에서만 로드되는지 단위테스트
    on_violation: block_merge

  - id: FORBID-2
    when:         클라이언트 페이로드에 서버 산출 필드(is_bot, visitor_id, occurred_at)가 포함되어 수신된 경우
    must_not:     그 값을 저장하거나 집계 입력으로 사용
    because:      봇이 자기가 봇인지 신고하는 구조가 되면 봇 필터·NSM·H4 코호트가 동시에 무의미해지고, 조작된 리드 수치 위에서 수익화 판단이 내려진다
    detect:       통합테스트 — 위조 페이로드 3종(is_bot=false 인 봇 UA, 타인 visitor_id, 미래 occurred_at) 입력 시 저장값이 서버 산출값으로 덮어써지는지 assert
    on_violation: block_merge

  - id: FORBID-3
    when:         packages/events/schema 의 기존 이벤트 필드명·타입·enum 의미를 변경하는 경우
    must_not:     event_version 증가 없이 동일 파생 뷰에 계속 적재하거나, 파생 뷰에서 event_version 필터를 생략
    because:      같은 이름 다른 의미의 이벤트가 섞이면 H4·H5·H7 의 시계열이 조용히 어긋나고, 원본에 구분자가 없어 사후 분리가 영구히 불가능하다
    detect:       CI 잡 event-schema-guard — 스키마 파일 diff 대비 version bump 강제 + 파생 뷰 3종의 event_version WHERE 절 존재 검사 + 수신 버전 분포 지표(events_by_version) 노출 테스트
    on_violation: block_merge

  - id: FORBID-4
    when:         봇 판정기가 이벤트를 is_bot=true 로 분류한 경우
    must_not:     수집 단계에서 드롭하거나 raw 테이블에서 삭제
    because:      봇 규칙은 운영 중 반드시 수정되는데 원본이 없으면 과거 구간 재집계가 불가능해 지표 정정이 막히고, 규칙 오탐 시 진짜 방문자를 소리 없이 잃은 사실조차 확인할 수 없다
    detect:       통합테스트 — 봇 UA 픽스처 20건이 raw 테이블에 20행 존재하고 파생 뷰 3종에서만 제외됨을 assert
    on_violation: block_merge

  - id: FORBID-5
    when:         수집 엔드포인트가 5xx·타임아웃·네트워크 차단 상태인 경우
    must_not:     페이지 렌더를 지연시키거나 링크 이동·필터 적용을 차단하며 재시도 대기
    because:      계측이 실패할 때 제품이 함께 멈추면 측정하려던 행동 자체가 사라지고, 사용자는 "느리고 반응 없는 사이트"로 인지해 H7 재방문까지 동시에 잃는다
    detect:       e2e 테스트 — ingest 를 500/차단으로 mock 한 상태에서 상세 페이지 TTFB 증가 100ms 미만, 필터 적용 후 결과 렌더 100ms 이내 assert
    on_violation: block_merge

  - id: FORBID-6
    when:         visitor_id 가 없는(쿠키 차단·최초 진입 실패) 세션을 리텐션·코호트 지표에서 처리하는 경우
    must_not:     session_id 를 visitor_id 대체값으로 사용해 분모·분자에 포함
    because:      쿠키 차단 사용자가 매 방문 신규 방문자로 계산되면 4주 재방문율이 구조적으로 과소 추정되어, H7 이 실제로는 통과했는데 기각되거나 그 반대의 판정이 내려진다
    detect:       단위테스트 — visitor_id NULL 픽스처 15건이 retention_week4 분모에서 제외되고 unidentified_sessions 카운터에 15로 집계됨을 assert
    on_violation: block_merge
