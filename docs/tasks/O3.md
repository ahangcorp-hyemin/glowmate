# O3 — 배포·모니터링·알림

> 개정 2판 (감사 `docs/audit/W1-O3-audit.md` O3 절 반영)
> 주요 변경: **"존재하지 않는 메트릭을 가리키는 룰"이 CI 를 통과하던 경로 차단**(룰 등록 조건 = 메트릭 실존 + 합성 주입 채널 도달) ·
> **하트비트/데드맨 스위치 신설**(무음 = 정상으로 읽히는 경로 차단) · **H3 용 외부 프로브 룰 3종 추가** ·
> 무음화 조건을 윈도우 확대·셀렉터 축소·비활성화까지 확대 · 드리프트 탐지를 자기 채널 밖(GitHub Actions 실패 알림)으로 이중화 ·
> W6·W7·W8 메트릭 룰은 각 태스크가 규약에 따라 추가하도록 이관 · `parallel_with` 의 폐기 노드 F3 정리

```yaml
# ─── 식별 ───────────────────────────────
id:            O3-DEPLOY-MONITORING
title:         배포 파이프라인(웹/크롤러 분리) · 모니터링 · 알림 규약
workstream:    ops
owner_agent:   dev-ops

# ─── 존재 이유 ──────────────────────────
traces_to:     [H1, H3, NSM-qualified-lead]
why:           "웹 배포와 크롤러 워커 배포가 서로를 파괴하지 않고 장애 발생 사실이 사람에게 도달하는 경로가 없으면, 수집 중단(H1)·색인 손상(H3)·계측 유실(NSM)이 며칠간 무증상으로 진행된다."

# ─── DAG ────────────────────────────────
depends_on:    [F1-REPO-SCAFFOLD]
blocks:        []
parallel_with: [F2a-CORE-SCHEMA, F4-NEED-TAG-ONTOLOGY, F5-API-LAYER]
gate:          null      # Phase 1 은 게이트와 무관하게 선행 (PRD §4)

# ─── 산출물 ─────────────────────────────
deliverable:
  pr_count:    1
  touches:
    - .github/workflows/deploy-web.yml
    - .github/workflows/deploy-worker.yml
    - .github/workflows/migrate-guard.yml
    - .github/workflows/deadman-drift.yml
    - ops/alerts/**
    - ops/probes/site-health.mjs
    - ops/scripts/rollback-web.sh
    - ops/scripts/rollback-worker.sh
    - ops/scripts/deploy-worker-drain.sh
    - apps/web/src/app/api/version/**
    - apps/web/src/lib/observability/error-reporter.ts
    - ops/tests/**
  artifacts:
    - "웹/워커 분리 배포 워크플로 2종 + drain 배포 스크립트"
    - "알림 룰 스키마 + 등록 조건 검증 CI (메트릭 실존 · 합성 도달)"
    - "하트비트/데드맨 스위치 (외부 스케줄 경로)"
    - "H3 외부 프로브 룰 3종 (sitemap URL 수 · 4xx/5xx 비율 · robots 해시)"
    - "롤백 스크립트 2종 + 스테이징 리허설 잡"
    - "마이그레이션 파괴적 구문 가드 잡"
    - "에러 리포터 스크러빙 훅"

# ─── 요구사항 ───────────────────────────
requirements:
  - id: REQ-1
    statement: >
      웹은 main 머지 시 자동 배포되고 /api/version 이 해당 커밋 SHA 를 반환하며, 30분 주기 드리프트
      체크 잡이 배포 SHA 와 main HEAD 를 비교해 불일치 지속 시 GitHub Actions 잡 실패로 기록한다.
    acceptance: >
      (a) 배포 스모크 — GET /api/version 의 sha == GITHUB_SHA, (b) 드리프트 잡에 불일치 픽스처 주입 시
      워크플로가 exit != 0 으로 종료.

  - id: REQ-2
    statement: >
      크롤러 워커는 웹과 분리된 워크플로·이미지 태그로 배포되며, apps/web 경로만 변경된 PR 은
      워커 배포 잡을 트리거하지 않는다.
    acceptance: >
      워크플로 path filter 테스트 — apps/web 단독 변경 이벤트 시뮬레이션에서 deploy-worker 잡이 skipped.

  - id: REQ-3
    statement: >
      워커 배포는 실행 중 크롤 작업이 0건이 되거나 drain 대기 10분이 경과한 뒤에만 새 버전으로
      전환하며, 전환 과정에서 SIGKILL 호출 횟수가 0이다.
    acceptance: >
      통합테스트 — 실행 중 job 1건 상태에서 deploy-worker-drain.sh 실행 시 job status=completed 이후
      전환, SIGKILL 호출 0회 assert.

  - id: REQ-4
    statement: >
      ops/alerts 에 등록되는 모든 룰은 (a) 참조 메트릭이 메트릭 저장소에 최근 24시간 내 데이터포인트를
      1개 이상 가지고, (b) 합성 조건 주입 시 알림 채널에 실제 메시지가 도달하며, (c) 억제 창
      필드(suppress_minutes)를 갖는 3조건을 모두 충족해야 CI 를 통과한다.
    acceptance: >
      `pnpm test:alerts:e2e` — 등록된 룰 전수에 대해 메트릭 존재 질의 + 합성 주입 후 채널 수신 assert,
      미존재 메트릭을 참조하는 룰 픽스처 1건에서 exit 1.

  - id: REQ-5
    statement: >
      모니터링 파이프라인이 5분 주기로 하트비트를 전송하고, 15분 이상 미수신이면 알림 채널과 무관한
      외부 경로(스케줄 워크플로 실패 통지)로 통지가 발생한다.
    acceptance: >
      통합테스트 — 하트비트 중단 주입 후 데드맨 잡이 exit != 0 으로 종료하고 통지 호출 1회 기록.

  - id: REQ-6
    statement: >
      외부 프로브 기반 H3 룰 3종(sitemap URL 수가 전일 대비 -30% 이하, 프로덕션 4xx+5xx 비율 1% 초과
      /5분 창, robots.txt 본문 해시 변경)이 등록되고 각각 합성 조건에서 발화한다.
    acceptance: >
      `pnpm test:alerts:e2e -- h3` — 3종 각각 합성 주입 시 채널 수신 1건, 정상 상태에서 수신 0건.

  - id: REQ-7
    statement: >
      웹·워커 각각 단일 명령 롤백 스크립트가 제공되며, 스테이징 실행 시 직전 배포 SHA 로 300초 이내
      복귀한다.
    acceptance: >
      CI 잡 — rollback-web.sh / rollback-worker.sh 실행 후 /api/version 및 워커 이미지 태그가 직전 SHA,
      소요 시간 < 300초 assert.

  - id: REQ-8
    statement: >
      배포 파이프라인은 expand 계열 마이그레이션만 자동 실행하고, DROP·RENAME·TRUNCATE·DELETE 를
      포함한 마이그레이션은 수동 승인 잡(작성자 외 승인자 1인)을 요구한다.
    acceptance: >
      CI 잡 migrate-guard — 파괴적 구문 포함 픽스처에서 자동 실행 잡이 exit 1 및 approval-required 상태를
      반환하고, 작성자 본인 승인만으로는 통과하지 않음을 assert.

# ─── 조건부 금지사항 ────────────────────
forbid:
  - id: FORBID-1
    when:         ops/alerts 에 룰을 추가·수정하는데 그 룰이 참조하는 메트릭이 메트릭 저장소에 최근 24시간 내 데이터포인트 0건인 경우
    must_not:     해당 룰을 main 에 등록해 "모니터링 중"으로 표기
    because:      존재하지 않는 메트릭을 가리키는 YAML 은 스키마 검증을 통과하지만 영원히 발화하지 않는다. 알림이 오지 않는 것과 정상인 것을 구분할 수 없게 되고, O3 의 존재 이유(장애를 사람이 아는 경로)가 계약 준수 상태에서 소멸한다
    detect:       CI 잡 alerts-metric-exists — 룰 파일의 metric 필드를 메트릭 저장소에 질의해 데이터포인트 0건이면 exit 1 (신규 메트릭은 소유 태스크가 메트릭을 먼저 배포한 뒤 룰을 추가하는 순서를 규약으로 명시)
    on_violation: block_merge

  - id: FORBID-2
    when:         크롤러 워커 배포가 트리거되었고 실행 중인 크롤 작업이 1건 이상인 경우
    must_not:     컨테이너 즉시 종료(SIGKILL) 또는 작업 큐를 비우고 새 버전으로 교체
    because:      중단된 크롤은 원문이 일부만 적재된 상태로 남아 C4 가 반쪽 가격을 정상 데이터로 오인하고, 소스 재방문은 레이트리밋·차단 위험(G3) 때문에 즉시 재시도할 수 없다
    detect:       통합테스트(REQ-3) — 실행 중 job 픽스처에서 SIGKILL 호출 0회 및 job status=completed assert
    on_violation: block_merge

  - id: FORBID-3
    when:         배포 파이프라인이 프로덕션 DB 에 마이그레이션을 실행하는 경우
    must_not:     DROP TABLE/DROP COLUMN/TRUNCATE/DELETE 구문을 포함한 스크립트를 수동 승인 없이 자동 실행
    because:      크롤링 원문은 소스가 바뀌면 동일하게 재수집되지 않고 리드·관측 이벤트는 과거 행동이라 재생성이 불가능해, 한 번의 자동 실행으로 NSM 시계열과 H1 근거 데이터가 영구 소실된다
    detect:       CI 잡 migrate-guard — SQL 정적 스캔 후 자동 실행 잡 거부(픽스처 테스트 포함)
    on_violation: block_merge

  - id: FORBID-4
    when:         ops/alerts 의 룰에 대해 (삭제 · 임계값 상향 · 평가 윈도우 확대 · 라벨 셀렉터 축소 · enabled:false) 중 하나에 해당하는 diff 가 발생한 경우
    must_not:     라벨 `alert-threshold-change` 와 작성자 외 승인 1인 없이 머지
    because:      노이즈를 이유로 룰을 무음화하면 수집 유실·W7 삭제요청 방치 같은 법적·지표적 사고가 아무에게도 보고되지 않은 채 진행되고, 방치 기간이 그대로 책임 범위가 된다. 삭제와 임계 상향만 막으면 윈도우를 5분에서 6시간으로 넓히는 동일 효과의 변경이 그대로 통과한다
    detect:       CI — 룰 파일 diff 를 5개 패턴으로 분류해 해당 시 라벨·승인자 조건 검사, 미충족이면 exit 1
    on_violation: block_merge

  - id: FORBID-5
    when:         프로덕션 시크릿·환경변수를 추가·변경하는 경우
    must_not:     값을 리포지토리 파일·CI 로그·에러 리포트에 평문으로 기록
    because:      크롤링 소스 계정과 DB 크리덴셜이 유출되면 데이터 전체 유출과 소스 영구 차단이 동시에 발생하며, 차단된 소스는 G3 재실사 없이는 복구할 수 없다
    detect:       CI secret scanning(gitleaks) + 로그 마스킹 단위테스트(시크릿 값 포함 출력이 마스킹되는지 assert)
    on_violation: block_merge

  - id: FORBID-6
    when:         에러 모니터링 SDK 가 요청 컨텍스트를 이벤트에 첨부하는 경우
    must_not:     요청 본문·쿼리스트링·쿠키를 필터 없이 외부 모니터링 서비스로 전송
    because:      W7 정정 요청 폼 본문과 검색 파라미터에는 이용자가 직접 입력한 개인정보가 포함될 수 있고, 국외 서비스로 전송된 뒤에는 고지·파기 통제가 불가능해 개인정보 국외이전 위반이 된다
    detect:       단위테스트 — beforeSend 훅이 body·cookie·query 키를 제거함을 금지 키 스냅샷으로 assert
    on_violation: block_merge

rollback: >
  워크플로·스크립트·룰 파일 PR revert 로 이전 배포 구성으로 복귀한다. 웹은 Vercel 에서 직전 배포를
```
