# O3 — 배포·모니터링·알림

> 개정 3판 (2차 감사 `docs/audit/round2-webops.md` O3 절 반영)
> 주요 변경: **메트릭 저장소를 본 계약 범위로 편입**(detect 대상 부재 해소) · **알림 룰 소유 경계를 파일 단위 제공자 규약으로 확정**
> (W6·W7·W8·W9·O2 가 각자 `ops/alerts/<task>.yml` 을 소유하고 O3 는 규약·공통 룰·pending 추적을 소유) ·
> **`pending_rules` 데드맨**으로 "메트릭은 있는데 룰이 없는 상태"를 자동 탐지 · `suppress_minutes` 상한 명시 ·
> 보호 상수 완화 금지 확대 · 에러 리포터 스크러빙을 값 패턴 재귀 스캔으로 격상 · G4 색인 게이트를 배포 단계에서 집행

## 알림 룰 소유 규약 (본 계약이 정의하고 하류가 따른다)

| 구분 | 소유 | 파일 |
|---|---|---|
| 룰 스키마 · 등록 조건 CI · 채널 · 억제 · 데드맨 · pending 추적 | **O3** | `ops/alerts/_schema.json` · `ops/alerts/_pending.yml` · `ops/alerts/o3-*.yml` |
| 각 계약이 노출하는 메트릭의 룰 | 해당 계약 | `ops/alerts/w6-lead.yml` · `w7-correction.yml` · `w8-correction-sla.yml` · `w9-observability.yml` · `o2-review-queue.yml` |

> W1 sitemap 제공자 규약과 동형이다. 디렉터리는 공유하되 **파일 단위로 소유자가 1명**이므로 PR 1개 원칙이 깨지지 않는다.

  - id: REQ-4
    statement: >
      워커 배포는 실행 중 크롤 작업이 0건이 되거나 drain 대기 10분 경과 후에만 새 버전으로 전환하며

    acceptance: >

    statement: >

    acceptance: >
      `pnpm test:alerts:e2e` — 등록 룰 전수 3조건 검사 통과, 미존재 메트릭 참조 픽스처와

    on_violation: block_merge

    detect:       CI migrate-guard — SQL 정적 스캔 후 자동 실행 잡 거부(픽스처 테스트 포함)
    on_violation: block_merge

  - id: FORBID-4
    when:         보호 상수·룰에 대해 (룰 삭제 · 임계 상향 · 평가 윈도우 확대 · 셀렉터 축소 · enabled:false · suppress_minutes 증가 · drain 대기 10분 단축 · 롤백 상한 300초 상향) 중 하나에 해당하는 diff 가 발생한 경우

    detect:       CI — ops/alerts 와 ops/scripts 상수 diff 를 8개 패턴으로 분류해 해당 시 라벨·승인자 조건 검사, 미충족이면 exit 1

    detect:       CI secret scanning(gitleaks) + 로그 마스킹 단위테스트

    detect:       단위테스트 — beforeSend 훅이 페이로드를 **재귀 스캔**해 (a) 금지 키, (b) 이메일·전화 정규식 매치 값, (c) 200자 초과 자유 텍스트를 제거함을 중첩 3단 픽스처로 assert
