# C6 — 니즈 태그 자동 부여 (룰 + LLM)

> 계약 규격: [02-task-contract-spec.md](../02-task-contract-spec.md) §1 (R-6·R-7 반영)
> **v2 (2026-08-03)** — 감사 REVISE 반영: 의미 반전 환각 봉쇄 · FORBID-2 의 '치료' 오작동 수정 ·
> 결정론/실데이터 하한 신설 · F2/F4 정합화 · ID 오참조 4건 정정
> 상태: 착수 대기 (⛔ G1·G3 통과 + F4 확정 + 아래 **선행 조건** 충족 후)

---

## 설계 전제 1 — 태그는 '니즈'이지 '효능'이 아니다

F4 온톨로지의 태그는 **사용자의 상태·조건**을 가리키는 라벨이지 업체의 **치료 효과 주장**이 아니다.

- ✅ `back_neck` = "허리·목 관련 프로그램을 표방하는 업체"
- ❌ `back_neck` = "허리디스크에 효과가 있는 업체"

**단, '치료'라는 단어 자체는 금지어가 될 수 없다.** `도수치료`는 메디컬 웰니스 축의 정식 업종명이고 PRD 는 이 축을
유지하기로 확정했다. 단어 단위 금지는 메디컬 축 태그를 대량 소실시키고, 그러면 개발자가 사전을 임의로 완화해
**규격 원칙 2(무조건 금지는 깨지고, 깨지는 순간 다른 금지도 협상 대상이 된다)** 가 그대로 실현된다.
→ FORBID-2 의 `when` 은 **질환명 + 효능 동사 결합 패턴**이며, D4 `medical_scope.yaml` 의 업종명 enum 은
명시적 예외다.

## 설계 전제 2 — substring 검증만으로는 환각의 한 종류만 잡힌다

`raw_payload.substr(offset,len) === evidence_text` 는 **완전 날조**만 막는다. 잡지 못하는 것:

| 유형 | 예 | v2 대응 |
|---|---|---|
| 의미 반전 | "여성 전용 탈의실 **없음**" → `women_only` | REQ-1 I4(문장 경계 정렬·최소 길이) + REQ-2(부정·반전 평가셋 20건 태그 0건) |
| 근거 부적합 | 2글자 부분문자열 인용 | REQ-1 I3(최소 12자) |
| 타 대상 귀속 | 같은 문서 내 다른 지점 설명 구간 인용 | REQ-1 I5(evidence 는 대상 venue 에 연결된 source_record 에서만) |

## 선행 조건 — F2 스키마 개정 (미충족 시 착수 금지)

| 대상 | 필요 정의 | 근거 |
|---|---|---|
| `venue_need_tag.assignment_method` | `ENUM('rule','llm','editor')` NOT NULL | REQ-1 · FORBID-4 |
| `venue_need_tag.confidence` | `numeric(3,2)` NOT NULL, CHECK 0~1 | REQ-1 |
| `venue_need_tag.model_id` | `text` NOT NULL (룰 태그는 `'rule'` 리터럴) | REQ-1 · REQ-6 |
| `venue_need_tag.prompt_hash` | `text` NOT NULL (룰 태그는 `'rule'` 리터럴) | REQ-1 · REQ-6 |
| `venue_need_tag.evidence_source_record_id` | FK NOT NULL | REQ-1 |
| `venue_need_tag.evidence_char_start` / `evidence_char_end` | `integer` NOT NULL | REQ-1 |
| `venue_need_tag.evidence_text` | `text` NOT NULL | REQ-1 |
| `venue.tagging_status` | `ENUM('pending','done','failed')` NOT NULL DEFAULT `'pending'` | REQ-8 · FORBID-3 |

**본 태스크는 마이그레이션도, F4 온톨로지 파일도 수정하지 않는다.** 온톨로지에 결함이 발견되면
(예: 태그 라벨 자체가 D4 금지표현에 매칭) 코드를 쓰지 않고 **F4 변경을 요청한 뒤 대기**한다.

```yaml

id:            C6-TAG-ASSIGN
title:         니즈 태그 자동 부여 (룰 + LLM 하이브리드)
workstream:    pipeline
owner_agent:   dev-pipeline

# ─── 존재 이유 ──────────────────────────
traces_to:     [H5, H3]
why:           "니즈 태그가 자동으로 붙지 않으면 '3050 몸 상태 기준 필터'(W2)와
                지역×카테고리×니즈 롱테일 랜딩(W4)이 둘 다 성립하지 않는다."

# ─── DAG ────────────────────────────────
depends_on:    [C5-ENTITY-RESOLUTION, F4-NEED-TAG-ONTOLOGY, F2a-CORE-SCHEMA]
blocks:        [C7-QUALITY-GATE, W4-COMBO-LANDING]
parallel_with: [W2-DISCOVERY-LIST, W3-VENUE-DETAIL, W5-EDITOR-REPORT, W7-CORRECTION-REQUEST]
gate:          [G1, G3]

# ─── 산출물 ─────────────────────────────
deliverable:
  pr_count:    1
  touches:
    - packages/pipeline/src/tagging/**
    - packages/pipeline/tests/tagging/**
    - packages/pipeline/fixtures/tag-eval/**
    - packages/pipeline/prompts/tagging/**
    - packages/pipeline/scripts/sample_tag_eval.py
  artifacts:
    - "룰 태거 + rule-map.yaml (온톨로지 aliases 에서 유도한 키워드 규칙)"
    - "LLM 태거 (구조화 출력 + evidence 검증 게이트)"
    - "개발셋 200업체 / 홀드아웃 100업체 평가 데이터 + 표집 스크립트"
    - "부정·반전 표현 픽스처 20건"

# ─── 요구사항 ───────────────────────────
requirements:
  - id: REQ-1
    statement: >
      저장되는 venue_need_tag 행은 불변식 I1~I6 을 전수 만족한다.
      I1 tag_id 는 F4 need-tags.yaml 의 id 집합에 속한다;
      I2 assignment_method · confidence · model_id · prompt_hash NULL 0건;
      I3 evidence_text 는 evidence_source_record_id 의 raw_payload 에서
         [char_start, char_end) 로 잘라낸 문자열과 정확히 일치하며 길이 ≥ 12자;
      I4 evidence 구간의 시작·끝이 문장 경계(문장부호 또는 문서 시작/끝)에 정렬되어
         근거 문장 전체를 포함한다;
      I5 evidence_source_record_id 는 해당 venue 에 venue_source_link 로 연결된 레코드다;
      I6 rule-map.yaml 에 등재된 tag_id 의 assignment_method 는 'llm' 이 될 수 없다.
    acceptance: >
      속성 테스트 `pnpm test:tag-invariants` — 개발셋+홀드아웃+무작위 입력의 전 출력에서 I1~I6 위반 0건,
      그리고 rule-map.yaml 이 온톨로지의 filter_visible=true 태그를 8개 이상 포함하지 않으면 exit 1.

  - id: REQ-2
    statement: >
      부정·반전 표현 픽스처 20건("주차 불가", "여성 전용 아님", "샤워실 없음" 등 온톨로지 태그별 최소 1건)에서
      해당 태그가 부여된 건수가 0 이다.
    acceptance: "`pnpm test:tag-negation` — 20건 처리 결과 대상 태그 부여 0건, 1건이라도 붙으면 exit 1"

  - id: REQ-3
    statement: >
      홀드아웃 100업체 기준 태그 부여 precision ≥ 0.90 이다.
    acceptance: "`pnpm test:tag-holdout` 내 precision assertion >= 0.90 (임계 하드코딩)"

  - id: REQ-4
    statement: >
      홀드아웃 100업체 기준 recall ≥ 0.70 이다.
    acceptance: "`pnpm test:tag-holdout` 내 recall assertion >= 0.70"

  - id: REQ-5
    statement: >
      평가 데이터는 `sample_tag_eval.py` 로 C5 가 확정한 venue 모집단에서 축별 층화 무작위 추출(시드 고정)되며,
      개발셋 200업체와 **개발 중 열람이 차단된 홀드아웃 100업체**로 분리되고,
      라벨 작성자·작성일·판단 근거가 업체×태그마다 기록된다.
    acceptance: >
      CI job `tag-eval-integrity` — (a) 표집 재실행 결과 id 집합이 커밋본과 일치,
      (b) 홀드아웃 경로가 `src/tagging/**` 에서 참조 0건, (c) 라벨 3필드 빈 값 0건.

  - id: REQ-6
    statement: >
      동일 venue·동일 source_record 스냅샷에 대해 태깅을 2회 실행한 결과의 태그 집합
      (tag_id, assignment_method, evidence 구간)이 동일하다.
    acceptance: >
      `pnpm test:tag-determinism` — 50업체 2회 실행 결과 서명 해시 일치, 그리고 LLM 호출 파라미터에
      temperature === 0 이 아닌 호출이 1건이라도 있으면 exit 1.

  - id: REQ-7
    statement: >
      실수집 venue 300건을 입력한 nightly 배치에서 최소 1개 태그가 부여된 venue 비율이 ≥ 60% 이다.
    acceptance: >
      CI job `tag-smoke` (스테이징 DB, nightly) — 비율 < 0.60 이면 exit 1 및 태그별 부여 건수 stdout 출력.
      픽스처로는 만족 불가(입력이 DB 질의로 고정).

  - id: REQ-8
    statement: >
      동일 nightly 배치에서 tagging_status='failed' 인 venue 비율이 ≤ 5% 이고,
      failed venue 는 전량 재처리 큐에 적재된다.
    acceptance: >
      CI job `tag-smoke` — failed 비율 > 0.05 이면 exit 1, 그리고 (failed venue 수 − 큐 적재 수) ≠ 0 이면 exit 1.

# ─── 조건부 금지사항 ────────────────────
forbid:
  - id: FORBID-1
    when:     >
      LLM 이 반환한 태그가 REQ-1 의 I3·I4·I5 중 하나라도 위배하는 경우
      (원문 불일치 · 12자 미만 · 문장 경계 미정렬 · 타 venue 소스 인용)
    must_not: >
      그 태그를 저장하거나, evidence 를 원문에서 가장 유사한 구절로 치환 · 구간을 확장해 통과시키기
    because:  >
      원문에 없는 '여성전용'이나 "여성 전용 탈의실 없음"에서 잘라낸 '여성 전용' 태그가 붙으면
      3050 사용자가 그 필터를 믿고 헛걸음하고, 한 번 겪은 사용자는 필터를 다시 쓰지 않아
      H5(필터 사용률 25%)가 붕괴한다
    detect:   >
      통합테스트 — mock LLM 응답 40건(완전 날조 10 · 부정문 인용 10 · 2글자 인용 10 · 타 venue 인용 10)에서
      저장 태그 0건 검증 + REQ-2 의 부정·반전 20건 회귀
    on_violation: block_merge

  - id: FORBID-2
    when:     >
      태그 근거 문구가 D4 `forbidden_lexicon.yaml` 의 **질환명 + 효능 동사 결합 패턴**(치료효과 보장 계열
      rule_id)에 매칭되고, 그 매칭이 D4 `medical_scope.yaml` 의 업종명 enum(도수치료·한의원 등)에서
      비롯된 것이 아닌 경우
    must_not: >
      그 근거로 태그를 부여하거나, 태그 라벨·설명 문자열에 효능 표현을 포함
    because:  >
      '허리디스크에 좋은 필라테스' 같은 태그는 의료광고법상 치료효과 보장·오인 광고이며,
      크롤링 문구를 우리가 태그로 재가공한 순간 광고 주체가 우리로 옮겨온다.
      반대로 업종명까지 금지하면 메디컬 축 태그가 대량 소실돼 축 하나가 제품에서 사라진다
    detect:   >
      CI job `tag-medical-guard` — `validate_d4.py` 의 lexicon 판정을 태그 evidence 전수에 적용하되
      medical_scope enum 매칭 구간을 예외 처리. 단위테스트 픽스처 30건(업종명 15건은 태그 유지 /
      효능 주장 15건은 태그 0건)으로 양방향 검증
    on_violation: block_merge

  - id: FORBID-3
    when:     >
      LLM 응답이 JSON 스키마 검증에 2회 연속 실패한 경우
    must_not: >
      자유텍스트 응답에서 정규식·문자열 분할로 태그를 추출하거나, 룰 태거 결과로 빈칸을 채워
      tagging_status 를 'done' 으로 마킹
    because:  >
      스키마 밖 응답은 모델이 지시를 따르지 못한 상태이고, 여기서 뽑은 태그는 근거 추적이 불가능해
      O2 검수에서도 걸러지지 않은 채 영구히 남는다
    detect:   >
      통합테스트 — 스키마 위반 응답 mock 에서 호출 3회 · 저장 태그 0건 · tagging_status='failed' ·
      재처리 큐 1건 검증 + 모듈 경계 테스트로 LLM 응답 원문 문자열이 zod parse 이외 경로로
      태그 생성 함수에 도달하지 않음을 확인
    on_violation: block_merge

  - id: FORBID-4
    when:     >
      동일 venue 에 assignment_method='editor' 인 태그가 존재하는 상태에서 태깅을 재실행하는 경우
    must_not: >
      해당 행을 삭제하거나 tag_id·evidence·confidence 를 덮어쓰기
    because:  >
      O2 어드민에서 사람이 고친 태그가 다음 파이프라인 실행에 조용히 되돌아가면 검수 작업이
      무한 반복되고, 검수자는 결국 검수를 포기한다
    detect:   >
      통합테스트 — editor 태그 10건이 있는 venue 를 재처리한 뒤 해당 10건의 행 id·값이 동일한지 검증
    on_violation: block_merge

  - id: FORBID-5
    when:     >
      LLM 태거의 프롬프트(동적 조립분 + 정적 템플릿 파일 전체)를 구성할 때
    must_not: >
      대상 venue 에 연결된 source_record 외의 데이터(다른 업체 원문·태그 결과, 카테고리 평균,
      실제 업체명이 포함된 few-shot 예시)를 포함
    because:  >
      이웃 업체 정보가 컨텍스트에 있으면 모델이 그 사실을 대상 업체의 것으로 옮겨 적고(교차오염),
      이 오류는 evidence 검증도 통과할 수 있어 가장 잡기 어렵다
    detect:   >
      (a) 프롬프트 빌더 단위테스트 — 생성된 프롬프트에서 대상 venue 소스 문자열과 정적 템플릿을 제외한
      잔여 문자열 0, (b) CI job `prompt-lint` — `prompts/tagging/**` 정적 템플릿 자체를 venue 상호명
      사전(스테이징 venue 명 전수)과 대조해 매칭 시 실패
    on_violation: block_merge

  - id: FORBID-6
    when:     >
      `pnpm test:tag-holdout` · `test:tag-negation` · `tag-eval-integrity` 중 하나가 실패한 상태에서
      통과시키려는 변경을 만들 때
    must_not: >
      임계(precision 0.90 / recall 0.70 / 실데이터 0.60 · 0.05)를 완화하거나, 평가 라벨 수정 ·
      홀드아웃/부정 픽스처 삭제 · 홀드아웃을 소스에서 참조
    because:  >
      태그 precision 은 필터 신뢰도의 유일한 측정치이고, 이를 낮추면 H5 검증이 '맞춰 놓은 숫자'가 되어
      S2 가 진짜 차별점인지 판단할 근거가 사라진다
    detect:   >
      CI job `tag-eval-integrity` — 임계 상수 파일과 `fixtures/tag-eval/**` diff 감지 시

    on_violation: block_merge
```
