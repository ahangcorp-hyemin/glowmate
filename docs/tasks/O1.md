# O1 — 게이트 지표 대시보드

> 개정 2판 (감사 `docs/audit/W1-O3-audit.md` O1 절 반영)
> 주요 변경: **G1 3구간 차등 판정**(≥40 / 25~40 / <25) 모델링 · 소스 없는 CTR 카드 스코프 제외 ·
> H2(파싱 성공률) 카드 추가 · 임계값 원천을 **F1 소유 지표 레지스트리**로 교체(문서 마크다운 파싱 폐기) ·
> W9·C7 의존 명시 · 이벤트 기반 지표 한정 조건 · 실데이터 하한 REQ 추가

```yaml
# ─── 식별 ───────────────────────────────
id:            O1-METRICS-DASHBOARD
title:         게이트 지표 대시보드 (G1 3구간 · H2 · H4 · H5 · H7 · NSM)
workstream:    ops
owner_agent:   dev-ops

# ─── 존재 이유 ──────────────────────────
traces_to:     [H1, H2, H4, H5, H7, KM-price-coverage, NSM-qualified-lead]
why:           "게이트 판정과 가설 판정을 단일 정의로 관측하지 못하면, 축 제외·피봇·중단 결정이 사람마다 다른 숫자 위에서 내려진다."

# ─── DAG ────────────────────────────────
depends_on:    [F1-REPO-SCAFFOLD, F2b-QUALITY-SCHEMA, C7-QUALITY-GATE, W6-LEAD-TRACKING, W9-OBSERVABILITY-EVENTS]
blocks:        []
parallel_with: [O2-REVIEW-ADMIN, W8-CORRECTION-PROCESSING]   # KM-override-public-ratio 는 O2 코드가 아니라
                                                             # F2 오버라이드 레이어 테이블을 읽는다 (O2 미머지 시 값 0)
gate:          G4

# ─── 산출물 ─────────────────────────────
deliverable:
  pr_count:    1
  touches:
    - apps/web/src/app/(internal)/metrics-dashboard/**
    - apps/web/src/components/metrics/**
    - packages/metrics/definitions/**
    - packages/metrics/src/registry-loader.ts
    - .github/workflows/metric-registry-check.yml
    - apps/web/tests/metrics/**
    - apps/web/fixtures/metrics/**
  artifacts:
    - "지표 정의 SQL 6종 + 3구간 판정 함수"
    - "F1 지표 레지스트리 로더 (임계·구간·min_n·n 정의를 코드가 아닌 레지스트리에서 로드)"
    - "지표 카드 컴포넌트 (값 · 구간 · 표본 수 · 정의 버전 마커)"
    - "레지스트리 정합성 CI 잡"
    - "골든 픽스처 기반 쿼리 테스트"

# ─── 요구사항 ───────────────────────────
requirements:
  - id: REQ-1
    statement: >
      대시보드는 6개 지표 카드(KM-price-coverage, KM-parse-success, KM-filter-usage,
      KM-retention-week4, NSM-qualified-lead, KM-override-public-ratio)를 렌더하며, 각 카드의
      data-metric-id 가 F1 지표 레지스트리의 ID 집합과 대칭차집합 0으로 일치한다.
    acceptance: >
      e2e 테스트 — 카드 6개 존재, data-metric-id 집합과 레지스트리 ID 집합의 대칭차집합 0건.

  - id: REQ-2
    statement: >
      KM-price-coverage 는 3축 각각에 대해 PRD G1 의 3구간 판정
      (≥40% = pass / 25~40% = reinforce / <25% = exclude)을 산출해 축별 구간 라벨을 렌더한다.
    acceptance: >
      쿼리 골든 테스트 — 축별 커버리지 (45%, 32%, 18%) 픽스처 입력 시 구간 라벨이
      pass / reinforce / exclude 로 3/3 일치.

  - id: REQ-3
    statement: >
      각 지표의 집계 로직은 packages/metrics/definitions/*.sql 파일에만 존재하고, 대시보드 컴포넌트와
      API 라우트의 인라인 집계 SQL 검출 건수가 0이다.
    acceptance: >
      린트 규칙 `no-inline-metric-sql` — touches 내 ts/tsx 에서 SELECT·GROUP BY 문자열 검출 시 exit 1.

  - id: REQ-4
    statement: >
      임계값·구간 경계·min_n·n 의 정의는 F1 소유 지표 레지스트리(docs/metrics/registry.yaml)에서만
      로드되며, packages/metrics 및 apps/web 코드 내 임계 수치 리터럴 검출 건수가 0이다.
    acceptance: >
      CI 잡 `metric-registry-check` — (a) 코드 내 임계 리터럴 정규식 검출 0건, (b) 레지스트리에
      6개 지표 ID 가 전부 정의되어 있고 각 항목이 threshold·bands·min_n·n_unit 4필드를 가짐,
      (c) 누락 시 exit 1.

  - id: REQ-5
    statement: >
      각 카드는 집계 기간(rolling 28일), 표본 수 n, n 의 단위(레지스트리의 n_unit)를 표시하고,
      n < 레지스트리 min_n 이면 state="insufficient_sample" 로 렌더한다.
    acceptance: >
      컴포넌트 테스트 — min_n=100 지표에서 n=99 / n=100 두 케이스의 state 가
      insufficient_sample / ok, n_unit 문자열이 레지스트리 값과 일치.

  - id: REQ-6
    statement: >
      지표 쿼리가 에러를 반환하거나 결과 0행인 경우 카드가 state="unavailable" 로 렌더되고 값 노드가
      존재하지 않으며, 정상 픽스처에서는 6개 카드 전부 state="ok" 로 값이 렌더된다.
    acceptance: >
      통합테스트 — (a) 에러 mock·0행 픽스처에서 unavailable 및 값 노드 0개,
      (b) 정상 픽스처에서 ok 카드 6/6 (전량 unavailable 구현 시 실패).

  - id: REQ-7
    statement: >
      이벤트 기반 지표 4종(KM-filter-usage, KM-retention-week4, NSM-qualified-lead 및 그 전환율)은
      is_bot=false 이벤트만 입력으로 사용하며, 파이프라인 산출 지표 2종(KM-price-coverage,
      KM-parse-success)에는 이 조건을 적용하지 않는다.
    acceptance: >
      쿼리 테스트 — 봇 이벤트가 섞인 픽스처에서 이벤트 지표 4종 결과가 봇 제외 기대치와 일치하고,
      파이프라인 지표 2종은 is_bot 조건 없이 C7 리포트 값과 일치.

  - id: REQ-8
    statement: >
      스테이징의 실데이터 스냅샷에서 6개 카드 중 5개 이상이 state="ok" 로 값을 렌더한다.
    acceptance: >
      `pnpm test:e2e:metrics-staging` — 스테이징 대시보드 응답 파싱, ok 카드 수 ≥ 5
      (하드코딩 방지를 위해 값이 픽스처 상수와 동일하면 실패).

# ─── 조건부 금지사항 ────────────────────
forbid:
  - id: FORBID-1
    when:         F1 지표 레지스트리의 threshold·bands 값과 PRD·lean canvas 표(H1 40% · H5 25% · H7 20% · H2 80% · G1 3구간)가 1개라도 불일치한 상태로 PR 이 올라온 경우
    must_not:     대시보드를 머지·배포
    because:      게이트 판정 기준이 문서와 다르면 <25% 축을 통과시키거나 통과한 축을 제외하는 등 제품 범위 자체가 틀린 근거로 확정되고, 그 결정은 수개월치 작업량을 좌우한다
    detect:       CI 잡 metric-registry-check — 레지스트리 값과 PRD 표에서 추출한 값의 대조 테이블을 검증(레지스트리가 정본이며 PRD 표는 레지스트리 생성 시 F1 이 고정한 스냅샷과 비교)
    on_violation: block_merge

  - id: FORBID-2
    when:         지표 쿼리가 예외를 던지거나 결과 행이 0행인 경우
    must_not:     0% · "-" · 직전 캐시값으로 채워 정상 카드와 동일한 형태로 렌더
    because:      파이프라인 중단을 "지표 하락"으로 오독하면 멀쩡한 가설을 기각하거나 실제 하락을 데이터 결손으로 착각해 방치하게 되고, 둘 다 되돌릴 시점을 놓친다
    detect:       통합테스트(REQ-6) — 에러·0행 케이스에서 state="unavailable" 및 값 노드 0개 assert
    on_violation: block_merge

  - id: FORBID-3
    when:         packages/metrics/definitions/*.sql 의 분자·분모·기간·필터를 변경하는 경우
    must_not:     definition_version 증가와 차트상의 정의 변경 마커 없이 과거 구간까지 새 정의로 표시
    because:      정의가 바뀐 지점이 보이지 않으면 H4·H5 추세 판정이 조용히 뒤집히고, 어떤 정의로 어떤 결정을 내렸는지 사후 재구성이 불가능해진다
    detect:       CI — definitions diff 시 definition_version bump 강제 + 컴포넌트 테스트로 버전 경계 구간에 [data-definition-break] 마커 렌더 assert
    on_violation: block_merge

  - id: FORBID-4
    when:         지표 API 응답 또는 대시보드 화면이 집계 이전 단위 데이터를 포함하는 경우
    must_not:     visitor_id · session_id · ip_hash · 개별 이벤트 행을 응답 페이로드나 화면에 노출
    because:      집계 목적으로 수집한 행동 로그를 개인 단위로 열람하는 것은 목적 외 이용이며, 스크린샷 한 장이 외부로 나가면 개인정보 유출 사고로 처리된다
    detect:       통합테스트 — 지표 API 응답 JSON 을 재귀 탐색해 금지 키 4종이 0개임을 assert
    on_violation: block_merge

  - id: FORBID-5
    when:         docs/metrics/registry.yaml 또는 packages/metrics/definitions/*.sql 의 diff 가 포함된 PR 인 경우 (지표 미달 여부와 무관)
    must_not:     PR 작성자 본인의 승인만으로 머지 (라벨 `metric-definition-change` + 작성자 외 CODEOWNERS 승인 1인 필요)
    because:      게이트는 피봇·중단을 판단하는 장치인데 기준이 결과에 맞춰 움직이면 게이트가 없는 것과 같다. "미달 상태에서만 금지"로 조건을 좁히면 미달 직전에 미리 낮추는 경로가 그대로 열린다
    detect:       브랜치 보호 규칙 + CI — 해당 파일 diff 존재 시 라벨 및 작성자≠승인자 조건을 검사, 미충족이면 exit 1
    on_violation: block_merge

# ─── 경계 ───────────────────────────────
out_of_scope:
  - 검색 노출 기반 CTR(KM-search-to-detail-ctr) 카드 — Search Console 데이터를 수집하는 소유 태스크가 DAG 에 없어 본 태스크에서 제외한다. 소스 태스크 신설 후 별도 PR
  - 이벤트 수집·스키마 정의 — W9·W6 소관
  - 지표 레지스트리 파일의 신규 생성·항목 추가 — F1 소관 (본 태스크는 로드·검증만)
  - 알림 룰·임계 초과 통지 — O3 소관
  - 데이터 검수 큐 UI — O2 소관
  - 외부 BI 도구 도입 · 데이터 웨어하우스 구축
  - 임의 코호트 탐색·세그먼트 질의 기능

rollback: >
  PR revert 시 /metrics-dashboard 라우트와 packages/metrics 가 제거된다. 지표 정의는 읽기 전용
  뷰·쿼리만 사용하므로 원본 테이블 변경·삭제가 없고, revert 후에도 이벤트·파이프라인 데이터는
  그대로 보존된다. CI 잡(metric-registry-check)도 같은 PR 에 포함되어 함께 제거되며,
  F1 레지스트리 파일은 본 태스크가 만들지 않으므로 남는다.

done_when:
  - REQ-1~REQ-8 acceptance 가 CI 에서 전부 통과
  - FORBID-1~5 각각의 위반 픽스처·시나리오가 커밋되고 detect 가 차단함을 PR 본문에 기록
  - F1 지표 레지스트리에 6개 지표 ID 가 실재함을 확인 (없으면 착수 중단, F1 변경 선행)
  - W9 파생 뷰 3종과 W6 파생 뷰 2종, C7 `report:g4-coverage` 산출물이 실재함을 확인
  - 스테이징 실데이터에서 ok 카드 5개 이상 확인 (REQ-8)
  - touches 밖 파일 변경 0건 (CI path guard 통과)
```
