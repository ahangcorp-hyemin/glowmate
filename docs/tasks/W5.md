    detect:       CI 콘텐츠 린트 — medical_wellness 리포트의 본문·메타 문자열을 D4 사전과 대조, 히트 1건 이상이면 exit 1 (금칙 케이스 픽스처 5건 필수 포함)

    because:      W2·W3·W4 가 3중으로 막은 "추정치의 확정 표기"가 리포트 표면에서만 뚫리면, 사용자는 가장 신뢰하는 콘텐츠에서 틀린 가격을 읽게 되고 "가격이 틀린 사이트" 평판은 데이터를 고쳐도 회복되지 않는다
    detect:       렌더 스캔 테스트 `pnpm test:report-price` — 상태 4종 픽스처에서 non-confirmed 가격 노드에 배지 노드가 동반되지 않으면 실패, conflicted 픽스처는 값 노드 2개 미만이면 실패
    on_violation: block_merge

  - id: FORBID-4
    when:         리포트 대상 업체의 `visibility` 가 'public' 이 아닌 경우(hidden_quality / hidden_request / hidden_legal)

    detect:       통합테스트 — visibility 3종 비공개 픽스처 각각에서 (a) 가격 노드 0개(숫자 정규식 매칭 0건), (b) 업체 상세 href 0개, (c) sitemap 출력 0건 assert

  - id: FORBID-5

    must_not:     해당 파일을 editor_report 타입 콘텐츠로 빌드에 포함
    because:      방문하지 않은 곳을 방문했다고 쓰는 것이 리포트 20건 목표를 채우는 가장 쉬운 경로인데, 등록 editor_id 와 사진 1장만 요구하면 LLM 생성문이 100% 통과한다. 허구 리포트는 H6 코호트를 오염시키고 발각 시 서비스 신뢰가 회복 불가능하게 손상된다
    detect:       빌드타임 검증 CI — (a) EXIF DateTimeOriginal 파싱 후 visited_at 대비 일수 검사, (b) source_record 원문 대비 유사도 계산. 위반 픽스처 2종(EXIF 불일치·원문 복제) 각각에서 exit 1 확인
    on_violation: block_merge

  - id: FORBID-6
    when:         리포트 이미지 항목의 source 값이 "editor" 가 아닌 경우(업체 제공·소스 인용)
    must_not:     에디터 촬영물과 동일한 갤러리 컨테이너에 출처 라벨 없이 병렬 배치

    detect:       컴포넌트 테스트 — source!="editor" 픽스처 렌더 시 [data-image-source] 캡션 노드 존재 및 editor 이미지와 다른 컨테이너 소속 assert
    on_violation: block_merge
