## 선행 조건 — F2 스키마 개정 (미충족 시 착수 금지)

본 태스크는 **마이그레이션을 작성하지 않는다.** 아래 객체가 `F2a-CORE-SCHEMA, F2b-QUALITY-SCHEMA` 개정으로 머지되기 전에는 착수하지 않으며,
착수 후 부족이 발견되면 코드를 쓰지 않고 F2 변경을 요청한 뒤 대기한다.

| 대상 | 필요 정의 | 근거 REQ/FORBID |
|---|---|---|
| `price_plan.price_unit_type` | `ENUM('per_session','period_pass','single_session','unparseable')` NOT NULL | REQ-5 |
| `price_plan.total_amount_krw` | `integer` NULL, CHECK > 0 — 원문에서 추출한 **총액** | REQ-5 · FORBID-4 |
| `price_plan.session_count` | `integer` NULL, CHECK > 0 — 원문에서 추출한 **횟수** | REQ-5 · FORBID-4 |
| `price_plan.price_per_month_krw` | `integer` NULL, CHECK > 0 | REQ-2 · REQ-5 |
| `price_plan.period_days` | `integer` NULL, CHECK > 0 | REQ-2 · REQ-5 |
| `price_plan.is_promotional` | `boolean` NOT NULL DEFAULT false | FORBID-3 |
| `price_plan.promo_valid_until` | `date` NULL | FORBID-3 |
| `price_plan.parser_version` | `text` NOT NULL | REQ-5 · rollback |
| `price_plan.evidence_snippet` | `text` NOT NULL — `source_record.raw_payload` 의 부분문자열 | REQ-5 |

**이미 존재하므로 신설하지 않는 것**: `raw_text` · `source_record_id` · `price_per_session` · `failure_reason` ·
`confidence numeric(3,2)` · `visibility ENUM(...)` (F2 REQ-3·4·5).
수집 시각·출처 URL은 `source_record.fetched_at` · `source_record.source_url` 을 조인해 얻고 **price_plan 에 복제하지 않는다.**

## 이 계약이 봉쇄하는 악의적 준수 경로

이전 판(v1)은 "unparseable 이 **아닌** 비율 ≥ 80%"를 요구했다. `price_unit_type` 이 4값이므로
**애매한 입력을 전부 `single_session`·`period_pass` 로 분류하면 회당 단가를 한 건도 산출하지 않는 파서가
계약을 100% 준수했다.** v2는 (1) 분모를 "회차 정보가 존재하는 홀드아웃 라벨"로 고정한 **`per_session` 산출률**로
바꾸고, (2) 4개 `price_unit_type` 의 판정 기준을 계약에 명시하며, (3) `period_pass`·`single_session` 결과의
정확도까지 라벨과 대조한다.

```yaml
# ─── 식별 ───────────────────────────────
id:            C4-PRICE-NORMALIZER
title:         가격 정규화 엔진 (회당 단가 환산 · price_plan.confidence 생산)
workstream:    pipeline
owner_agent:   dev-pipeline

# ─── 존재 이유 ──────────────────────────
traces_to:     [H2, G4]
why:           "원문 가격 문자열('10회 65만' / '3개월 무제한 45만')을 회당 단가와 신뢰도로 환산하지 못하면
                '전화 안 걸고 가격까지 비교한다'는 UVP와 W2·W3의 확정/추정 구분이 동시에 소멸한다."

# ─── DAG ────────────────────────────────
depends_on:    [C1-CRAWLER-CORE, F2a-CORE-SCHEMA, F2b-QUALITY-SCHEMA, D4-MEDICAL-AD-GUARDRAIL]
blocks:        [C7-QUALITY-GATE, F6-PRICE-STATE, W2-DISCOVERY-LIST, W3-VENUE-DETAIL, W4-COMBO-LANDING]
parallel_with: [C5-ENTITY-RESOLUTION, C2-ADAPTER-NAVER, C3-ADAPTER-KAKAO, W1-SEO-FOUNDATION]
gate:          [G1, G3]

# ─── 산출물 ─────────────────────────────
deliverable:
  pr_count:    1
  touches:
    - packages/pipeline/src/price/**
    - packages/pipeline/tests/price/**
    - packages/pipeline/fixtures/price-golden/**
    - packages/pipeline/scripts/sample_price_golden.py     # 표집 스크립트 (REQ-3)
  artifacts:
    - "가격 정규화 모듈 (원문 → price_plan 레코드)"
    - "price_unit_type 4값 판정 기준표 + 실패 사유 코드 표"
    - "confidence 감점 규칙표 (요인·감점값 상수)"
    - "개발셋 140건 / 홀드아웃 60건 평가 데이터 + 표집 스크립트"
    - "실수집 스모크 잡 (nightly)"

# ─── 요구사항 ───────────────────────────
requirements:
  - id: REQ-1
    statement: >
      홀드아웃 평가셋 중 **정답 라벨의 unit_type 이 per_session 인 케이스**(= 원문에 총액과 횟수가
      모두 존재하는 케이스)를 분모로 한 per_session 산출률이 G1 통과 축별로
      exercise_body ≥ 0.85 · relax_recovery ≥ 0.75 · medical_wellness ≥ 0.60,
      통과 축 전체 가중평균 ≥ 0.80 이다.
    acceptance: >
      `pnpm test:price-holdout` — 위 4개 임계값을 테스트 소스에 하드코딩하고, 축 목록은
      `config/g1-axes.json` 에서 주입받아 통과 축만 판정. 미달 축이 1개라도 있으면 exit 1.

  - id: REQ-2
    statement: >
      홀드아웃 평가셋 전체에서 정답 라벨과 불일치하는 케이스가 0건이다. 대조 대상은
      price_unit_type · price_per_session · price_per_month_krw · period_days ·
      total_amount_krw · session_count 6개 필드 전부다 (파싱 포기는 허용, 틀린 값은 불허).
    acceptance: "`pnpm test:price-holdout` 내 fieldMismatch 카운트 assertion === 0"

  - id: REQ-3
    statement: >
      평가 데이터는 `sample_price_golden.py` 로 C1 이 수집한 `source_record` 모집단에서
      축별 층화 무작위 추출(시드 고정)되며, 개발셋 140건과 **개발 중 열람이 차단된 홀드아웃 60건**으로
      분리되고, 정답 라벨 작성자·작성일·판단 근거가 케이스마다 기록된다.
    acceptance: >
      CI job `price-eval-integrity` — (a) 표집 스크립트 재실행 결과의 케이스 id 집합이 커밋본과 일치,
      (b) 홀드아웃 파일이 `fixtures/price-golden/holdout/` 아래에 있고 개발 대상 소스(`src/price/**`)에서의
      참조가 0건, (c) 라벨 3필드(labeler·labeled_at·rationale) 빈 값 0건.

  - id: REQ-4
    statement: >
      C1 이 실제 수집한 `source_record` 중 무작위 200건을 입력한 nightly 스모크에서
      price_unit_type='per_session' 인 price_plan 이 25건 이상 생성된다.
    acceptance: >
      CI job `price-smoke` (스테이징 DB, nightly) — 산출 건수 < 25 이면 exit 1 및 실측치 stdout 출력.
      픽스처 입력으로는 이 잡을 만족시킬 수 없다(입력 소스가 DB 질의로 고정).

  - id: REQ-5
    statement: >
      출력 레코드는 아래 불변식 I1~I7 을 전수 만족한다.
      I1 price_unit_type='per_session' ⇔ (total_amount_krw NOT NULL ∧ session_count > 1 ∧
         price_per_session = floor(total_amount_krw / session_count));
      I2 price_unit_type='single_session' ⇔ (session_count = 1 ∧ price_per_session = total_amount_krw);
      I3 price_unit_type='period_pass' ⇒ (price_per_session IS NULL ∧ period_days NOT NULL ∧
         price_per_month_krw = floor(total_amount_krw × 30 / period_days));
      I4 price_unit_type='unparseable' ⇒ (금액 필드 4종 전부 NULL ∧ failure_reason 은 8종 폐쇄 enum 중 1개);
      I5 evidence_snippet 은 해당 source_record.raw_payload 의 부분문자열이며 길이 ≥ 6자;
      I6 parser_version NOT NULL;
      I7 모든 금액은 정수 KRW (부동소수 타입 미사용).
    acceptance: >
      속성 테스트 `pnpm test:price-invariants` — 홀드아웃 + 개발셋 + 무작위 생성 입력 500건에 대해
      I1~I7 위반 건수 합계 0. 위반 시 위반 불변식 id 와 레코드를 stdout 에 출력.

  - id: REQ-6
    statement: >
      price_plan.confidence 는 커밋된 감점 규칙표(기준값 0.95, 감점 요인 5종 — 횟수 유추 −0.20 ·
      축약 단위 정규화 −0.05 · is_promotional −0.35 · 종료일 불명 프로모션 −0.10 ·
      fetched_at 180일 초과 −0.15, 하한 0.10)로 산출되며, 라벨된 60건의 기대 confidence 와
      소수 둘째자리까지 일치한다.
    acceptance: >
      `pnpm test:price-confidence` — (a) 60건 기대값 일치, (b) 전 출력에서 confidence = 1.00 인 행 0건,
      (c) is_promotional=true 인 행의 confidence ≤ 0.60 위반 0건.

  - id: REQ-7
    statement: >
      동일 입력 200건에 대해 파서를 2회 실행한 결과 JSON 이 바이트 단위로 동일하다.
    acceptance: "`pnpm test:price-determinism` — 2회 실행 결과 sha256 일치"

# ─── 조건부 금지사항 ────────────────────
forbid:
  - id: FORBID-1
    when:     >
      원문에서 (총액, 횟수) 중 하나라도 추출에 실패했거나, 추출값이 CHECK(>0)를 만족하지 못하는 경우
    must_not: >
      나머지 값 · 카테고리 평균 · 업종 기본 횟수 가정으로 price_per_session 을 채우거나,
      price_unit_type 을 per_session / single_session 으로 분류
    because:  >
      추정 가격이 확정 가격과 구분 없이 노출되면 사용자가 그 값을 믿고 전화를 걸었을 때 실제 가격과
      어긋나고, UVP 전체가 걸린 '가격 신뢰'가 단 한 건의 오차로 붕괴한다
    detect:   >
      `pnpm test:price-invariants` 의 I1·I2·I4 (결손 입력 12케이스 포함) 위반 0건 +
      CI grep — src/price/** 에 카테고리 평균·기본 횟수 상수(`DEFAULT_SESSION_COUNT` 류 식별자)가
      선언되면 실패
    on_violation: block_merge

  - id: FORBID-2
    when:     >
      price_unit_type 이 period_pass 로 분류된 레코드를 처리할 때
    must_not: >
      주 n회 / 월 n회 이용 가정을 곱해 price_per_session 을 산출
    because:  >
      실제 이용 빈도 가정이 1회만 틀려도 회당 단가가 2~3배 왜곡되고, 무제한권 업체가 회당가 정렬
      최상단을 독식해 '비교'라는 기능 자체가 허위가 된다
    detect:   >
      레코드 수준 불변식 I3 (period_pass 행의 price_per_session IS NULL) 위반 0건 +
      CI grep — src/price/** 에 주당/월당 이용횟수 리터럴(`2.5`, `weeklyVisits`, `sessionsPerMonth` 등
      규칙표에 열거된 식별자)이 등장하면 실패
    on_violation: block_merge

  - id: FORBID-3
    when:     >
      원문이 D4 `forbidden_lexicon.yaml` 의 유인 표현 rule(`MED-L-*` 중 할인·이벤트·무료·최저가 계열)
      또는 커밋된 프로모션 토큰 사전에 매칭되거나, 가격에 종료일이 명시된 경우
    must_not: >
      is_promotional=false 로 기록하거나, confidence 감점(−0.35)을 적용하지 않고 저장
    because:  >
      미끼가 된 첫 달 가격이 확정가(confidence ≥ 0.7)로 노출되면 방문자가 현장에서 다른 가격을 듣게 되고,
      '가격이 틀린 사이트'라는 평판은 데이터를 고쳐도 회복되지 않는다
    detect:   >
      단위테스트 — D4 golden_cases 의 kind=lexicon 유인 케이스 20건 + 자체 프로모션 픽스처 18건에서
      is_promotional=true ∧ confidence ≤ 0.60 위반 0건. 토큰 사전 확장은 사전 파일 diff에
      `promo-lexicon-approved` 라벨을 요구
    on_violation: block_merge

  - id: FORBID-4
    when:     >
      session_count > 1 인데 price_per_session 이 total_amount_krw 와 같거나(나눗셈 미적용),
      산출된 price_per_session 이 축별 sanity 범위
      (exercise_body 5,000~500,000 / relax_recovery 5,000~800,000 / medical_wellness 5,000~1,500,000 KRW)
      를 벗어나는 경우
    must_not: >
      그 값을 price_per_session 에 기록
    because:  >
      '만' 단위 누락으로 650,000원이 65원이 되거나 횟수 나눗셈이 빠져 10회권 총액이 회당가로 기록되면,
      그 레코드는 회당가 오름차순·내림차순 정렬의 양 극단에 올라 가장 눈에 띄는 자리에서 서비스를 무너뜨린다
    detect:   >
      속성 테스트 — 두 조건에 해당하는 입력에 대해 반드시 unparseable + failure_reason ∈
      {OUT_OF_RANGE, DIVISION_NOT_APPLIED} 를 반환하는지 검증 (범위 상수 테스트에 하드코딩)
    on_violation: block_merge

  - id: FORBID-5
    when:     >
      venue.category 가 medical_wellness 인 레코드를 저장할 때
    must_not: >
      price_plan.visibility 를 'public' 으로 기록하거나, 할인율 · 최저가 · 타 업체 대비 비교 ·
      시술명 결합 표시문자열 등 공개 표기용 파생 필드를 산출
    because:  >
      의료광고법상 비급여 진료비의 비교·유인 표시는 규제 대상이고, 공개 표기 판정이 게이트(C7) 앞단에서
      일어나면 어느 필드가 가드레일을 거쳤는지 추적이 불가능해져 위반 1건에 서비스 전체가 중단될 수 있다.
      medical 표기 판정은 D4 화이트리스트를 인용하는 C7 단독 소유다
    detect:   >
      통합테스트 — medical_wellness 픽스처 30건 처리 후 price_plan.visibility 가 전부 F2 DEFAULT
      ('hidden_quality') 로 남아 있는지 검증 + CI 스키마 체크로 price_plan 에 `public_` 접두 컬럼 또는
      discount/min_price 파생 컬럼이 존재하면 실패
    on_violation: block_merge

  - id: FORBID-6
    when:     >
      `pnpm test:price-holdout` 또는 `price-eval-integrity` 가 실패한 상태에서 통과시키려는 변경을 만들 때
    must_not: >
      임계 상수(0.85 / 0.75 / 0.60 / 0.80 / 25건)를 낮추거나, 정답 라벨을 수정하거나,
      홀드아웃 케이스를 개발셋으로 이동 · 삭제하거나, 홀드아웃 파일을 소스에서 참조
    because:  >
      H2(회당가 환산율)는 UVP의 생존 조건이고, 시험지를 고쳐 통과시키면 게이트가 '측정 결과'가 아니라
      '맞춰 놓은 숫자'가 되어 G1·G4 판정 전체가 근거를 잃는다
    detect:   >
      CI job `price-eval-integrity` — 임계 상수 파일과 `fixtures/price-golden/**` 의 diff 감지 시
      `eval-change-approved` 라벨 없이 머지 차단, 홀드아웃 경로가 src/price/** 에서 참조되면 즉시 실패
      (CODEOWNERS 병행)
    on_violation: block_merge
```
