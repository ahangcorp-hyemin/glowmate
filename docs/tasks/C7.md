> 계약 규격: [02-task-contract-spec.md](../02-task-contract-spec.md) §1 (R-6·R-7 반영)
> **v2 (2026-08-03)** — 감사 **REJECT** 반영 전면 재작성: 뷰 필터·공개 임계값의 계약화 ·
> `is_public` → `venue.visibility` ENUM 정합화 · O2 오버라이드와의 충돌 해소 · 캐시 우회 차단 · 커버리지 축별 분리

## v1 이 REJECT 된 이유와 v2 의 대응

| REJECT 사유 | v2 대응 |
|---|---|
| `public_venue` 뷰의 **필터 조건이 계약에 없어** `SELECT * FROM venue` 로도 전 REQ 통과 | **REQ-3** — 결합 진리표 · 컬럼 화이트리스트 · hidden 픽스처 60건 뷰 조회 0건 |
| **공개 임계값이 계약에 없음**. C4·C5·C6 에 다 있는 '임계 하향 금지'가 집행자에게만 부재 | **REQ-2**(임계 60 하드코딩) + **FORBID-3**(임계·가중치·골든 기대값 승인 게이트) |
| REQ-1(`is_public` 쓰기 경로 1개) ↔ O2 REQ-4(2인 승인 공개 전환) **양립 불가** | **판정(C7: `quality_verdict` + `venue.visibility`)과 오버라이드(O2: `review_override`)를 분리 저장**, 최종 상태는 뷰가 결합 (REQ-1·REQ-3) |
| `is_public`·`canonical_venue`·`venue_price` 는 **F2 에 없음** → grep detect 가 공허 통과 | F2 정본(`venue.visibility` ENUM 4값 · `price_plan` · `price_conflict` · `venue_suppression`)으로 전면 재작성 |
| `hidden_request`(W7/W8)·`hidden_legal`(D4) 상태가 설계에서 누락 | **REQ-4** 사유코드↔visibility 대응표 + **FORBID-6**(품질 판정이 법적·요청 비공개를 뒤집는 것 금지) |
| 게이트가 시점 기반이라 캐시·정적 산출물로 우회 | **REQ-7** — visibility 전이 시 무효화 이벤트 발행(소비는 W1 소유) + 판정 신선도 상한 |

## 설계 전제 — 최종 공개 상태의 단일 진리표

```
final_public(venue) =
  venue.visibility = 'hidden_legal'   → 비공개 (오버라이드 불가)
  venue.visibility = 'hidden_request' → 비공개 (오버라이드 불가)
  review_override.decision = 'force_hidden'                        → 비공개
  review_override.decision = 'force_public'
      ∧ venue.visibility = 'hidden_quality'
      ∧ medical_guardrail_pass                                     → 공개
  venue.visibility = 'public'                                      → 공개
  그 외                                                            → 비공개
```

- **판정 컬럼**(`quality_verdict`, `venue.visibility` 의 `public`↔`hidden_quality` 전이)은 C7 이 단독으로 쓴다.
- **오버라이드**(`review_override`)는 O2-REVIEW-ADMIN 이 단독으로 쓴다. C7 은 읽기만 한다.
- **`hidden_request`** 전이는 W8-CORRECTION-PROCESSING, **`hidden_legal`** 전이는 법무 대응 경로가 쓴다.
- 세 소유자의 값을 **결합하는 유일한 장소가 `public_venue` 뷰**이며 그 뷰는 C7 소유다.

## 선행 조건 — F2 스키마 개정 (미충족 시 착수 금지)

| 대상 | 필요 정의 | 근거 |
|---|---|---|
| `quality_verdict` | (venue_id PK FK, score smallint CHECK 0~100, reason_codes text[] NOT NULL, ruleset_version text NOT NULL, evaluated_at timestamptz NOT NULL) | REQ-1·2·4·6 |
| `review_override` | (venue_id FK, decision ENUM('force_public','force_hidden'), approver_ids text[], reason text, created_at) — **스키마는 F2 소유, 행 기록은 O2 소유** | REQ-3 · O2 REQ-5 |
| `visibility_change_event` | (venue_id FK, from_value, to_value, changed_at, consumed_at NULL) | REQ-7 |
| F2 REQ-1 스냅샷 | 위 3개 테이블 추가 + `public_venue` **뷰를 스냅샷 대상에 포함** | F2 `test:schema` 통과 |

**이미 존재하므로 신설하지 않는 것**: `venue.visibility` / `price_plan.visibility` ENUM 4값(DEFAULT `hidden_quality`),
`price_conflict`, `venue_suppression`, `price_plan.confidence`.
