## 계약 고정 상수

### K-1. 정본 산출물 경로와 형식 — 하류 8개 태스크의 인용 규약

> 감사 지적: "하류가 rule_id 를 쓰지 않고 '`D4 금칙어 사전`'이라는 **이름으로만** 인용한다.
> 없는 파일을 스캔하는 테스트는 스텁이 되고 스텁은 항상 통과한다."

| 항목 | 확정값 |
|---|---|
| 정본 위치 | **`packages/legal-medical/`** (**`docs/` 아래 금지** — 런타임·테스트가 로드한다) |
| 워크스페이스 이름 | `@glowmate/legal-medical` |
| 규칙 소스 | `rules/*.yaml` (scope · display · lexicon · review) — 커밋 대상 |
| **기계 판독 발행물** | **`packages/legal-medical/exported_rules.json`** — 커밋 대상 |
| 발행물 생성 | `pnpm --filter @glowmate/legal-medical build` 가 `rules/*.yaml` 에서 결정론적으로 재생성한다 |
| 패키지 진입점 | `exports`: `"."` → `./src/index.ts`, `"./rules.json"` → `./exported_rules.json` |
| 스키마 | `schema/rules.schema.json` (JSON Schema draft 2020-12) |
| 버전 | `package.json` 의 semver. 규칙 완화 = minor 이상, 규칙 강화 = patch 가능 |
| 판정 출력 enum | `show` · `hide` · `needs_review` |
| 하류 인용 방식 | 워크스페이스 이름 `@glowmate/legal-medical` 로 import 하고, 규칙은 `exported_rules.json` 의 `rule_id` **문자열**만 인용. 상대 경로·파일명·자연어 인용 금지 |

`exported_rules.json` 의 각 항목 필수 키:
`rule_id` · `kind`(display\|lexicon\|review\|scope) · `status`(binding) · `pattern` 또는 `enum` ·
`applies_to`(축 배열) · `legal_basis` · `version`

> **왜 깊이 1인가 (v2.1 정정).** `pnpm-workspace.yaml` 의 패턴은 `apps/*` · `packages/*` 다.
> 구 위치 `packages/legal/medical/` 은 깊이 2라 어떤 패턴에도 매칭되지 않아
> `pnpm -r typecheck|build|test` 가 이 패키지를 **통째로 건너뛴다.** 그 상태에서는
> (a) REQ-7 의 "판정 함수 반환값이 3-enum 밖이면 실패"가 CI 에서 집행되지 않고,
> (b) 하류(C4·C6·C7·W2·W3·W4·O2)가 워크스페이스 이름으로 import 할 수 없어 상대 경로 인용으로
> 되돌아가며, (c) `rollback` 이 근거로 삼는 "모듈 해석 실패로 즉시 중단"이 성립하지 않는다.
> 대안이었던 "`touches` 에 `pnpm-workspace.yaml` 추가"는 F1 소유 파일을 하류가 편집하게 만들어
> 채택하지 않았다.

> **왜 `dist/` 가 아닌가 (v2.1 정정).** 리포 루트 `.gitignore` 가 `dist/` 를 무시한다.
> 발행물을 `dist/` 에 두면 커밋되지 않아 (a) 하류의 "파일 로드 후 대조" detect 가 파일 부재로
> 공허하게 통과하고, (b) FORBID-6 의 발동 조건("origin/main 에 발행물이 존재")이 영원히
> 성립하지 않아 회귀 잠금이 무력해진다. 발행물은 패키지 루트에 커밋하고, `build` 는 그것을
> **재생성해 diff 가 비어 있음**을 CI 가 확인하는 방식으로 드리프트를 잡는다.

### K-2. rule_id 네임스페이스 (하류 인용 가능 여부를 ID로 구분)

| 접두 | 의미 | 하류 인용 |
|---|---|---|
| `MED-[A-Z]-\d{2}` | `status: binding` — pattern 또는 enum 보유 | ✅ **exported_rules.json 에 포함** |
| `MEDA-[A-Z]-\d{2}` | `status: advisory` — 자연어 서술 | ❌ **export 금지** |
| `-X` 접미 | 비-medical 축 예외 적용 항목 (exception_reason 필수) | ✅ |

### K-3. 법적 근거 형식

`legal_basis` 는 정규식 `^(의료법|의료법 시행령|의료법 시행규칙|표시·광고의 공정화에 관한 법률)\s제\d+조`
매칭. **`status: binding` 인 모든 항목**에 필수 (scope 항목만이 아니다 — REQ와 FORBID의 적용 범위를 일치시킨다).

### K-4. 실측 코퍼스 — 표집 프레임과 취득 경로 (자기채점 차단)

| 항목 | 값 |
|---|---|
| 표집 프레임 소스 | **`public_license_registry` 단일.** 다른 프레임 소스로의 확대·대체 불가 (v2.2 — 공식 API 프레임 삭제 근거는 아래 주석) |
| `public_license_registry` 정의 | 지방행정 인허가 데이터개방의 **의원·한의원 등 의료기관 인허가 데이터**에서 강남3구(서초·강남·송파)를 필터한 집합. D1a K-5 와 동일 계열의 프레임이다 |
| **1순위 취득 경로** | **서울 열린데이터광장 파일 다운로드 — 호스트 `datafile.seoul.go.kr`.** 무인증 HTTP 200 (2026-08 실측). D1a K-5 가 확정한 호스트와 동일하다 |
| **백업 취득 경로** | **LOCALDATA 파일 서버 — 호스트 `file.localdata.go.kr`.** 무인증. **요청에 `User-Agent`·`Referer` 헤더 필수**(없으면 302 로 되돌려보낸다). 자치구 코드: 서초 `3210000` · 강남 `3220000` · 송파 `3230000` |
| 폐쇄된 호스트 | **`www.localdata.go.kr`(포털)은 2026-04-16 정식 폐쇄.** 포털 호스트로의 요청·재시도·대체 포털 탐색을 금지한다. 백업 경로의 **파일 서버는 별개 호스트**이므로 이 폐쇄와 무관하다 |
| 교차검증 | 1순위·백업 두 경로에서 각각 받은 강남3구 의원급 유효 행수를 `corpus/frame.md` 에 양쪽 다 기록하고, 차이가 **≤ 1.0%** 임을 확인한다 (2026-08 실측 시차 0.3%). 초과 시 수집일을 맞춰 재취득하고 재취득 이력을 남긴다 |
| **필수 자격증명** | **없음.** 프레임 취득은 무인증 파일 다운로드다. `NAVER_SEARCH_CLIENT_ID`·`NAVER_SEARCH_CLIENT_SECRET`·`KAKAO_REST_API_KEY`·`DATA_GO_KR_SERVICE_KEY` 중 **어느 것도 요구하지 않으며**, 코드·문서·CI 시크릿에서 참조하지 않는다 |
| 인코딩 (함정 ①) | 원본은 **CP949**인데 HTTP 응답 헤더가 `charset=UTF-8` 로 **거짓 선언**한다. 헤더를 믿고 UTF-8 로 디코딩하면 전 행의 상호·주소가 깨진다. 디코딩 인코딩을 **`cp949` 로 고정**하고 응답 헤더의 charset 으로 분기하지 않는다 |
| 좌표 (함정 ②) | 좌표 컬럼은 **EPSG:5174**(보정계수 미적용 Bessel 중부원점TM)이며 WGS84 가 아니다. **D4 는 좌표를 사용하지 않는다** — 강남3구 필터는 **자치구 코드 또는 소재지 주소 문자열로만** 수행하며, 좌표 컬럼을 읽거나 WGS84 로 간주하는 코드를 두지 않는다 |
| 영업상태 (함정 ③) | **`영업상태명 == '영업/정상'` 필터 필수.** 2026-08 실측 폐업 비율 **57%** — 필터 없이 표집하면 코퍼스 절반이 폐업 업체가 되어 "가격 미공개"로 집계된다 |
| 요청률 (함정 ④) | `file.localdata.go.kr` 은 임계값 미공개 상태로 **429** 를 반환한다. 자치구당 다운로드 1회를 넘기지 않고, 429 수신 시 지수 백오프(초기 30초 · 최대 3회) 후 **중단**하며 재시도 이력을 `corpus/frame.md` 에 남긴다 |
| 프레임 구축 필터 **사용 금지** 속성 | 가격/요금/이용권 · 예약·결제 연동 여부 · 광고·상위노출 상품 가입 여부 · 리뷰 수·평점 상위 정렬 · 검색 결과 상위 N |
| 규모 | **40건** = 개발셋 30 + **홀드아웃 10(봉인, 룰 확정 후 개봉)** |
| 수집 대상 | 각 업체의 가격 표기 원문 + 스냅샷. 취득 채널은 **K-6** 의 부분집합 |
| 건별 상태값 `acquisition_status` | `price_observed` · `no_price_display` · `blocked_by_robots` · `blocked_by_tos` (**4-enum**, v2.2). `blocked_by_*` 두 값은 40건에 산입하지 않고 프레임에서 다음 건으로 교체하며 교체 이력을 `corpus/frame.md` 에 남긴다 |
| 골든 케이스 `origin` | `observed` 비율 **≥ 50%** (나머지는 `synthetic` 허용) |

> **백업 경로와 D1a K-5 의 관계 — 호스트를 혼동하지 마라.**
> D1a K-5 는 `localdata.go.kr`(포털 계열 호스트)을 **사용 불가**로 못박았다. 그 판정의 대상은
> 2026-04-16 폐쇄된 **포털**이고, K-4 의 백업 경로는 **파일 서버 `file.localdata.go.kr`** 로 별개
> 호스트다. 따라서 두 계약은 충돌하지 않지만, **혼동하면 D1a 가 금지한 호스트로 재시도를 반복하게
> 된다.** 저자는 백업 경로를 처음 사용할 때 `corpus/frame.md` 에 도달성 프로브 결과
> (호스트 · 요청 헤더 유무 · HTTP 상태코드 · 수집 일시)를 기록한다. 백업 경로가 200 을 주지 않으면
> **1순위 경로만으로 진행하거나 중단**하며, 제3의 소스로 갈아타지 않는다(프레임 확대는 불가).

> **공식 API 프레임을 삭제한 이유 (v2.2). 되살리지 마라.**
> v2.1 은 `map_category_enumeration_via_official_api` 를 프레임으로 지정하며
> *"robots.txt 는 크롤러를 규율하고 공식 API 는 발급 키로 규율되므로 D3 의 forbidden 판정과
> 충돌하지 않는다"* 고 적었다. **그 판단이 틀렸다. robots 는 통과해도 이용약관이 정면으로 막는다.**
>
> 「NAVER API 서비스 이용약관」
> **7.3 ③** … 무단으로 복제, **저장(캐시 행위 포함)**, 가공, 배포 등 이용하거나 제3자에게 제공하는 행위
> · **네이버 지역정보를 수집하여 별도 데이터베이스로 관리하며 이용하는 행위**
> · 네이버 지역정보를 수집하여 해당 정보를 광고 영업에 이용하는 행위
> **7.2 ③** … 사용자들로부터 **API서비스 이용에 대한 대가(금전, 정보 제공 등 일체의 유·무형의 대가)를
> 제공받아서는 안됩니다.**
>
> 「카카오 개발자 운영정책」
> **제5조 20항** 앱에서 사용자 환경을 개선하기 위한 목적 외 다른 목적으로 카카오에서 받은 데이터를
> **캐시하거나** 캐시 후 최신 데이터로 유지하지 않는 행위
> **제5조 30항** 서비스 및 개발자센터를 이용하여 얻은 정보를 카카오의 사전 승낙 없이 **복사, 복제, 변경,
> 번역, 출판, 방송, 검색 엔진 또는 디렉터리에 입력 기타의 방법으로 사용하거나 이를 타인에게 제공하는 행위**
>
> 즉 **양사 모두 캐시조차 금지하고 지역정보의 별도 DB 구축을 명시 금지**한다. 우리 제품은 정확히 그 DB 를
> 구축해 공개 서비스로 제공하고 리드로 대가를 취하므로 두 약관에 정면으로 저촉된다.
> **기술적 상한(네이버 `display` 최대 5건 · 카카오 최대 45건) 이전에 계약적으로 불가**다.
> 덧붙여 네이버 지역검색의 `total` 은 신뢰할 수 없다 — `display` 를 1→5 로 바꾸면 `total` 도 1→5 로
> 따라온다. **분모를 알 수 없으므로 "전수 나열"을 애초에 주장할 수 없다.**
>
> 따라서 `public_license_registry` 가 **유일 프레임**이다. 공식 API 를 프레임 또는 원문 채널로
> 되살리는 변경은, 위 인용 조항을 무효화하는 근거(**양사의 서면 승낙** 또는 **개정된 약관의 조항 번호와
> 원문 스냅샷**)를 본 계약에 첨부하지 않는 한 불가하다. 근거 없이 되살리면 FORBID-2 (c) 위반이다.

> **지도 서비스 웹 화면과의 관계 (v2.1 서술 유지).**
> 2026-08 실측 기준 `map.naver.com` · `map.kakao.com` · `search.naver.com` 은
> `User-agent: * → Disallow: /` 이며 ClaudeBot 도 개별 차단된다 — D3 기준 `forbidden` 이다.
> v2.2 이후 **웹 화면(robots 차단)과 공식 API(약관 차단) 양쪽 모두 이 태스크에서 사용 불가**이며,
> 두 경로 사이에 우회로는 존재하지 않는다.
> 코퍼스는 리포 내부 검증용으로만 보관하며 공개 발행물인 `exported_rules.json` 에 원문을 싣지 않는다
> (FORBID 아님, 경계 조건).

### K-5. 최소 공개 커버리지 하한 (원칙 2.5 짝)

실측 코퍼스 중 가격 표기가 존재하는 건(`acquisition_status == price_observed`)에 대해
화이트리스트 적용 시 **`show` 판정 비율 ≥ 0.60** — 개발셋과 홀드아웃 **각각**에서 충족해야 한다.

> 이 하한이 없으면 허용 포맷을 극단적으로 좁게 정의(`^도수치료 \d{1,2}회 [0-9,]+원$` 정확 매칭)해
> REQ와 FORBID를 전부 만족하면서 medical 축 가격을 사실상 전부 숨길 수 있다.
> PRD G1이 축별 차등 판정으로 지켜낸 3축 UVP를 D4가 조용히 되돌리는 경로다.

### K-6. 가격 표기 원문의 허용 취득 채널 (이 집합의 **부분집합만** 사용 가능. 확대 불가)

| 값 | 정의 |
|---|---|
| `official_website` | 업체가 소유·운영하는 공식 웹사이트 중, ① 해당 호스트 `robots.txt` 가 취득 경로를 차단하지 않고 ② 해당 호스트의 이용약관 원문 스냅샷을 확보해 수집·재이용 금지 조항이 없음을 확인한 페이지 (D3 K-1 `conditional` 과 동일 강도의 요건) |
| `official_blog` | 업체가 운영 주체로 명시된 공식 블로그 중, 위 ①②를 충족한 페이지. **약관은 블로그 플랫폼 운영사의 것이 적용된다** — 플랫폼 약관이 수집·DB화를 금지하면 그 플랫폼 전체가 제외다 |
| `d1b_field_ledger` | D1b 현장 조사 원장의 `price_found == true` 행 중 스냅샷과 `price_evidence_snippet` 부분문자열 검증을 통과한 행. 인용 시 D1b 행 식별자를 기록한다. **D1b 산출물이 리포에 커밋되어 있을 때만 사용 가능**하며, 미커밋 상태에서는 이 채널을 사용할 수 없다 (D4 는 D1b 없이도 40건을 채울 수 있어야 한다 — `depends_on` 을 추가하지 않는 이유) |

**취득 채널로 인정 금지 (v2.2 확대):**
**네이버·카카오의 모든 경로** — 지도·검색 웹 화면, 플레이스/장소 상세, **공식 오픈 API 응답 필드
(`openapi.naver.com` · `dapi.kakao.com`) 포함**. 약관이 저장·캐시·DB화를 금지하므로 키가 있어도 불가다
(근거: K-4 주석의 NAVER 7.3③·7.2③ / 카카오 제5조 20항·30항) ·
전화·카카오톡·DM·방문 문의 · 제3자 후기/카페/체험단 글에 적힌 결제 금액 · 쿠폰·소셜커머스 판매가 ·
종료된 이벤트 가격 · 조사자 추정치 · **심평원 비급여 진료비 공개 집계값**(기관별 값이 아니다. K-7) ·
**`public_license_registry` 필드**(가격 필드가 존재하지 않는다 — v2.1 의 이 항목은 착오였다)

> **왜 원문은 업체 자체 채널뿐인가 (v2.2 실사 결론).**
> 어느 공공 API·상용 API 에도 미용 시술 가격이 없다. 심평원 비급여 진료비 공개는 도수치료·추나·약침 등
> 급여 인접 항목만 대상이고 **비만·미용·제모·필러·보톡스는 제도 대상 자체가 아니다(0건)**.
> 인허가 데이터는 상호·주소·업종만 제공하고 가격 필드가 없다.
> 따라서 **프레임(누구를 볼 것인가)은 공공 인허가 데이터로, 원문(무엇이 게시돼 있는가)은 업체 자신의
> 채널 + D1b 수기 조사로만** 취득된다. 이 둘 말고 다른 원문 경로는 존재하지 않으며, 없는 경로를 찾다가
> 네이버·카카오로 돌아가는 것이 이 태스크의 가장 유력한 실패 경로다.
>
> `official_website`·`official_blog` 건은 건별로
> `robots_check`(`host` · `fetched_at` · `allows_path`) 와
> `tos_check`(`tos_url` · `fetched_at` · `snapshot_sha256` · `clause_ref` 또는 `no_restrictive_clause`)
> 를 **둘 다** 기록한다. `allows_path: false` 인 건은 `blocked_by_robots`,
> 약관에 수집·재이용 금지 조항이 있는 건은 `blocked_by_tos` 로 분류하고 코퍼스 40건에 산입하지 않는다.
> **`blocked_by_robots`·`blocked_by_tos` 를 `no_price_display` 로 기록하는 것은 FORBID-2 위반이다** —
> 그 혼동은 "가격을 안 걸어둔 업체"의 분모를 부풀려 show 하한을 무력화한다.

### K-7. 심평원 비급여 집계값 — **D4 에 도입하지 않는다** (판단과 근거, v2.2)

무인증 xlsx 로 취득 가능한 국가승인통계(의원급 포함, 서울 기준 도수치료 중간값 120,000원 ·
단순추나 24,940원 · 약침술 10,000원)를 **D4 의 어떤 요구·검사·임계에도 사용하지 않는다.**

1. D4 가 판정하는 것은 **표기 형태**(허용 포맷·금칙 표현)이지 **금액의 타당성**이 아니다. 코퍼스는
   금액을 검증하기 위한 것이 아니라 규칙이 실제 표기 분포에서 과잉/과소인지 재는 자다.
2. 값은 기관별이 아니라 **종별/시도 집계**이고 **연 1회(매년 9월)** 갱신이다. K-5 의 `show` 하한을
   포함한 어떤 임계에 연결되는 순간, **연 1회 갱신되는 외부 집계값이 공개/비공개 판정을 좌우**한다.
   그 상태에서는 통계 갱신 한 번으로 medical 축 노출이 통째로 흔들리고, 원인 추적도 불가능하다.
3. 회차 패키지·할인 표기가 없어 **코퍼스 원문의 대체가 되지 않는다** (REQ-2 가 요구하는 것은 원문 문자열이다).

**상신 3 — 참조점으로서의 용도는 다른 계약 소관이다.** 금액 상식 범위의 근거로는
**C4**(FORBID-4 의 축별 sanity 범위 상수에 대한 근거 문서화)와 **D1b**(현장 조사 가격 기록의 상식성
점검)에 속한다. 채택 여부는 각 계약 저자가 판단하며 **D4 저자는 그 파일들을 수정하지 않는다.**

`exported_rules.json`·수집기에서 이 수치를 참조하는 것은 금지한다(REQ-2 의 `--check frame-integrity` 가 검사).
