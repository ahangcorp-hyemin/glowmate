forbid:

      packages/db · pg · postgres · drizzle-orm · @prisma/client 중 하나를 직접 import 하는 경우

    on_violation: block_merge

  - id: FORBID-2
    when: >
      CI job 중 하나 이상이 red 인 PR 의 diff 에 `continue-on-error: true` 또는 `|| true` 가 신규 추가되거나,
      `eslint-disable`·`depcruise-disable` 주석이 `-- reason: <이슈 URL>` 없이 신규 추가되는 경우
    must_not: "규칙을 무력화하는 방식으로 CI 를 통과시키는 것 (사유 주석 + CODEOWNERS 승인 리뷰가 있는 disable 은 허용)"
    because: >
      F1 의 CI 는 이후 F2a~W9 모든 FORBID 의 탐지 기반이다. 여기서 우회 관용구가 한 번 허용되면
      개발 에이전트가 동일 우회를 학습해 계약 체계 전체가 장식이 된다.
    detect: >
      CI job `lint` — diff 스캔으로 `continue-on-error`·`|| true` 신규 추가 시 무조건 실패,
      사유 없는 disable 주석 시 실패, `--report-unused-disable-directives` 병행.
      본 검사 자체는 픽스처 `ci-fixture/violations` 로 REQ-5 에서 검증된다.
    on_violation: block_merge

  - id: FORBID-3
    when: >
      apps/web 의 라우트 세그먼트 또는 루트 레이아웃에 `dynamic='force-dynamic'` · `revalidate=0` ·
      `unstable_noStore` · `fetchCache='force-no-store'` · `cache:'no-store'` 중 하나가 선언되거나,
      `next build` 라우트 요약에서 스캐폴딩 라우트가 Static/ISR 이 아닌 것으로 출력되는 경우
    must_not: "기본 렌더링 모드를 동적으로 전환"

      색인되지 않아 H3(1페이지 진입 롱테일 ≥100)을 측정할 기회 자체가 사라진다.
    detect: >
      CI job `test` — 1차 수단: `next build` 라우트 요약 파싱으로 전 라우트의 렌더 전략 assert.
      2차 수단: 위 5개 토큰 grep. 두 검사 중 하나라도 실패하면 job 실패.
    on_violation: block_merge

  - id: FORBID-4
    when: >

    must_not: "스키마·마이그레이션(F2a/F2b), 디자인 토큰(DS), API 구현(F5) 등 타 태스크 소유 경로를 선행 작성"

    detect: "CI job `lint` — `git diff --name-only origin/main` 을 touches 글롭과 대조, 밖의 경로 1건이라도 있으면 exit 1"

    must_not: "검사 기준을 올려 통과시키는 것 (테스트 분할·캐시·계약 수정으로 해결)"
    because: >

    detect: >
      CI job `dag-check` — 세 파일의 diff 가 완화 방향이면 `standard-change-approved` 라벨 + 해당 파일
      CODEOWNERS 승인 리뷰(승인자 ≠ PR 작성자, GitHub API 조회) 없이는 exit 1.
      base 에 파일이 없는 최초 도입 커밋은 검사 대상에서 제외.
    on_violation: block_merge

  - id: FORBID-6
    when: >

    because: >

    detect: >
      메타테스트 `pnpm test:ci-meta` — validate 스크립트를 제거한 픽스처와 항상 exit 0 인 스텁 픽스처
