# ─── 요구사항 ───────────────────────────
requirements:
  - id: REQ-1
    statement: >
      큐 목록은 C7 이 `visibility='hidden_quality'` 로 판정한 레코드를 사유코드(6종) 필터와 함께
      페이지당 50건, 품질 스코어 오름차순으로 표시한다.
    acceptance: >
      e2e 테스트 — 픽스처 120건 입력 시 3페이지, 1행이 최저 스코어, 사유코드 필터 적용 시 해당 코드

  - id: REQ-2
    statement: >
      검수 액션 4종(승인 요청·2인 승인·수정·반려) 각각은 review_audit_log 1행

    acceptance: >
      통합테스트 — 4액션 실행 후 로그 4행, before/after JSON 이 서로 다르며 actor_id 가 세션 사용자와 일치.

  - id: REQ-3
    statement: >
      승인은 폐쇄 enum 의 reason_code 1개와 자유서술 note 20자 이상을 함께 요구하며, 둘 중 하나라도
      없으면 422 를 반환한다.
    acceptance: >
      통합테스트 — reason_code 누락 422, note 19자 422, 정상 입력 200.

  - id: REQ-4
    statement: >
      C7 이 비공개로 판정한 레코드의 공개 전환은 사유코드와 무관하게 서로 다른 2인의 approver 승인이
      기록된 경우에만 성공한다.
    acceptance: >
      통합테스트 — 사유코드 6종 각각에 대해 (a) reviewer 단독 403, (b) 동일 approver 2회 409,
      (c) 서로 다른 approver 2인 200 (총 18케이스).

  - id: REQ-5
    statement: >
      검수 액션은 오버라이드 레이어에만 기록되며, venue.visibility 와 C7 판정 컬럼
      (quality_score, reason_codes)의 값은 변화하지 않고, 공개 반영은 public_venue 뷰의 결합으로
      나타난다.
    acceptance: >
      통합테스트 — 2인 승인 후 (a) 오버라이드 행 1건, (b) venue.visibility·quality_score 불변,
      (c) public_venue 조회 결과 1건 assert.

  - id: REQ-6
    statement: >
      정상 보강 케이스 골든 큐 20건에 대해 2인 승인 플로우를 실행하면 20건 전부가 public_venue 에
      노출된다.
    acceptance: >
      e2e 테스트 `pnpm test:review-golden` — 20/20 공개 전환 성공 (전량 반려·전량 차단 구현 시 실패).

  - id: REQ-7
    statement: >
      어드민 라우트·API 는 role in (reviewer, approver) 세션이 없는 요청에 404 를 반환하며,
      동일 자연인이 2개 계정으로 2인 승인을 채우지 못하도록 approver 계정은 조직 이메일 도메인 기준
      유일성 제약을 갖는다.
    acceptance: >
      통합테스트 — (a) 비인증 404, role=none 404, role=reviewer 200,
      (b) 동일 이메일 로컬파트 별칭(+ 태그) 계정 생성 시 409.

  - id: REQ-8
    statement: >
      큐 대기 건수(review_queue_depth), 최장 대기 시간(review_queue_oldest_hours),
      override 공개 비율(공개 업체 중 오버라이드로 공개된 비율)을 내부 메트릭으로 노출한다.
    acceptance: >

      3, 50, 0.12 로 반환.

# ─── 조건부 금지사항 ────────────────────
forbid:
  - id: FORBID-1
    when:         C7 이 `visibility='hidden_quality'` 로 판정한 레코드를 공개로 전환하는 경우 (사유코드 6종 무관)
    must_not:     단일 actor 의 조작만으로 오버라이드 행을 유효 상태로 만들기
    because:      2인 승인을 스코어 미달 건에만 걸면 PRICE_CONFLICT·SINGLE_SOURCE·STALE_DATA·MISSING_REQUIRED_FIELD 로 비공개된 레코드는 한 사람이 되돌릴 수 있고, C7 이 "충돌 시 대표 단가 NULL 유지"로 막아둔 것을 어드민 한 명이 뒤집어 잘못된 가격이 색인된다
    detect:       통합테스트(REQ-4의 18케이스) — 사유코드 6종 각각에서 단독 승인이 403/409 로 거부됨을 assert
    on_violation: block_merge

  - id: FORBID-2
    when:         검수 결과를 데이터에 반영하는 경우
    must_not:     venue.visibility · quality_score · reason_codes 컬럼에 직접 쓰기 또는 base 레코드 DELETE (오버라이드 레이어 기록만 허용)
    because:      C7 은 "공개 판정 쓰기 경로가 정확히 1개"를 전제로 만들어졌다. 두 번째 쓰기 경로가 생기면 다음 게이트 실행이 검수 결과를 조용히 덮어쓰거나 반대로 게이트 판정을 지워버리고, 어떤 기준으로 공개됐는지 사후 재구성이 불가능해진다. G4 는 "미달 데이터는 비공개(삭제 아님)"이므로 물리 삭제는 다음 수집 주기에 같은 레코드를 되살린다
    detect:       CI 정적 검사 — 본 태스크 touches 내 visibility/quality 컬럼 UPDATE·ORM 호출 및 DELETE 0건 + 통합테스트로 C7 재실행 후 오버라이드 결과가 유지됨을 assert
    on_violation: block_merge

  - id: FORBID-3
    when:         단일 actor 가 60분 내 20건을 초과해 공개 전환을 승인하려는 경우
    must_not:     추가 확인 절차 없이 승인을 계속 수락 (초과분은 429 와 함께 표본 감사 대기 상태로 전환)
    because:      "note 20자 이상"은 상수 문자열 붙여넣기로 충족되므로, 큐 120건을 30분 만에 전량 공개하는 것이 계약상 모범 준수가 된다. 그 순간 G4 는 통과 의례가 되고 지표는 실제 품질이 아니라 승인 속도를 측정하게 된다
    detect:       통합테스트 — 60분 창에서 21번째 승인 요청이 429 이고 해당 레코드가 공개되지 않음을 assert
    on_violation: block_merge

  - id: FORBID-4
    when:         검수자가 스코어 입력값(가격 수치·소스 목록·수집일)을 수정하는 경우
    must_not:     source_url·entered_by 없이 값을 저장하거나, C7 재판정 없이 동일 세션에서 그 레코드를 공개 승인
    because:      임계값을 건드리지 않고 입력을 손보면 게이트를 정면으로 통과시킬 수 있다. 검수자의 기억·추정으로 채운 가격은 크롤링 근거와 구분되지 않아, 오류 1건의 출처조차 추적할 수 없게 되고 UVP 가 걸린 가격 신뢰가 검증 불가능해진다
    detect:       DB 제약 + 통합테스트 — manual override 는 source_url NOT NULL·entered_by NOT NULL(위반 422), 입력값 수정 후 재판정 이벤트 없이 승인 시도 시 409 assert
    on_violation: block_merge

  - id: FORBID-5
    when:         어드민 롤(reviewer, approver)이 review_audit_log 에 접근하는 경우
    must_not:     UPDATE·DELETE 권한을 부여하거나 애플리케이션 코드에서 로그 수정 경로를 제공
    because:      지울 수 있는 감사로그는 감사로그가 아니다. 잘못된 공개 전환이 문제가 됐을 때 기록을 고칠 수 있으면 W8 로 접수된 이의 제기에 대해 처리 경위를 증명할 수 없고, 내부 통제가 존재하지 않는 것과 같아진다
    detect:       DB 권한 테스트 — 어드민 롤로 review_audit_log UPDATE/DELETE 시도 시 42501 발생 assert + CI 정적 검사로 해당 테이블 대상 UPDATE/DELETE 호출 0건
    on_violation: block_merge

  - id: FORBID-6
    when:         category_axis 가 medical_wellness 인 레코드를 공개 전환하는 경우 (수정 액션으로 문구를 바꾼 뒤 승인하는 경로 포함)
    must_not:     승인 시점의 최종 상태에 대한 D4 가드레일 재검사(금지표현·허용 가격 표기 포맷) 없이 오버라이드를 유효화
    because:      사람 검수가 자동 검사를 대체한다고 가정하면 규제 문구가 그대로 공개되고, 의료광고법 위반은 해당 축 제외를 넘어 서비스 전체 중단으로 이어질 수 있다. 검사 시점을 수정 전으로 두면 수정→승인 2단계로 언제든 우회된다
    detect:       통합테스트 — (a) 금지표현 포함 medical 레코드 승인 시 422, (b) 수정으로 표현을 추가한 뒤 승인 시도해도 422(최종 상태 기준 검사)임을 assert
    on_violation: block_merge
