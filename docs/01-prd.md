## 1. 제품 범위

**MVP 정의:** 강남·서초·송파 3구의 웰니스 업체를 크롤링해 **회당 단가로 정규화된 가격**과 **3050 니즈 태그**로 탐색하게 하고, **리드 액션을 계측**하는 SEO 우선 웹 서비스.

### 확정된 판단 (사용자 미응답 항목에 대한 기획 결정)

| 항목 | 결정 | 근거 |
|---|---|---|
| 세그먼트 | **primary = 38~52세 여성**, 단 니즈 태그 온톨로지 스키마는 **성별 중립** | 초기 콘텐츠·카피는 여성 3050에 집중해 메시지 선명도를 확보하되, 데이터 스키마에 성별을 하드코딩하면 4050 남성(사우나·도수·골프체형) 확장 시 마이그레이션이 발생. **카피는 좁게, 스키마는 넓게.** |
| 카테고리 | **3축 전부 유지**, RA-1 게이트는 **카테고리별 차등 판정** | 3축 동시 검증은 RA-1 비용을 3배로 만들지만, 하나로 좁히면 "웰니스 지도"라는 UVP 자체가 성립하지 않음. 대신 게이트를 축별로 나눠 **운동·바디만 통과해도 그 축으로 출시**할 수 있게 함 (전부 아니면 전무를 회피) |

### Non-Goals (MVP에서 명시적으로 하지 않는 것)

- 결제 · 예약 확정 · 정산
- 업체 셀프서브 어드민 / 업체 계정
- 강남3구 외 지역
- 네이티브 앱 (단, API 레이어는 앱 확장을 전제로 설계)
- 개인화 추천 / 로그인 필수 기능
- 자체 후기 작성 기능 (에디터 리포트로 대체)

## 2. 기술 스택 결정

| 레이어 | 선택 | 근거 |
|---|---|---|
| 웹 | **Next.js App Router** (SSG/ISR 중심) | 채널 1순위가 SEO. 조합 랜딩 페이지를 정적 생성해야 색인 규모가 나옴 |
| API | **Route Handler 기반 공용 API 레이어**를 웹과 분리 | 앱(Expo) 확장 시 동일 API 재사용. 웹 컴포넌트가 DB를 직접 호출하지 못하게 경계를 강제 |
| DB | **Postgres + PostGIS** | 지리 반경 검색 필수 |
| 크롤러 | **Python + Playwright**, 웹과 별도 프로세스 | 배포 주기·실패 격리·언어 생태계 분리 |
| 배포 | Vercel(웹) + 별도 워커(크롤러) | |

## 3. 가설 백로그

> 모든 태스크는 아래 가설 중 **최소 1개**를 `traces_to` 로 참조해야 한다. 참조 없는 태스크는 감사에서 반려된다.

| ID | 가설 | 검증 지표 / 임계값 | 검증 단계 |
|---|---|---|---|
| **H1** | 강남3구 웰니스 업체의 **40% 이상**이 공개 채널에 가격을 노출한다 | 표본 100개 중 가격 확인 비율 ≥ 40% (축별 차등) | Discovery (RA-1) |
| **H2** | 노출된 가격의 **80% 이상**이 회당 단가로 환산 가능한 구조를 갖는다 | 파싱 성공률 ≥ 80% | Discovery → Pipeline |
| **H3** | 지역×카테고리×니즈 롱테일 키워드 중 **100개 이상**에서 신규 도메인이 1페이지 진입 가능하다 | SERP 난이도 분석 + 출시 후 색인/순위 | Discovery (RA-2) → 출시 후 |
| **H4** | 가격 비교 블록을 본 사용자의 **상세→리드 전환율이 유의하게 높다** | 전환율 차이 (노출 vs 미노출 코호트) | 출시 후 |
| **H5** | 방문자의 **25% 이상**이 니즈 태그 필터를 사용한다 | 필터 사용 세션 비율 ≥ 25% | 출시 후 |
| **H6** | 에디터 리포트가 있는 업체의 리드 전환율이 없는 업체보다 높다 | 코호트 비교 | 출시 후 |
| **H7** | 4주 재방문율 **20% 이상** — 일회성 검색 도구 이상이다 | 리텐션 | 출시 후 |

## 4. 게이트

| 게이트 | 조건 | 통과 실패 시 |
|---|---|---|
| **G1** | H1 검증 — 축별 가격 노출율 판정 | ≥40% 축: 정상 진행 / 25~40% 축: 에디터 실사 보강 후 진행 / <25% 축: **해당 축 MVP 제외** |
| **G2** | H3 검증 — 1페이지 진입 가능 롱테일 ≥ 100개 | 미달 시 채널 전략 재설계 (네이버 중심 / 커뮤니티 시딩) |
| **G3** | 크롤링 소스 법적·기술적 실사 통과 | 미통과 소스는 파이프라인에서 제외 |
| **G4** | 데이터 품질 — 공개 대상 업체의 가격 신뢰도 스코어 임계 통과 | 미달 데이터는 **비공개** (삭제 아님) |

> **G1·G2·G3 통과 전에는 Phase 2(데이터 파이프라인) 이후 태스크를 착수하지 않는다.** Phase 1(Foundation)은 게이트와 무관하게 선행 가능.
